## 适用场景

已定稿（或已有）剧本要落地为 AI 视频：资产建档 → 分镜 → 逐组视频提示词 → QC 交付。剧本创作不在本 skill（归 `drama-crew` 短剧创作团）。

## 核心原则

1. **主理人不代写**：资产归丹青、分镜归景川、质检归严恪，沈砚只做编排与汇编。
2. **唯一事实源**：分镜总表一镜一行，全项目**唯一 Schema**（v1.7.2 定版，其他文件只引用不复写）：`镜号 / 所属Clip / 场景 / 时长 / 景别 / 运镜 / 光影 / 站位 / 表演 / 台词·音效 / 资产ID / 情绪强度1-10 / 叙事目的（七分类，见 storyboard-craft §16；答不上"为什么存在"的镜回查隐性价值——显性隐性都立不住才删除或合并）/ 结尾选型`。角色卡、维度卡、storyboard-craft 均引用本行，禁止另立字段清单。
3. **唯一终编**：每个镜头的维度由景川统一整合，再按 Clip 成组终编成一条路由后视频提示词——通用任务四区块，明确启用的 30 秒直出专项固定八段且不双交；**并行调多个生成器=人脸漂移主因**。
4. **写与查分离**：景川负责交付完整性与本职装配自检（自检清单照跑），但不对自己的作品作**最终质量放行**——独立审查归严恪。
5. **先判断后生成**：首次设计先由当前专业角色判断观众应看什么、有哪些表现机会，再按镜头职责形成可拍证据；镜头卡不冻结不投喂。静态建立、停留或余波镜不为齐项硬造转折、压制或破坏。
6. **主要/复用视觉资产先建档、分镜只引用**：提示词里不临时编人物外貌、核心场景或承载连续性的关键道具，只引用资产 ID；参考资产在既有索引中标就绪状态，实体按 `reuse/new_variant/new_asset/unresolved` 判身份血缘；一次性且不承载状态的普通小物件及只承担人数/声势的未命名群演并入场景描述，不单独建档。
7. **信息流经沈砚中转**：上一阶段产出**原文**传给下一阶段，成员间不直连。
8. **过程透明化（防黑盒）**：每个阶段产出即落盘、按「展示分级」展示给用户（**落盘 ≠ 打断**），用户可阶段间纠偏，见「过程透明化机制」。

## 过程透明化机制（防黑盒 · 用户全程可见可纠偏）

**用户看到"在工作"却不知道在产出什么 = 黑盒，禁止。** 制作侧每阶段产出必须即时可见：

1. **即时落盘**：每个阶段产出按 `references/file-management.md` 目录结构落盘独立文件——资产库（`02_资产/`）、分镜总表与提示词集（`03_分镜/`，命名 `storyboard_SXX.md` / `prompts_SXX.md`）、声音方案（`04_声音/`）、成片与 QC（`05_成片/`）。
2. **展示分级（v1.8.0 收窄 · 落盘 ≠ 打断）**：每个产出**落盘即留档**；**决策节点主动 present_files 展示**并一句话通报（`{阶段}产出已生成：{文件名}，可查看纠偏`）——其他非决策中间文件不逐个打断，在下一个自然节点合并通报文件名。
3. **关键关卡必展（决策节点清单）**：①资产建档产出（角色三件套/场景板，资产确认弹窗前）；②每批分镜总表+提示词集；③成片自检与 QC 报告；④最终整合交付——这四类必须展示文件。
4. **阶段间纠偏**：用户在任意阶段产出展示后可要求调整（改资产/改镜头/改提示词/改声音），纠偏发生在阶段间而非成片后；调整按「调整规则」表执行（资产问题回丹青、提示词问题回景川；按重拍协议先定责任层和修复范围）。
5. **最终交付**：第 6 步整合全部产出再次 present_files，并按 file-management 清理临时文件。

## 需求 → 模式路由表（自动加载核心·第 0 步前置）

**先判断任务范围，再依据用户原话、项目锁和实际目标材料选模式**；表中说法只是例子，不以关键词代替上下文。参考案例的语言、模型或时长不自动成为项目配置。按第 0 步选择引导展示方式，不因“跳过引导”扩大或缩小工作范围。

| 用户说法（特征词） | 模式 | 跑什么 |
|---|---|---|
| 「试个镜头」「一句话创意」「先看看效果」 | **快做分流** | 不建团队，沈砚临时兼任景川职责（「主理人不代写」的唯一例外）按规范出 1-3 镜 |
| 「做角色图/三视图/场景图/道具图/九宫格」 | **资产模式** | 只调丹青 |
| 用户自带单集稿做分镜/提示词，且无可继承的项目审核记录 | **裸本试制** | 丹青→景川→（严恪），轻流程；已有交接状态时走对应模式 |
| 从 drama-crew 交接来（四样/五样交接块） | **标准交接** | 全流程：丹青→景川→（闻笙→陆离→）严恪 |
| 从 drama-crew 交接来且标「未终审稿（直通模式）」或 `review_state=unreviewed` | **未审稿模式（直通交接）** | 不补四样、不拒收；按第 0 步分流，严恪执行未审稿限制声明与制作侧从严核查 |
| 整部剧裸本（多集剧本直接给） | **整剧交接** | 先与用户确认分批节奏（默认先 E01 试制验证，满意再批量） |
| 「单次生成 30 秒」「一个 30 秒 Clip」「30 秒直出」或项目已启用 | 在当前范围上匹配 **30 秒八段式** | 按 `prompt-assembly.md` §2，不要求用户再点名专项；只给 30 秒参考不触发 |
| 「配音/音色/对口型」 | 在既有流程上**加开闻笙**；台词镜**可见口型**再加开**唇形师** | 闻笙阶段必跑；对口型按 `lip-sync.md` 走 |
| 「配乐/BGM/氛围音乐/音效方案」 | 镜头级 cue 归景川（装配 dim-music）；**全剧配乐方案加开闻笙** | 闻笙出槽位包/母题分支/授权曲库检索词 |
| 「剪辑/成片/混音/发布」 | 在既有流程上**加开陆离** | 陆离阶段必跑 |
| 说「写剧本/改剧本/续写剧情」 | **路由出**：归 `drama-crew`，本 skill 不接 | 提示用户切创作团 |

**派单五问自检（每次下发子 Agent 前，沈砚内部静默执行）**：
```
本次派单：{角色} | ①角色卡 ✓ | ②必读规范：{文件名} ✓ | ③命中维度卡：{哪几张/无} ✓ | ④资产库/前序产出 ✓ | ⑤经验库同环节条目：{有/无} ✓
```
缺任何一项 = 不许下发（防「规则很全但没加载」）。**五问是主理人内部自检清单，默认不对用户外显**——只有缺文件或口径冲突需要用户裁决时才把相关项外显。

## 与 drama-crew 的衔接协议（三模式）

| 模式 | 适用 | 流程 |
|---|---|---|
| **单集试制（默认推荐）** | 所有项目起点 | drama-crew 出 E01 定稿 → 验收适用交接包 → 本团做 E01 → 用户验证效果（资产/分镜/提示词风格）→ 满意后批量 |
| **整剧交接** | 剧本已全部定稿 | 验收适用交接包 → 沈砚接稿统一分派（资产全量建档 → 分镜按集分批 → QC 按批）——**先全剧本、再由制作人分配，不在剧本中途插制作** |
| **边写边制（高级，明示才用）** | 赶工期/长篇（≥30 集，含现实题材轻量版）连载 | 每批剧本在 crew 侧走完其质检流程 → 本团跟做该批；返修稿绝不流入，剧本改动→受影响镜头卡作废重判 |

drama-crew 标准交付始终包含**定稿剧本原文 + 终审评分报告 + 合规报告**，并标 `review_state=reviewed`；正典账本已启用或继承时必须随包提供，实际低风险且无既有账本时接受带明确适用性依据、足以承载必要状态的合并交付记录。触发口径以 crew 侧 `drama-crew/references/world-bible.md` 唯一口径为准（跨 Skill 引用，本包无本地副本），已触发/继承的项目另带「世界观档案」（六模块：空间地理/时间线/力量规则体系/势力格局/视觉奇观/设定边界）。缺真正必需的正典、终审或合规材料仍阻塞，不为凑固定件数要求空账本，也不把已审项目降成直通模式。直通交接只要求剧本与实际存在的账本/世界观，并标「未终审稿（直通模式）」及 `review_state=unreviewed`。**制作侧只验收与消费，不重新推定缺失材料**：交接材料按「命中片段注入」消费进各成员模板（v1.10.1，见 role-cards 沈砚必做 1）——丹青按六模块命中内容消费+实际存在的账本/合并记录状态行；景川消费正典命中行+世界观②③④⑥；闻笙只消费 crew 交接单中的**文字声音指纹原文**与 `source_locator`（用于说话方式，不把它当作实际音色资产，也不从账本猜声音）；陆离/严恪消费合规结论与终审未闭环项；只贴命中片段不贴全文。第 0 步按实际来源和审核状态验收：有既有项目或交接状态就继承；只有用户自带稿且没有可继承的审核记录时才按裸本接收。「直接做」「跳过引导」只改变展示与推进方式，不把已审项目降成裸本或未审稿。**剧本返修发生在制作中 → 仅受影响镜头卡作废重判**。

**两团共同翻译原则（v1.7.4 定版，drama-crew 侧同步）**：drama-crew 负责定义人物欲望、阻力、选择、代价、信息变化、关系变化和观众期待；drama-studio 负责把这些内容**翻译**成可见、可听、可剪的表演与镜头。制作侧可以改变表现方式，**不能改变故事事实和因果**；一种技术方案无法实现时，先识别并**保留原节拍的叙事功能**，再换用其他镜头、表演、声音或剪辑表达（与 storyboard-craft §14「模型限制改变表达方法不改变故事事实」同源）。

## 流程总览

### 第 0 步：配置引导与接稿识别
先读本包 [references/startup-guide.md](references/startup-guide.md)：新项目默认展示完整功能导航和自动填好的本次配置；续作继承，只显示本次配置/变化；用户说“跳过引导”就省略导航与长表，回显必要设置后直达当前环节。信息足够不追加接稿停点，“展开全部功能”只恢复展示。跳过不改变 `review_state`、资产确认、预算或发布权限。

按前置路由表判断本次范围，再验收实际输入；已有材料先读，只问影响当前产物的缺项，不让用户先填完整问卷。无任务内容只问目标或所需稿件，不自造剧情；只做资产/声音/局部提示词不启动整剧链。

| 模式 | 条件 | 输入 |
|---|---|---|
| 标准交接 | 从 drama-crew 来（走过终审/合规，`review_state=reviewed`） | 定稿剧本 + 终审报告 + 合规报告 + 正典账本（已启用/继承时）或带适用性依据且足以承载必要状态的合并交付记录（实际低风险且无既有账本时）+ 世界观档案（按唯一口径已触发/继承时）；缺真正必需材料阻塞 |
| 未审稿模式（直通交接） | 从 drama-crew 来但交接单标「未终审稿（直通模式）」或 `review_state=unreviewed` | 定稿剧本+正典账本（若有）+世界观档案（若有）——**不要求补齐四样、不因缺报告拒收**；终审/合规证据缺失记 `not_provided`，不得写成「无风险」；严恪按未审稿合同核查并通报「本稿未走 crew 终审，制作 QC 不等于剧本终审」 |
| 裸本试制/整剧交接 | 用户自带剧本，且无可继承的项目审核记录 | 剧本原文；题材/载体/平台先识别，仅影响当前产物的缺项才问；整剧先定分批节奏，已约定则继承 |
| 资产模式 | 用户只要角色/场景图 | 剧本或人物描述 |

本次配置按 `startup-guide.md` §3 自动填：项目/模式/本次范围、输入来源与 `review_state`、媒介与画幅、目标语言/口音、单集时长与单次 Clip 时长、模型/渠道、格式路由、功能及执行状态；逐项带已确认/识别建议/待确认/待就绪与来源，未知或建议不得冒充已锁事实。目标明确单次 30 秒即匹配八段，不要求再答一次专项开关；英文或 30 秒仅是参考时不推定目标。标准/直通交接同时验收版本锁字段（项目标识 / script_rev / 目标成片时长 / 主画幅与用途；未携带 script_rev 时按 1 处理并通报其为接收默认）。用户自带裸本记 `review_state=not_provided`，不把未提供写成已审无风险。
**execution 附加确认（v1.8.0 · 仅代生成时）**：确认行追加 `/ 目标成片时长 [X] / 用途 [X] / 分辨率·帧率 [X]`；成片可交付以**可剪素材总量覆盖目标成片时长**为守恒判断（不搬固定比例阈值），缺素材如实报告缺口，不缩水目标时长。
**execution 调用责任（v1.8.1 收口 · v1.13.5 工具接线）**：资产图调用归丹青、逐镜图片/视频素材调用归景川；默认本机调用先用 `scripts/dreamina_route.py` 生成官方 Dreamina 命令预览，核对路由、模型、时长、画幅、分辨率和参考素材后，完成耗积分告知才执行返回的命令。若实际工具只能由宿主调用，沈砚仅中转提示词、任务 ID 与结果路径，不代写专业产出。**谁实际发起调用，谁在调用当时记录**：对象 ID（资产 ID / Shot / Clip）、模型任务 ID、状态、结果路径、实际成本（或 unknown）、尝试次数；陆离只汇总并消费这份记录，不得事后猜补。`planning_only` 不调用、不记录、不询问。
**快做分流**：用户只要一两个镜头/一张角色图时，不建团队，沈砚**临时兼任景川职责**（「主理人不代写」的唯一例外，不视为代写违规）按规范出，不跑全流程。

### 第 1 步：资产建档（调「丹青」，按真实视觉缺口触发）
**第一动作（v1.8.1 资产缺口自动路由收口）**：沈砚先核对剧本、已锁事实、现有资产与本地素材索引是否可达，只负责协调下发；丹青据作品任务首次判断本批的**视觉观看重点与资产表现机会**，再判断**真实视觉缺口**——分镜所需的主要人物身份 / 场景拓扑 / 承载连续性的关键道具状态 / 必要精确端点。命中角色参考、场景美术或参考资产职责时，Read `references/case-library/README.md`，按用途标签只取命中的稳定 ID 与 metadata 状态；获准且本地根已绑定时才把该 ID 单条 TXT 交丹青，不传整库。**只有已有资产库完整覆盖本批这些要素时**才自动跳过本步与资产确认弹窗，直接进第 2 步（M1 由景川首批生成），不要求用户主动说「跳过资产」；剧本文字只用于判断需要什么，**不能替代可复用视觉资产**。确需新增主要资产时调丹青：Read `references/role-cards.md` 取丹青角色卡；Read `references/asset-library.md` 的视觉资产相关节（跳过只归闻笙的 §7）原文贴进模板；按 `references/external-platforms.md` §2 从已有规则与本地方法中只取命中范围。在既有资产条目/复用说明内写明参考的实际控制职责，并使用**参考资产就绪三态**（`prompt_only / file_ready / external_mount_plan`）与**身份/状态决策四词**（`reuse / new_variant / new_asset / unresolved`）。一次性且不承载状态的普通小物件及未命名群演并入场景资产，不单独建档。
**产出**：资产三库 JSON + 资产索引 + 角色三件套 + 场景资产板 + 道具档案 + **全片风格母版 M1 初版** + 复用说明 → **立即落盘 `02_资产/` 并 present_files 展示**。就绪状态与身份决策写进既有资产条目/复用说明，不增加交付物。**资产分级（减负）**：主角与高频角色做三件套（定妆照+肖像特写+三视图）；低频配角先做单张锚定图，确认复用后再升级三件套；整剧交接只建立全量资产索引，实体化先做 E01 与当前批次会用到的资产，其余按批次补。M1 按 storyboard-craft §8 八字段生成，并入下方资产确认弹窗 2 一并锁定。
**资产确认（弹窗 2，仅首项目/新增主要资产时）**：向用户展示新增的主要角色、核心场景或承重关键道具锚定与场景基调（**先展示资产文件再弹窗确认**，风格母版 M1 一并展示），确认后锁定；后续复用不再弹。

### 第 2 步：分镜装配（调「景川」）
**第一动作**：Read 景川角色卡；景川先据作品任务与已锁约束判断本批**观看重点、表现机会和各镜职责**。命中摄影、空间运动、动作/特效、表演、复杂交互或编辑接续问题时，沈砚 Read `references/case-library/README.md`，按用途标签把命中稳定 ID 与 metadata 状态直接交给景川；只有获准且本地根已绑定时才附该 ID 单条 TXT。没有本地原文就按现有规则原创，不伪称已读，也不因候选未复现停止合理规划。沈砚继续让其他命中材料可达并原文下发：Read `shot-contract.md` + `prompt-assembly.md` + `storyboard-craft.md` 命中条目，按 `references/external-platforms.md` §2 读取已有规则与本地方法，再由景川选择相称的方法组合；**按装配映射表** Read 命中的 `dimensions/` 维度卡原文贴进模板。注入内容必须覆盖镜头修订血缘、首尾帧边界、同句对白/OS/VO 单一正文、`show_now` / `withhold_now` 悬念权限、provider 条件续接及承重/失败证据驱动的表演规则。采用的方法不另立清单，由景川写进既有资产复用说明、分镜总表「叙事目的」以及格式路由后的实际画面/声音/参考职责；不采用的候选不占槽位。**按已选目标视频模型（用户指定或第 0 步默认）**，先按上方常用模型别名路由（或模型卡文件名）定位模型卡，再 Read 对应 `references/models/*.md`；规划时同时定位实际 provider/adapter 卡，默认由 Dreamina 执行 Seedance 2.0/2.5 时必须同时读取 `seedance.md` 与 `dreamina.md`。把模型/版本、支持模式、时长、画幅、分辨率、参考资产上限、首尾帧、多镜头、原生音频或声音控制边界、已知冲突、失败降级、提示词适配与 provider/adapter 口径的命中原文贴进景川模板；仅用户明确暂不选型时写「通用保守模式」。已锁定 30 秒直出专项与 Seedance 2.5 时不被普通 `seedance2.0fast_vip` / 15 秒默认覆盖。`execution` 前由实际调用者按本次 `provider / adapter / version` 的实时 schema 复核，实时接口与模型卡冲突时以实时接口为准；接口不支持 30 秒时保留 30 秒规划并报告执行差异，不把两次 15 秒冒充一次调用。**风格母版 M1 已在资产阶段生成锁定**——景川只继承引用，不重新生成；**跳过资产阶段时，景川在首批分镜开头生成 M1，直接用于本批提示词并随首批分镜展示，不新增停点**（M1 生成权归景川，不归沈砚——沈砚不代写专业产出）。
**逐镜流程**：六问判读 → 分镜总表一行（含情绪强度 1-10）→ 镜头卡写定（冻结时机按 shot-contract：付费生成/拍摄前锁死，planning_only 直接更新总表；同一叙事职责内修改**保留 Shot ID，提升修订号**，拆分/合并/改变职责才新建 ID）→ 标 `show_now` / `withhold_now` → 按 Clip 选择 §2 格式路由并唯一终编（同一句对白/OS/VO 的**逐字正文只出现一次**）→ 双版本提示词 → 装配自检。
**产出**：分镜总表 + 逐 Clip 路由后视频提示词（通用四区块；明确启用的 30 秒直出专项为固定八段；每 Clip 一组且不双交；图片提示词按图片职责另写）。含对白/OS/VO 的批次本步先完成分镜与提示词草案，交第 3 步声音设计后回注景川，才冻结并正式生成；新角色尚无母音色时只生成筛选所需候选，不先批量做完临时对白片。无声音依赖的素材可先生成。`execution` 仍由景川实际调用并即时记录最低六字段，`planning_only` 只交文本 → **每批立即落盘 `03_分镜/storyboard_SXX.md` + `prompts_SXX.md` 并 present_files 展示**（用户可逐批纠偏，不必等整剧分镜全做完）。
**批头版本锁（v1.8.1，与 crew 交接块字段对齐）**：每批分镜总表批头记录 **项目标识 / 剧本修订号（script_rev，取自 crew 交接块）/ 分镜修订号（storyboard_rev，首版 = 1）/ 主画幅与用途**。本批发生实质修改时，仅该受影响批次的 `storyboard_rev +1`，未受影响批次保留原修订号；具体镜头同一叙事职责内保留 Shot ID 升修订号，拆分、合并或改变职责才创建新 Shot ID 并停用旧 ID。**失效范围合同**：剧本/正典/世界观实质修改后，**只使依赖该修改的分镜、提示词、时长结论与 QC 结论失效**，未受影响部分保留沿用；**旧 QC 报告不得为新版本背书**。**画幅版本规则**：新增副画幅（如 16:9 补 9:16 版）不是裁切——副画幅按新画幅独立重构镜头功能与构图后重出该部分分镜与提示词，禁止把 16:9 成片直接裁成 9:16。

### 第 3 步：声音（调「闻笙」，有台词/配音/配乐需求时）
**第一动作**：Read 闻笙角色卡；Read `asset-library.md` 第 7 节 + `dimensions/dim-audio.md`；有配乐需求才再读 `dimensions/dim-music.md`。命中对白声音视点、口型、声线连续或音乐表演问题时，从 `references/case-library/README.md` 只取用途匹配的稳定 ID 与状态；本地单条原文的读取边界同上。闻笙先按本批观看重点判断哪些声音承担人物感受、画内动作或画外空间，再选择命中的已有方法，不为齐层数填满声音。声音设计以本批分镜草案与台词为输入，不等待正式视频生成；由沈砚把命中的声音卡/表演变化/OS·VO 类型和母音色状态回注景川既有模板，再由景川冻结最终提示词并调用。这是第 2/3 步内部依赖回传，不增加阶段、角色或确认点。
**产出**：声音指纹与母音色卡集 + 逐句声音表演参数表 + **配乐方案**（槽位制情绪床包/母题变奏分支/授权曲库检索词 三选一按需求）+ 三对齐核对表 + 配乐版权自查结论 → **立即落盘 `04_声音/` 并 present_files 展示**。`planning_only` 只建立母音色候选与冻结计划；`execution` 从**该角色首次发声**开始试听筛选，冻结后在接口支持时将已冻结母音色作为后续正式对白镜的原生音频参考，并核对该角色此前临时对白，来源候选镜经音色与画面核对合格可直接转正式，其他未匹配样本只重生受影响 Clip；接口不支持或实听不稳才降级外部 TTS＋对口型。

### 第 4 步：剪辑合成（调「陆离」，要出成片时）
**第一动作**：Read 陆离角色卡；把分镜总表+配音参数表+素材清单原文下传；`execution` 同时把 `scripts/assemble_timeline.py` 的调用方式贴入模板，由陆离按时间线顺序合成。
**产出**：时间线编排表 + 混音参数表 + 成片自检报告（红黄绿）+ 发布交接清单 → **立即落盘 `05_成片/` 并 present_files 展示**（成片定稿前先展示时间线/自检报告供纠偏）。

### 第 5 步：QC（调「严恪」，按需）
**第一动作**：Read 严恪角色卡；Read `references/failure-atlas.md` 原文贴进模板。严恪按各镜承担的观看功能核对采用方法是否真正落进画面/声音与参考职责，并以当前能力、素材和具体失败为据判断降级，不把方法名或旧风险清单当成完成证明。
**产出**：核查表（类别|命中项|位置|证据|修复建议）+ 情绪曲线验证 + 整批交付核对清单 + 结论（通过/返修-指明责任项）→ **立即落盘 `05_成片/delivery_check.md` 并 present_files 展示**。**QC 双层结论（v1.8.1 · execution 成片时）**：分**技术可用**（能播放、时长/分辨率/画幅正确、音画同步）与**语义合格**（身份/动作因果/故事事实/声音/口型/连续性正确）两层分别给结论——技术可用 ≠ 语义合格，两层都过才算通过；最终候选成片**正常速度完整观看**后再下结论，不跳看抽样。依赖镜头在生成过程中只做内联最小语义核对，严恪启用时，其批次结论覆盖此前接受状态，不把按批 QC 变成逐镜关卡。
**返修路由**：提示词问题回景川（按重拍协议定位责任层与修复范围）；资产问题回丹青；声音问题回闻笙；**同类返修仍不过且故障已稳定复现，或将触及用户批准预算/工具硬上限时，回沈砚上报用户**。

### 第 6 步：交付、资产归档与清理
整合：资产库 + 分镜总表 + 提示词集 +（配音参数表/成片自检）+ QC 报告，保留成员原格式（提示词不加代码围栏），写 Markdown 成稿并 present_files；收尾清理团队。
**文件管理（按 `references/file-management.md`）**：①初始化/核对项目目录（01 剧本→07 交接）；②资产按命名规范归档进 `02_资产/`，临时文件一律带 `_draft/_retry/_preview` 后缀放 `06_临时/`；③**批次进行中不删除、不询问**（临时文件留在 06，避免打断创作节奏）；④**整剧交付时**若确有清理候选，按审计制一次出清单、一次确认、一次清理 + 打包交接包（无候选不生成空报告不询问）；⑤清理留一行记录（清了什么/留了什么）。

## 维度装配机制（本 skill 核心）

```
景川接到一批镜头 → 先判断观看重点、表现机会与逐镜职责，再诊断类型（对话/特写/打斗/建立/悬疑/转场）
→ 从已有规则与本地方法选相称组合，查装配映射表得必装+选装维度
→ 沈砚按命中维度 Read dimensions/ 卡片原文贴进景川模板
→ 景川按 Clip 唯一终编路由后视频提示词（通用四区块 / 30 秒直出专项八段式；每组一次提交，组内按需多镜）
→ 冲突按九层仲裁（安全>平台>用户硬性>参考契约>连续性>物理>剪辑逻辑>风格>默认）
→ 严恪过失败图谱
```

**装配映射速查**（全表见 prompt-assembly.md 第 1 节）：对话正反打=站位+表演+音效；情绪特写=表演+光影；打斗=景别+运镜+动作+光影；**打斗含法术/能量/变身时再加特效卡**；建立=景别+运镜+光影+风格；悬疑揭示=光影+表演+站位+音效；转场空镜=风格+光影+运镜。**要音乐 cue 时（用户明示或剧本标注）任何类型都加装配 dim-music**（只取契约要素+短 cue 矩阵+修复规则；槽位制/母题法/版权节归闻笙不贴景川）。

## 避坑清单

- 引导展示不新增审批：接稿只问当前必要缺项，新增主要资产沿用原确认点，已有授权直接继承；付费、IP 或发布另按实际边界处理。快做分流不建团队，沈砚临时兼任景川职责（「主理人不代写」唯一例外）。
- **并行调多个生成器=人脸漂移主因**——所有维度景川唯一终编。
- **禁止并行多 skill 同时生成同一镜头**；维度卡是规范不是生成器。
- 镜头卡未冻结不投喂；可拍证据按本镜职责写入，静态建立、停留或余波镜可用空间基线、持续状态、细微反应或声音证据，不硬造转折、压制或破坏。
- 资产缺口**自动路由（v1.8.1 收口）**：分镜前先判断真实视觉缺口——只有已有资产库完整覆盖本批主要人物身份/场景拓扑/承载连续性的关键道具状态/必要精确端点时，才自动跳过丹青与资产确认弹窗；剧本文字不能替代资产。一次性普通小物件并入场景资产；新增主要资产才走建档与既有弹窗。
- 提示词不加代码围栏、不出现第三方视频模型名（统一「AI 视频模型」）。
- 站位禁弱词（附近/旁边）；一镜一主导动作；一镜一个内容类型。
- 分镜总表是唯一事实源，禁止另建平行版本。
- 剧本返修→受影响镜头卡作废重判，不拿旧片硬接。
- 专项规范一律按需加载贴进模板，不堆进本主文件。
- **经验库必须转起来**：产出被用户修改/纠正、用户要求吸收外部案例，或定向补项取得新材料后，沈砚按 `references/learnings.md` 形成入库候选并完成项目适配与相称核验；用户明确说「记住/写入经验库」或认可条目时才持久化/升格。重复来源优先补全共享 metadata 的既有 ID 与未核状态，不另造索引；低置信或待讨论不自动作为生产或终审规则下发，不因一次搜索自动 push。
- **临时文件批次不删、整剧一次清**：批次进行中不动 `06_临时/`（不删不问）；整剧交付时按 file-management.md 审计制一次出清单一次确认（确有候选才生成清单，无候选不生成空报告不询问）；02_资产/ 永不清理；跨会话只读 02+03——临时区不作为事实源，但未完成 execution 任务确有依赖时可按需读取本任务临时文件（读取≠依赖，恢复后仍按整剧交付时机统一清理）。

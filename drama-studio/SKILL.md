## 适用场景

已定稿（或已有）剧本要落地为 AI 视频：资产建档 → 分镜 → 逐组视频提示词 → QC 交付。剧本创作不在本 skill（归 `drama-crew` 短剧创作团）。

## 宿主工具与依赖适配

本文与角色卡中的 TeamCreate、Agent、Read、SendMessage、present_files 是职责名称，执行前映射当前宿主实际可用工具，不调用不存在的接口。文件读取用宿主文件工具；产出先保存，再以真实路径链接或宿主文件预览展示。没有 present_files 不阻塞交付，没有 TeamCreate 也不要求建立可见任务窗口。

有子代理能力也默认贯通；只有独立核查、可独立开展的任务或真实专项缺口值得分工时才按角色卡派发，遵守宿主授权。角色名不等于工具 agent_type，不自动创建可见窗口。共享文件按所有权修改，依赖工作顺序执行，不通过反复复述产物传递事实。

无子代理能力时照常按单执行者模式完成规划、资产、视听终编与自检，不把默认贯通当能力降级。本人复读只记自检；要求独立核查/终审的范围保持未审，不能自行标 reviewed；只阻塞依赖缺失审查的放行，其余任务继续。已有合法审核记录按范围和版本继承。

两包并排安装可使用完整共用表演库与案例路由。仅安装一包时，先核所需跨包文件：普通创作可使用本包人物、对白与动作方法；普通制作规划可消费用户已有正文/资产及本包分镜方法。缺共用库时明确本次未参考该库，不猜原文或来源；确需另一包权威格式/世界规则或专项时，只暂缓依赖项并提示安装对应包。已有文件继续作为事实输入，不因此重写故事。私有案例绑定已配置却失效时仍按案例库规则报错，不把本段当作回退过期快照的许可。

## 核心原则

1. **默认贯通执行**：同一执行者连续完成需求判断、资产引用、分镜声画终编和自检；沈砚、丹青、景川等是可取用的专业职责，不以改角色名制造多轮协作。
2. **唯一事实源**：分镜总表一镜一行，全项目**唯一 Schema**（v1.7.2 定版，其他文件只引用不复写）：`镜号 / 所属Clip / 场景 / 时长 / 景别 / 运镜 / 光影 / 站位 / 表演 / 台词·音效 / 资产ID / 情绪强度1-10 / 叙事目的（七分类，见 storyboard-craft §16；答不上"为什么存在"的镜回查隐性价值——显性隐性都立不住才删除或合并）/ 结尾选型`。角色卡、维度卡、storyboard-craft 均引用本行，禁止另立字段清单。
3. **唯一终编**：每个镜头的维度由景川统一整合，再按 Clip 成组终编成一条路由后视频提示词——所有时长统一中文八段式且不双交；多生成器并行可能增加身份与风格漂移风险，仍由景川统一终编。
4. **写与查分离**：景川负责交付完整性与本职装配自检（自检清单照跑），自检按实际结果标注；用户要求独立审查、重大风险或正式成片放行时另做独立核查，不对所有草案机械增加审批。
5. **问题先行、专业选择**：先锁任务入口、项目约束、当前阶段与当前创作问题；沈砚确认材料与权限，丹青/景川/闻笙各选一个主方法并把可观察证据落进原产出。专项缺失时用现有通用技法继续，方法名不构成通过证据。
6. **最低必要资产先建档、分镜只引用**：先复用/建立人物身份、承重场景拓扑和关键道具状态；视频参考默认保持独立角色参考，并在景川批准构图后由丹青组装缺失的按集参考总表。场景/道具职责可在资产记录和 Prompt 中指向真实文件 + Panel；提交生成接口的仍是实际文件路径，必要时窄导出相应区域。规划不冒充就绪；一次性普通小物件可并入场景，纯背景群演按 asset-library §1 复用场景描述/已有 Panel，群体外观有真实缺口时补多人参考板；承担事件行动/回应或需独立身份的未具名人物仍单独建参考。
7. **事实通过原产物传递**：复用原文件、版本和真实引用，不强制主理人逐次中转。只有拆分任务才提供必要交接。
8. **过程透明化（防黑盒）**：每个阶段产出即落盘、按「展示分级」展示给用户（**落盘 ≠ 打断**），用户可阶段间纠偏，见「过程透明化机制」。

## 过程透明化机制（防黑盒 · 用户全程可见可纠偏）

**用户看到"在工作"却不知道在产出什么 = 黑盒，禁止。** 制作侧每阶段产出必须即时可见：

1. **即时落盘**：按 `references/file-management.md` 沿用本项目既有文件/章节和实际工序目录；资产、分镜、提示词、声音、成片与 QC 只在实际产出时落盘，不为每次回传另造文件。
2. **展示分级（v1.8.0 收窄 · 落盘 ≠ 打断）**：每个产出**落盘即留档**；**决策节点主动 present_files 展示**并一句话通报（`{阶段}产出已生成：{文件名}，可查看纠偏`）——其他非决策中间文件不逐个打断，在下一个自然节点合并通报文件名。
3. **关键关卡必展（决策节点清单）**：①资产建档产出（角色参考资产/按需群演参考/场景板，资产确认弹窗前）；②每批分镜总表+提示词集；③成片自检与 QC 报告；④最终整合交付——这四类必须展示文件。 资产按丹青原交付模板展示同源工作清单、真实图册与分离的纯提示词；多个 Panel 共用原文件，缺图明确，不用路径列表冒充实图。
4. **阶段间纠偏**：用户在任意阶段产出展示后可要求调整（改资产/改镜头/改提示词/改声音），纠偏发生在阶段间而非成片后；调整按「调整规则」表执行（资产问题回丹青、提示词问题回景川；按重拍协议先定责任层和修复范围）。
5. **最终交付**：第 6 步整合全部产出再次 present_files，并按 file-management 审计临时文件，满足授权和依赖条件才清理。

| 严恪：独立核查 | 用户要求、重大风险、正式成片放行 | 自检不冒充独立审查；日常局部修改只查影响范围 |

角色卡保留详细方法与专项模板；模板仅实际派单使用，不要求在单上下文中逐角色填表。

生图与视频工具分别继承，CLI/API/网页只决定操作渠道，不授权换掉已指定模型，按 external-platforms 的工具/模型/渠道规则执行。参考总表的综合视觉图板职责、人物实图绑定与自适应版式以 asset-library §4 为准；明确图板请求优先于常规资产模式的免总表分支。

## 与 drama-crew 的衔接协议（三模式）

| 模式 | 适用 | 流程 |
|---|---|---|
| **单集试制（默认推荐）** | 所有项目起点 | drama-crew 出 E01 定稿 → 验收适用交接包 → 本团做 E01 → 用户验证效果（资产/分镜/提示词风格）→ 满意后批量 |
| **整剧交接** | 剧本已全部定稿 | 验收适用交接包 → 沈砚接稿统一分派（资产全量建档 → 分镜按集分批 → QC 按批）——**先全剧本、再由制作人分配，不在剧本中途插制作** |
| **边写边制（高级，明示才用）** | 赶工期/长篇（≥30 集，含现实题材轻量版）连载 | 每批剧本在 crew 侧走完其质检流程 → 本团跟做该批；返修稿绝不流入，剧本改动→受影响镜头卡作废重判 |

合规、终审及连续性可在同一验收文件分区保存，须保留各自审核者、范围、版本、证据定位与独立结论；已有独立报告仍可直接引用。drama-crew 标准交付始终包含**定稿剧本原文 + 终审评分报告 + 合规报告**，并标 `review_state=reviewed`；正典账本已启用或继承时必须随包提供，实际低风险且无既有账本时接受带明确适用性依据、足以承载必要状态的合并交付记录。触发口径以 crew 侧 `drama-crew/references/world-bible.md` 唯一口径为准（跨 Skill 引用，本包无本地副本），已触发/继承的项目另带「世界观档案」（六模块：空间地理/时间线/力量规则体系/势力格局/视觉奇观/设定边界）。缺真正必需的正典、终审或合规材料仍阻塞，不为凑固定件数要求空账本，也不把已审项目降成直通模式。直通交接只要求剧本与实际存在的账本/世界观，并标「未终审稿（直通模式）」及 `review_state=unreviewed`。**制作侧只验收与消费，不重新推定缺失材料**：交接材料按「命中片段注入」消费进各成员模板（v1.10.1，见 role-cards 沈砚必做 1）——丹青按六模块命中内容消费+实际存在的账本/合并记录状态行；景川消费正典命中行+世界观②③④⑥；闻笙只消费 crew 交接单中的**文字声音指纹原文**与 `source_locator`（用于说话方式，不把它当作实际音色资产，也不从账本猜声音）；陆离/严恪消费合规结论与终审未闭环项；只贴命中片段不贴全文。第 0 步按实际来源和审核状态验收：有既有项目或交接状态就继承；只有用户自带稿且没有可继承的审核记录时才按裸本接收。「直接做」「跳过引导」只改变展示与推进方式，不把已审项目降成裸本或未审稿。

**制作中发现问题先定责任层**：既定事实下的机位、路线、遮挡、表演可读性由 Studio 修正；改变致因、行动选择、伤亡/损坏结果、知情或后续兑现时回 Crew 唯一正文责任位。用户已授权补齐该因果时直接在授权范围内修订，不重复索取同一许可，也不把“继续制作”扩大成任意改剧情。回源时指明缺失事实、已有证据和受影响节拍，改完同步实际启用的设定/连续性与伏笔记录，再更新依赖的分镜、空间/道具状态、声音时窗、提示词和未提交输入。新事实沿原审核方式重判，未受影响部分保留；已提交快照不可回写，新候选与旧 take 分开，旧 QC 不为新稿背书。用户要求逐次提交确认时，修订稿仍按其确认范围处理。具体桥段与人物只留项目，通用规则仅保存诊断和传播条件。

**两团共同翻译原则（drama-crew 侧同步）**：drama-crew 定义人物欲望、阻力、选择、代价、故事可见/可听事件、机制与状态、信息/关系变化、观众期待及必要披露时机；drama-studio 负责把这些内容**翻译**成可见、可听、可剪的调度、表演、摄影、声音与特效。制作侧可以改变表现方式，**不能改变故事事实和因果**；一种技术方案无法实现时，先识别并**保留原节拍的叙事功能**，再换用其他表达（与 storyboard-craft §14 同源）。案例只能帮助选择相称机制，必须经过“案例 → 适合本场的机制 → 本场具体分镜/提示词”，不能把原提示词直接移植或用案例补正典；没有案例时通用技法照常成立。

## 流程总览

### 第 0 步：配置引导与接稿识别
先读本包 [references/startup-guide.md](references/startup-guide.md)：新项目默认简述本次范围、已有配置和必要缺项，用户要求展开才展示完整功能导航；续作继承，只显示本次配置/变化；用户说“跳过引导”就省略导航与长表，回显必要设置后直达当前环节。信息足够不追加接稿停点，“展开全部功能”只恢复展示。跳过不改变 `review_state`、资产确认、预算或发布权限。

按前置路由表判断本次范围，再验收实际输入；已有材料先读，只问影响当前产物的缺项，不让用户先填完整问卷。无任务内容只问目标或所需稿件，不自造剧情；只做资产/声音/局部提示词不启动整剧链。

| 模式 | 条件 | 输入 |
|---|---|---|
| 标准交接 | 从 drama-crew 来（走过终审/合规，`review_state=reviewed`） | 定稿剧本 + 终审报告 + 合规报告 + 正典账本（已启用/继承时）或带适用性依据且足以承载必要状态的合并交付记录（实际低风险且无既有账本时）+ 世界观档案（按唯一口径已触发/继承时）；缺真正必需材料阻塞 |
| 未审稿模式（直通交接） | 从 drama-crew 来但交接单标「未终审稿（直通模式）」或 `review_state=unreviewed` | 定稿剧本+正典账本（若有）+世界观档案（若有）——**不要求补齐四样、不因缺报告拒收**；终审/合规证据缺失记 `not_provided`，不得写成「无风险」；严恪按未审稿合同核查并通报「本稿未走 crew 终审，制作 QC 不等于剧本终审」 |
| 裸本试制/整剧交接 | 用户自带剧本，且无可继承的项目审核记录 | 剧本原文；题材/载体/平台先识别，仅影响当前产物的缺项才问；整剧先定分批节奏，已约定则继承 |
| 资产模式 | 用户只要角色/场景图 | 剧本或人物描述 |

**故事输入三态诊断（在既有 intake 内处理）**：①故事事实、过程与结果足够但表现方法未指定——直接由景川自主选择调度、表演、摄影、声音与特效；②文字泛化——回读原场正文、集纲与活动正典，推断本场观看任务并定位缺失的因果，不因标题没有“打斗/巨物”等词跳过动作、异常、证据、关系、喜剧、追逐或表演路由；③必要故事事实仍缺失或冲突——只把依赖该事实的内容退回 Crew 原故事责任位，或确需用户决定的事实选择，其余独立规划继续。可继续部分必须确实不依赖待定原因或结果，不得默选未知机制、伤态、伤亡或结局；确需先探索依赖部分时，只能列明前提的候选分支，未裁决前不得冻结、写成当前事实或提交生成。缺少非承重制作细节不构成剧本阻塞，制作侧自行补足并标明设计依据。

本次配置按 `startup-guide.md` §3 自动填：项目/模式/本次范围、输入来源与 `review_state`、媒介与画幅、目标语言/口音、单集时长与单次 Clip 时长、模型/渠道、格式路由、功能及执行状态；逐项带已确认/识别建议/待确认/待就绪与来源，未知或建议不得冒充已锁事实。目标明确单次 30 秒即匹配八段，不要求再答一次专项开关；英文或 30 秒仅是参考时不推定目标。标准/直通交接同时验收版本锁字段（项目标识 / script_rev / 目标成片时长 / 主画幅与用途；未携带 script_rev 时按 1 处理并通报其为接收默认）。用户自带裸本记 `review_state=not_provided`，不把未提供写成已审无风险。
**execution 附加确认（v1.8.0 · 仅代生成时）**：确认行追加 `/ 目标成片时长 [X] / 用途 [X] / 分辨率·帧率 [X]`；成片可交付以**可剪素材总量覆盖目标成片时长**为守恒判断（不搬固定比例阈值），缺素材如实报告缺口，不缩水目标时长。
**execution 调用责任（v1.8.1 收口 · v1.21.4 工具接线）**：资产图调用归丹青、逐镜图片/视频素材调用归景川。渠道按已锁模型分流：Dreamina/Seedance 先用 `scripts/dreamina_route.py` 生成官方命令预览，核对路由、模型、时长、画幅、分辨率和参考素材后，完成耗积分告知才执行返回的命令；本机 MiniMax H3 先读 `references/h3-comfy-mode-routing.md` 按输入选 11/20/21/30，再由宿主走 Comfy `:8188`（Hermes 执行 skill `h3-local-video`），不调用 dreamina CLI，也不把 11 号当人物连续性默认。若实际工具只能由宿主调用，当前执行者直接使用宿主工具并记录真实结果。**谁实际发起调用，谁在调用当时记录**：对象 ID（资产 ID / Shot / Clip）、模型任务 ID、状态、结果路径、实际成本（或 unknown）、尝试次数，及本次实际按序上传的每个文件路径、角色/母板/状态职责与禁止输入；记录缺失时，该 take 不得作为正式候选或连续性依据，不能事后凭提示词猜补。陆离只汇总并消费这份记录。冻结请求与实际命令、按序参考及回执的比对、成本异常处理见 `references/models/dreamina.md` 与 `references/file-management.md`，不以预览命令代替实际调用事实。`planning_only` 不调用、不记录、不询问。

### 第 1 步：资产建档（调「丹青」，按真实视觉缺口触发）
**正文接收约定**：接收 Crew 的唯一标准剧本正文，阅读与制作共用；人物基础视觉事实、设定、集纲、正典及版本/审核状态从必要配套资料读取，不要求恢复内部制作版。正文已自然提供环境、站位、动作、道具与表演状态；缺失或矛盾的承重事实局部退回，摄影设计仍由 Studio 完成。

**第一动作**：沈砚先锁任务入口、项目约束、当前资产阶段与具体视觉问题，核对剧本、已锁事实、现有资产与素材索引是否可达；丹青先复用或建立本批最低必要的主要人物身份、承重场景拓扑、关键道具状态与精确端点。案例绑定有效时必须从 canonical metadata 匹配所选 ID，并核输入缺项、完整性、模型与来源/观看/复现状态；绑定失败只停案例消费，现有通用规则继续规划。确需方法时，沈砚在原规范注入说明写清用途、适用/排除条件、来源/版本、资产落位、可观察证据与失败返回，由丹青选择，不传整库。只有已有资产完整覆盖最低必要要素时才跳过本步；剧本文字不能替代可复用视觉资产。一次性普通小物件可并入场景资产；纯背景群演按 asset-library §1 复用场景描述/已有 Panel，群体外观有真实缺口时补多人参考板；承担事件行动/回应或需独立身份的未具名人物仍单独建参考。
**产出**：本次实际启用的资产库 JSON（无该类资产不造空库）+ 既有资产索引 + 本集逐角色的独立角色参考资产 + 本集按缺口规划的场景/道具/群演参考与**按集参考总表**（视频任务）+ **全片风格母版 M1 初版** + 复用说明 → 立即落盘 `02_资产/` 并展示。本集 N 个实际出镜故事角色对应 N 份独立角色参考，默认一人一张角色综合设定板（大幅清晰正脸头肩肖像+完整正/侧/背全身+必要细节），配角及承担投币、裁决、递物、见证或结尾回应等事件职能的未具名/短暂出镜者都计入；纯画外声不编造外观，纯背景群演的描述/按需多人参考另按 asset-library §1，不计入故事角色板数。所需参考数不等于本轮新文件数：身份、外观与状态匹配的既有综合板/分图跨集、跨 Clip 复用，新角色或真实外观变化只补所需新板、变体或清晰度缺项；“一张”与图种分开判断，明确肖像等图种才覆盖默认综合板，统一按 asset-library §2。简单场景通常另共享一张按集参考总表，清楚的场景或道具 Panel 可直接履责，不机械另出文件；总表中实际关键道具、关键构图和纯场景区域分别履责，构图数量不能替代道具状态或角色参考。规划可先锁场景事实/拓扑和调度草案，按集总表场景区可作为首次获批视觉实现；实际生成前参考仍须就绪。纯资产请求到此按原交付完成；用户明确要参考总表时须交综合视觉图板，按 asset-library §4 分别锁总表画幅、目标构图面板比例与独立首帧；整表可选 16:9/21:9 等适配比例，优先有效面积与缩放后细节可读，其他资产请求不要求故事板或按集总表。新主要资产保留原确认；只重排已批准资产不新增审批。
资产产出在原索引/复用说明中列本批用途、来源、版本、覆盖、依赖与下一动作，区分参考身份、复用文件和新制文件；通过丹青图册展示原图/Panel，必要时导出只读看板（file-management §2），不重做已批准参考。

**资产确认（弹窗 2，仅首项目/新增主要资产时）**：向用户展示新增的主要角色、核心场景或承重关键道具锚定与场景基调（**先展示资产文件再弹窗确认**，风格母版 M1 一并展示），确认后锁定；后续复用不再弹。

### 第 2 步：视听一体终编（景川职责，默认贯通）
按当前观看任务读取 storyboard-craft、shot-contract、prompt-assembly 的相关段落及实际命中的维度；不全文搬运。先按 asset-library §4 的“事实与通路 → 调度 → 复用/窄补 → 按需总表”判断顺序推进，穿越遮挡按 dim-blocking 核起终点，复杂方法缺口才查案例。参考总表缺项沿资产主责补齐，含人物构图实际绑定角色参考，每个 Clip 只使用相关区域并保护后续信息，按 `show_now` / `withhold_now` 记录披露边界。纯规划不冒充文件已生成。

逐 Clip 一次完成画面与声音设计，同一声音 ID 的逐字正文只出现一次：实际发声者、逐字正文、语气/重音/气口、声窗、听者反应、环境拟音与动作衔接统一编排。默认由用户为人物匹配音色，已有选择直接继承；未选时标“用户待匹配”，不伪造 voice_id、不筛选母音色、不分离音轨、不自动调用 TTS。只有本次实际接口必需的音频输入缺失时才暂停依赖调用，其余规划继续。用户明确委托声音专项后才读取第 3 步方法。

**按需交付**：要分镜交分镜总表，要视频提示词交逐 Clip 中文八段最终提示词，两者都要才都交。要实际资产交图片/文件，不用 JSON 或提示词代替；资产记录仅维护实际使用项。图片提示词只在请求或真实首帧/参考制作需要时生成，实际首帧仍须可用文件。六问、站位核对、表情分析和算式不单独成报告；关键事实、资产绑定、起止状态、版本及未解决项保存在对应产物，不能只留临时上下文。已有工程型声音表按需引用，不重复制造逐句表、三对齐表和并行骨架。

实际生成前核输入、模型参数和已获授权预算；在当前预算内继续，不每镜重复请示。用户明确要求逐次提交确认时，先展示本次完整可执行提示词、按序实际图/音/视频与参数及估价，确认只绑定该版本和调用范围；确认后不改词、增减参考、换模型或暗拆调用。发起前依 file-management §4 核输入白名单及提示词/清单/预览一致；确认后直接执行，不再重复询问。已提交正文保留快照，后续评估建议不能回写成实际提交内容。附加媒体与异步结果按对应provider能力卡区分上传、接受、完成和验收。产物依赖前做最小语义检查，日常局部修改只复核受影响内容；正式成片仍需完整声画验收。规划结果直接更新已有文件；没有分镜表请求且无需持久工程表时，不为填流程新建一份表。

**批头版本锁（v1.8.1，与 crew 交接块字段对齐）**：每批分镜总表批头记录 **项目标识 / 剧本修订号（script_rev，取自 crew 交接块）/ 分镜修订号（storyboard_rev，首版 = 1）/ 主画幅与用途**。本批发生实质修改时，仅该受影响批次的 `storyboard_rev +1`，未受影响批次保留原修订号；具体镜头同一叙事职责内保留 Shot ID，提升修订号，拆分、合并或改变职责才创建新 Shot ID 并停用旧 ID。**失效范围合同**：剧本/正典/世界观实质修改后，**只使依赖该修改的分镜、提示词、时长结论与 QC 结论失效**，未受影响部分保留沿用；**旧 QC 报告不得为新版本背书**。**画幅版本规则**：新增副画幅（如 16:9 补 9:16 版）不是裁切——副画幅按新画幅独立重构镜头功能与构图后重出该部分分镜与提示词，禁止把 16:9 成片直接裁成 9:16。

### 第 3 步：声音专项（仅明确委托时）
默认由用户自行针对人物匹配声音，Studio 保留普通声画一体设计。用户明确要求音色样本管理/提取、配音处理、复杂音乐或口型修复时，才读取角色卡闻笙段、asset-library §7、dim-audio/lip-sync 中相关内容。只交该任务实际需要的音频、绑定记录、时间轴或方案，不固定全套卡表，不因有对白启动专项。

用户提供的声音、选择和修改直接继承并保留可追溯映射；文字声线不是实际声音资产，角色逻辑标识不是平台音色 ID。接口不支持用户选声方式时说明受影响调用与可选方案，不能静默换声、剥离音轨、转 TTS 或扩大付费生成。

**ADR 口型避让（仅已启用声音专项时）**：先测每条实际音轨的有效发声时长并冻结声窗；不要以文件总时长、静帧或听者的嘴部代替验证。若该声窗内没有已验证的逐音素口型，景川应优先把画面切到同一状态内的听者反应、手部/伤态、关键道具、行进动作或画外空间，确保说话者嘴部不在画面中；这种功能性切镜不能改人物、道具、伤势、火烟或门位状态。只有没有可用承接镜时，才回唇形修复或按重拍协议补拍。自然张口的急呼可保留为直拍，但不得据此宣称逐音素对齐。

### 第 4 步：剪辑合成（调「陆离」，要出成片时）
**范围先行**：用户已认可素材且明确只裁切/拼接时，按陆离角色卡的纯拼接分支直接合成；保留原生音轨，不主动加字幕、配乐或付费工作，不外发语义复审。交付说明「未做语义复审」，不声称语义 QC 通过。其他标准完整制作继续下述流程。
**第一动作**：按需读陆离角色卡，直接消费已有时间线、声音说明与素材；`execution` 同时把 `scripts/assemble_timeline.py` 的调用方式贴入模板，由陆离按时间线顺序合成。
**素材标准化闸**：合成前逐条探测入选片段的分辨率、实际帧率、像素格式、时间基和首帧时间戳。即使画幅相同，只要实际帧率或时间戳不一致，也必须先分别转为目标帧率、分辨率、像素格式并重置起始时间戳，再拼接；不得直接拼接不同来源的容器文件后把“能打开”当作连续。输出后完整解码，再抽查每个接点及等间隔时间点；出现卡帧、重复静帧、非单调时间戳或解码警告时隔离该版，回标准化阶段重建。
**产出**：实际成片与必要的时间线/素材记录；检查结论可在原交付记录中简述，单独混音表/发布清单仅按需要 → **立即落盘 `05_成片/` 并 present_files 展示**（成片定稿前先展示时间线/自检报告供纠偏）。

### 第 5 步：QC（调「严恪」，按需）
仅在本次包含标准完整制作或明确要求审核时执行；第 4 步的纯拼接不因此重开语义审核或新增报告，技术导出检查仍必做。
**第一动作**：Read 严恪角色卡与 `failure-atlas.md`。严恪按各镜观看职责核对方法的预期证据是否真的落进画面/声音/参考职责；不把方法名、来源声量或旧风险清单当证明。真实产出未完成职责时退原责任角色替换方法、回落通用技法或局部细化；没有专项方法但职责已完成，不判失败。
**产出**：与审核范围相称的结论、证据定位及需修问题，不固定另交情绪曲线和重复核对表→ **立即落盘 `05_成片/delivery_check.md` 并 present_files 展示**。**QC 双层结论（v1.8.1 · execution 成片时）**：分**技术可用**（能播放、时长/分辨率/画幅正确、音画同步）与**语义合格**（身份/动作因果/故事事实/声音/口型/连续性正确）两层分别给结论——技术可用 ≠ 语义合格，两层都过才算通过；最终候选成片**正常速度完整观看**后再下结论，不跳看抽样。ADR 成片逐句核：有效发声时长是否落在声窗、声源是否落给正确角色、画内是否露出未经口型验证的说话者嘴部、画外锣/喊声是否被误拍为画内角色；静帧只可支持构图与状态，不能为口型背书。依赖镜头在生成过程中只做内联最小语义核对，严恪启用时，其批次结论覆盖此前接受状态，不把按批 QC 变成逐镜关卡。
**返修路由**：提示词问题回景川（按重拍协议定位责任层与修复范围）；资产问题回丹青；声音问题回闻笙；**同类返修仍不过且故障已稳定复现，或将触及用户批准预算/工具硬上限时，回沈砚上报用户**。

### 第 6 步：交付、资产归档与收尾审计
仅展示本次要求的实际产物与必要状态，不补齐未启用环节的文件，保留原格式（提示词不加代码围栏）。批量资产按原交付模板给同源工作清单、实际图册与独立提示词原文；多词集中查阅可用只读 HTML 快照，不另复制汇总成稿或把管理说明贴进 Prompt。简单单图/改词不强制清单或看板；收尾清理团队。
**文件管理（按 `references/file-management.md`）**：沿用项目布局，首次实际产出才建对应目录；同项目引用唯一正文，资产按 ID/版本/状态关联；候选和恢复数据留工作区，真实可再生缓存入临时区。批次/阶段收尾可审计，实际删除另核用途、依赖与授权，遵守宿主逐文件安全规则；不默认复制交接包，无候选不造清理报告。

## 维度装配机制

判断当前镜头让观众看什么 → 按缺口读主责方法段落 → 同一执行者完成声画一体八段 → 内联核事实、容量、引用和连续性 → 按交付风险自检或独立审查。只有具体缺口才升级专项，不把逐镜方法选择与检查推导写成附属文件。

**装配映射速查**（全表见 prompt-assembly.md 第 1 节）：对话正反打=站位+表演+音效；情绪特写=表演+光影；打斗=景别+运镜+动作+光影；**打斗含法术/能量/变身时再加特效卡**；建立=景别+运镜+光影+风格；悬疑揭示=光影+表演+站位+音效；转场空镜=风格+光影+运镜。特殊场面按实际机制追加：表演音乐=动作+表演+音效/配乐，竞赛载具/精细操作/异种/特殊介质=动作及其相称站位、声音、必要物理效果，潜入=站位+光影+音效+表演，多方程序=站位+表演+音效，分层叙事=风格+光影+音效+站位。**要背景 cue 或剧情内音乐设计时加装配 dim-music**；不把其全剧槽位/版权段全贴给不承担该职责的景川。

## 调整规则

| 想改什么 | 怎么做 |
|---|---|
| 改某镜提示词 | 镜头号+修改点发景川（有上下文），按重拍协议修复；单变量仅用于归因对照 |
| 改角色形象 | 先按 shot-contract §2 检查实际选片的前后相邻状态 → 丹青改对应资产/状态，景川仅更新受影响引用与生成段，保留无关已认可素材 |
| 加资产（新角色/新场景） | 发丹青追加建档，沿用既有 ID 体系 |
| 补按集参考总表/局部 Panel | 景川先确认本集覆盖范围、受影响 Clip 的调度与具体视觉缺口 → 沈砚退丹青复用已批准资产组装或窄补 → 景川只为各 Clip 绑定相关 Panel 并核披露边界；旧按 Clip 表继续有效，纯资产请求不触发 |
| 剧本场面只有泛化标签或缺事实 | 先回读正文、集纲与活动正典诊断实际观看任务；表现未指定由景川自主设计，承重事实缺失/冲突只退依赖部分给 Crew 原责任位或必要用户裁决。真正不依赖缺口的规划继续；依赖项只能列明前提的候选分支，未裁决不冻结、不作为当前事实提交生成 |
| 换目标视频模型 | **先判兼容（v1.10.0）**：对照目标模型能力卡核对 Shot/Clip 结构、单镜时长、参考资产数量与类型、首尾帧、画幅、音频能力——**全部兼容才只过 prompt-assembly 第 6 节平台适配微调**；任一不兼容时仅使受影响镜头/提示词失效重判（如 Shot 数上限变小→重拆 Clip；参考上限不足→改参考组合；画幅不可用→按目标画幅重排构图），复用既有版本锁 +1，不新增流程 |
| 续作/下一集 | 传 reuse_asset_ids 复用资产库；分镜从新集镜头接着编号 |
| 跨会话承接 | 第一动作 Read 资产索引+分镜总表末尾 → 回显「资产 X 个｜分镜至 SX｜下一镜 SX+1」→ 再续跑 |

## 避坑清单

- 引导展示不新增审批：已有授权继承，只问当前必要缺项；新增主要资产按原确认，付费与发布按实际权限。普通任务默认贯通，不建团队。
- 多生成器并行可能增加身份与风格漂移风险；所有维度仍由景川唯一终编。
- **禁止并行多 skill 同时生成同一镜头**；维度卡是规范不是生成器。
- 镜头卡未冻结不投喂；可拍证据按本镜职责写入，静态建立、停留或余波镜可用空间基线、持续状态、细微反应或声音证据，不硬造转折、压制或破坏。
- 资产缺口自动路由：先满足人物身份、承重场景拓扑、关键道具状态和必要端点；规划可先锁事实/拓扑与调度，实际生成才要求视觉输入就绪。纯资产任务到资产交付即止；视频任务由景川确认本集关键构图与具体视觉缺口后再让丹青补按集参考，Panel 可承担场景/道具职责，已批准资产组装不新增弹窗，真正新增主要资产仍走既有确认。

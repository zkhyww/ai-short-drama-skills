# 资产库规范（丹青·美术资产师使用，按需加载）

> 解决：AI 短剧制作中「角色跨镜变脸、场景跨镜跳结构、资产无法跨项目复用」三大顽疾。
> 原则：**资产先建档、分镜只引用**——景川写提示词时不临时编外貌，只引用资产 ID。

## 1. 资产三库（JSON 建档，唯一 ID）

制作实际需要时启用下列资产库与既有索引；缺少该类资产的任务不创建空库，局部请求不补全套。已有三库结构继续使用，不为简化批量合并或迁移：

| 库 | 文件 | 核心字段 |
|---|---|---|
| 人物资产库 | characters.json | char_id / 姓名 / 身份定位 / 外貌特征 / 常服与特殊服饰 / 性格标签 / 标志性表情 / 声线特征 / prompt_template / negative_prompt |
| 场景资产库 | scenes.json | scene_id / 场景名 / 空间类型 / 时间天气 / 光影基调 / 氛围色调 / 固定陈设 / 关联道具 / prompt_template |
| 道具资产库 | props.json | prop_id / 道具名 / 外观细节 / 功能属性 / 出场关键场次 / 视觉特征标签 |
| 资产索引 | asset-index.json | 全资产 ID→名称→类型→文件路径，供 reuse_asset_ids 跨项目复用 |

人物 prompt_template 模式：`{已确认身份与外貌锚点}，{当前已确认服装与状态}，{本镜表情}，{本镜动作}`——身份锚点逐字继承；表情、动作和真实状态按本镜替换，不由模板补成年龄、性别或新身份。

**文件版本与使用状态**：在既有索引条目/复用说明中标候选、当前采用或被替代/归档，并明确实际文件版本及其引用范围；该状态不替代下方文件就绪三态。新图 file_ready 不代表已采用，同 ID 有新版本不意味着全部旧镜头自动换用。被旧集、Panel、音色、剪辑或其他项目引用的旧文件继续保留；外部引用不明不删。按 file-management §4–§5 核依赖与清理，不另建平行索引或仅凭文件名判废。

**复用机制**：续作/补拍/新集时传入 `reuse_asset_ids`（人物 ID 列表+场景 ID 列表），直接加载已有资产，不重画不重建。

**参考清晰度先诊断**：先区分低分辨率与运动模糊、残影；放大不能找回源片未记录的细节。按本批确需角度选择代表性视图试验，确认身份/结构与可读性后才批量放大；运动拖影或结构缺失只对真实缺口重绘。重绘保留已知布局、广告位置、大字、柜台与固定陈设；生成式重建不等于事实恢复，未知小字/隐藏结构不得冒充原始证据。

**参考资产就绪三态（写入既有资产索引/复用说明，不另建文件）**：`prompt_only` / `file_ready` / `external_mount_plan`。`prompt_only` 表示只有已锁定描述、尚无可传入文件；新图仅完成规划、提示词、预检或方案确认时仍是 `prompt_only`。转为 `file_ready` 前分开核验：①真实文件可解码、实际格式/尺寸/画幅和透明度符合请求；②实图的身份、版式完整性、空间/道具及当前控制职责可用。只读 `dreamina_route.py check-image` 可辅助第一项，不判断第二项；技术通过或接口 success 都不等于内容通过。JPEG 请求实际返回 PNG 时不能只改扩展名；不透明请求出现透明破洞时不能靠铺底冒充恢复缺失内容。技术或内容不合格的文件保留调用证据，不进入有效参考链；同类故障重复时先定位输入/参数/版式或内容原因，在原预算与授权内局部修复，不盲目连续抽卡。`external_mount_plan` 表示文件在外部系统或待挂载位置，必须写清取得方式与预期用途；完成挂载及同样核验前不能冒充当前可用。planning 允许三态并存；execution 只有 `file_ready` 或已完成挂载核验的外部资产才可实际提交。**引用语义另按本条区分且不新增资产类型或状态机**：`PLAN` 只表示计划中的来源/路径/职责，映射 `prompt_only` 或 `external_mount_plan`，不得作为 provider 输入；`REF` 表示本次实际提交用来控制身份、空间、道具、动作或风格的参考输入，不自动承担本镜起始状态；`IMG` 表示本镜实际可见的图像/关键帧/选用帧，只有画幅、内容状态和职责均匹配时才可承担首帧、尾帧或关键帧职责。每次引用在既有资产索引、分镜或调用记录中写明语义、来源文件/Panel、版本及控制职责；同一文件可在不同调用中承担不同语义，但不能在同一绑定中靠文件名互相冒充。

**身份/状态决策四词（仍落在现有资产条目或复用说明）**：`reuse` / `new_variant` / `new_asset` / `unresolved`。身份未变、状态也在既有锁内用 `reuse`；同一身份发生服装、伤态、年龄阶段或剧情状态变化用 `new_variant`；叙事身份确为新人物/新场景/新道具才用 `new_asset`；证据不足写 `unresolved` 并停在规划，不凭正文猜成新身份。新生成一张插画、裁切图或局部细节图本身不构成新叙事身份或剧情状态：沿用原 CHAR/SCENE/PROP ID 与相应身份判词，另在既有索引字段记录该新文件自己的就绪状态。文件名是新的但无法确认对应哪项既有身份时写 `unresolved`，不得凭新文件名猜映射；只有真实身份或剧情状态差异才分别触发 `new_asset` 或 `new_variant`。此判词决定是否沿用 ID，不增加一套资产系统。 本批作业清单直接投影这些条目/复用说明：列用途、来源文件/Panel、版本、覆盖、已有依赖及下一动作，分别汇总参考身份数、实际复用文件数和计划新制文件数；同一文件的多个 Panel 只算一张。文件作业写沿用/新制/返修或未明确，不从身份判词推断；既有武器 `reuse` 但补握持图仍是新文件工作。已有结构化记录可用可选 `file_action=reuse/generate/rework` 供只读工具统计，缺字段保持未知，不要求旧索引补新 Schema。候选/采用沿来源保留；只读展示不重新选片，实际路径与内容核验另标。

**背景群演参考（减负与按需图化）**：只承担人数、声势或环境活动的未命名群演不逐人建 CHAR；同类群体跨集复用不等于每个成员必须保持身份。被剧情点名、承担事件行动/互动/回应或确需辨认同一个人的角色，仍按 §2 独立建参考；从群体中升级时继承其原外观与成员定位，不重造脸，也不把全群升级。

- **先判视觉缺口**：远景虚焦、一次性路人，或已有场景/群体 Panel 足够时，沿用场景描述和现有图，不另出板。已有素材不足以控制群体统一装束、可辨差异或复用外观时，丹青主动规划多人群演参考板；沿用原资产确认与执行预算，不等用户点名技法，不因出现人群就加图。
- **出图方法**：先继承时代、职业、服装范围、群体构成与项目媒介，再按当前可见性选择脸型、发型、体态、穿着松紧或磨损等差异，新增项标 [制作设计/推断]。版面以人物清楚可分辨、彼此不重叠、必要服装可读为准，采用简单背景与自然中性姿态；人数和拆板数随所需外观覆盖、清晰度与工具容量决定，不固定五人/十人，也不默认铺九幅多人场景。复用说明分清板中示例人数和镜头实际人数：逐人选用时示例容量须足够；只作外观范式时，超出示例的背景人按已锁共性补足差异，不从少量固定成员声称选出更多不同人物。案例中的年龄、纹身、异种或阵营设定不自动带入当前项目。
- **引用与迭代**：群体描述挂既有场景资产及索引，写群体称谓、实际文件/Panel/成员位置、版本与覆盖集段；单独群演图尚无场景绑定时，只规划外观与文件用途，身份映射待绑定，不为补齐库捏造场景。项目图进入 `02_资产/`，作者原始提示词仍留案例库。群演板只管外观与群体构成，不控制场景光线、剧情队形、动作或首帧；景川另按当前镜头写区域、进出方向、行动与人数。跨集复用已批准外观，不要求每集换脸或重画；已知场景及其背景群体首次补图、补清晰度或重排版面时，交付按两轴写：`身份/状态：既有 SCENE_ID｜reuse｜无真实状态差异`；`文件就绪：计划文件 + Panel｜prompt_only｜未生成`。首次新增参考条目不等于 `new_asset`，新文件也不等于 `new_variant`。真实服装/状态变化才按同 ID 变体；局部修订只改指定成员或服装区域，核对其余外观未漂移，只更新采用新版本的引用。

## 2. 角色参考资产的默认、复用与补充

**新建角色参考的默认交付**：无论是纯角色资产请求，还是视频任务中的角色参考，新建时默认一人一张角色综合设定板，包含大幅清晰正脸头肩肖像特写 + 可读且完整的正面/侧面/背面全身三视图 + 当前连续性真正需要的局部细节。“一张角色图”只限定张数，交付仍是这一张综合板；只要提示词时描述同一版式，不生成图片。明确指定其他图种时按下一段处理。视频任务按**本集实际出镜的故事角色清单**逐人配参考，主角与配角都计入，不因出场短漏掉，也不把多个身份合并在同一角色板；纯画外声无既定可见形象时不编造外观，未命名背景群演继续按 §1 减负。综合板不自动再加独立定妆照、独立肖像、独立三视图或旧式大幅全身主立绘。

先区分**本集需要引用的角色参考数**与**本轮需要新生成的文件数**：本集有 N 个实际出镜故事角色，就需要 N 份彼此独立的角色参考；同一角色的身份、外观与状态匹配时，已批准角色板跨集、跨 Clip 复用，因此不等于每集新生成 N 张。新角色或确有变化的外观只生成所需的新板、同 ID 状态变体或清晰度缺项。用户明确指定正面半身肖像、独立三视图、全身立绘等图种时只交该图种，不扩成综合板；仅说“一张”不触发此分支。已有合格综合板或定妆照、肖像、三视图等分图足以承担当前职责时直接复用，不为套新版式重画；局部修改继承已批准的版本、模型、画风、版式和参考次序，只改指定区域并复核其余内容，不能自行换用未批准新版本。只有现有材料对当前景别、角度或连续性要点有真实缺口、下游又需要时，才窄补一项。表情十二宫格仅在情绪变化密集且基础参考不足时补，动作十五宫格仅在动作模式需要锁定时补，二者都不是默认前置。

**版式与补充规范**（吸收 XiaoLuo/LIRA/aipdd-char-view）：
- **角色综合设定板**：大幅清晰正脸头肩肖像为视觉重点；新建默认板的正面/侧面/背面均为头到脚完整全身，比例统一、轮廓和服饰细节可读；局部细节只放当前需要锁定的面部、发饰、材质、鞋或配饰。下游裁图是另有用途的派生输入，不删减默认板的完整三视图
- **独立三视图（按需）**：正面全身 / 侧面全身 / 背面全身，同一姿势同一光源，中性灰底，标注身高比例参照
- **独立肖像特写（按需）**：清晰正脸头肩特写，中性微表情；侧脸或 3/4 仅按辨识缺口补充，不能代替唯一正脸锚点
- **表情十二宫格（条件补充）**：3×4 网格，每格一种情绪表情，同角度同光
- **动作十五宫格（条件补充）**：3×5 网格，每格一个标志性动作
- **垫图版式（按需）**：明确需要此版式时可用单张 1:1 画布 4×4 网格 = 五官特写（2×2）+ 多角度脸型（2×2）+ 正/侧/背三视图（4×2 排布），不是默认角色板。图生图精修仅在实际适配器支持 denoise 时将 0.32–0.40 作为候选试验范围，以实图核验身份和修改幅度；不当作跨工具通用参数或一致性保证

**正脸负责身份、身体视图负责造型**：新建默认角色板把清晰正脸放在大幅头肩肖像区，不依赖缩小全身图里的小脸识别五官。相机近眼平、脸朝正面，双眼、鼻口、下颌轮廓与当前设定允许露出的辨识点可读；不美化改脸，不为露五官摘掉正典锁定的面罩、饰物或遮挡。侧脸/3/4 脸只在当前角度辨识有缺口时补，不固定增加三个头部。各区须属于同一身份与状态，核五官、发型、肤色、服装领口及饰物一致。

版式按实际输入尺寸分配：脸部优先获得足够有效像素，身体视图仍须读清比例、衣装、手脚与必要附件，不固定左右位置、画幅或占比。生图画幅继承已批准的资产设置；尚未确定时按当前版式和工具支持给出明确的生图建议，不自动套用视频 9:16 或脚本默认值，也不把建议写成已批准。仅在用户明确选择“肖像＋服装身体区”，或为下游导出服装专用输入时，才可采用颈下身体裁图，并标明用途、原板及对应身份；这类图不是完整三视图，也不是剧情首帧。

投喂前按平台实际缩放后的图检查正脸和承重衣装是否仍可辨；多面板受压缩变糊时，优先减少无关细节、重排，仍不足才从同一已批准原图导出清晰脸部/身体分图或按授权补缺，不重新捏脸。接口支持并实际使用分区裁图时注明对应职责；仅写 Panel 名称不代表模型已裁取。文字注明“同一角色的不同视图，身份参考，不是多人同框或视频首帧”，仍需核验生成结果，不能宣称正脸放大保证不变脸。已批准参考足够清晰时继续复用，不强制重画。姿态僵硬或遮挡有疑点时按 dim-blocking 的姿态检查处理，中性正面设定不强制侧身美姿。

角色综合设定板只锁角色身份、外观与需要的连续性细节。板内中性姿势、视线、构图和分区不代表剧情开场，不得覆盖剧本规定的起始姿态、动作方向、机位或实际首帧。

**视频节点投喂（本机 H3 30 号）**：整板、分图及槽位选择以 `h3-comfy-mode-routing.md` §2 为唯一主责规则，按本镜职责、用户指定和实际缩放后的可读性决定，不固定裁脸或固定三张配方。已批准且实测适配的组合继续复用；参考图不冒充 20/21 所需的开场状态图。

## 2.5 服化道的条件化生产描述

丹青先继承已确认的身份、时代、职业、剧情状态与项目风格，再只描述当前资产能够看见、且会影响辨认或连续性的服化道信息。不要用「华丽」「高级」「电影感」代替可见结构，也不设部位数量、字数或繁复程度配额。

**正向描述顺序**：先写整体廓形与穿着层次，再写可见的领口、袖口、开合、下摆或鞋靴结构；随后写项目媒介能表达的材质反应、缝制或边缘处理、合身与磨损状态、主辅色关系；最后只补已确认或当前设计确需的发饰、配饰、武器及持用状态。剧本/crew 已明确的内容标事实，生产补足标 `[制作设计/推断]`；性别、年龄、身份或题材未确认时不得据模板补成事实。

**条件示例（命中才用）**：动作服装可在真实运动和防穿帮需要下写短下摆、收束袖口、护具连接与受力后的褶皱；礼服或身份服装可在设定已成立时写多层结构、刺绣、珠饰或金属件；旧日常服可写起球、褪色、接缝变形与局部修补。它们是设计选项，不是由性别、年龄、正反派或古今题材自动触发的默认套装。

**项目风格为唯一权威**：真人摄影、3D 次世代写实、2D、像素、水墨或水彩分别使用与本项目相符的布料反光、PBR 表面、线条色块、像素边缘、纸纹笔触等证据；未锁定 3D 时不自动追加 CG、PBR、8K 或体积光，非写实时不强塞毛孔和次表面散射。角色参考图画幅服从项目与实际用途，不自动改成 9:16。

**面部细项扩展**（§3 持久区分项之外的表情层）：眼神按角色卡与资产用途写；只有独立肖像展示明确需要时才可直视镜头，剧情镜不得由资产模板改写既定视线对象。嘴角、面部不对称与妆容只选本角色已有设定或当前设计确需的项，新增设计仍按 §3 标注来源。

**姿态与动作行**：身体重心、手部状态与整体动势按资产用途和已确认身份选择；中性设定姿势不替代剧情镜中的真实调度。

**配饰与武器行**：只列实际存在的部位、材质、新旧与持握/佩戴状态；承重武器另入道具资产库（§5）管理状态，不为服装细节齐套而发明。

**负面提示词基线**（按资产用途和项目媒介取用，不逐字机械全贴）：低清晰度、比例错误、手指畸形、脸部崩坏、五官错位、复杂背景、杂乱 UI 与文字错误等当前高风险项。写实摄影/写实 3D 可按需排除塑料皮肤、蜡像感或过度磨皮；2D/水墨/水彩/像素只排除会破坏其线条、纸纹、笔触或像素边缘的越界媒介词。东亚题材需要反模板脸时按 §2.6 取用，不把题材示例覆盖角色既有事实。

## 2.6 真实感锚定（人种/皮肤/反模板脸 · v1.13.3 增）

> 解决两个高频失败模式：模型把非西方面孔拉向欧美网红脸，以及写实人物皮肤被磨成塑料。与 §10 抗趋同同族——§10 管「已有特征被修正」，本节管「基础长相被模板化」。东亚题材的人种、五官与反模板脸锚定始终执行；皮肤表面细节必须服从项目风格，不跨媒介套用写实毛孔。

**人种与五官锚定**（角色设定模块内写死，逐字进提示词）：

| 锚定点 | 写法 | 禁止 |
|---|---|---|
| 人种基调 | 继承该角色已确认的人种、年龄、性别与身份；本项目确为东亚角色时才写对应基调 | 不把老人年轻化、不擅改性别/人种；已批准身份参考继续绑定，不将其当待规避的新角色模板 |
| 发色 | 黑色或深棕色头发 | 金发、浅棕、挑染（非剧情要求时） |
| 瞳色 | 深棕色眼睛 | 蓝眼、灰眼、琥珀眼（非剧情要求时） |
| 脸部结构 | 脸部结构自然柔和，五官精致但不过度精致化 | 尖下巴、大眼高鼻梁模板脸、过强混血感、明显欧美脸 |
| 气质基准 | 像真实电影演员或高质感品牌人像，清新自然耐看 | 模板化 AI 美女脸、网红化五官 |

**皮肤/表面细节按风格分流**：写实摄影/写实 3D 才写轻微毛孔、自然肤色过渡、鼻翼阴影与真实面部细节，并禁止塑料感、过度磨皮和均匀无瑕的瓷娃娃肤质。2D/水墨/水彩/像素使用媒介相符的表面证据（线条粗细、色块层次、纸纹与笔触、有限色板与像素边缘），**不强制毛孔**、次表面散射或摄影级鼻翼阴影；只要求脸部结构清楚、身份稳定、不过度模板化。

**参考图吸收度控制**（混合参考时的「度」）：允许从参考图**少量吸收单项优点**（如骨相清晰度、皮肤通透感），但整体身份锚定不变——**吸收的每一项都要在提示词里点名（「保留图1的骨相清晰度」式写法），且总吸收项 ≤2**；吸收后整体仍必须明显偏东亚基调，混血感超标即废图重生成。无参考图时本条不适用。

**与身份区分门的关系**：§3 管角色**之间**不撞脸（按本剧需要选择持久差异）；本节管角色**与模型默认审美**不撞脸（人种/气质锚定）。新角色建档时两道门都过。

## 3. 身份区分门（防「一张脸演两个角色」）

crew 配套人物档中的「人物视觉锚定行」（历史母稿内的既定事实仍继承；单一正文交付时随配套人物资料提供）承载创作侧已确立的**基础视觉事实**。丹青必须**逐字继承 crew 基础视觉事实**，不得删改、同义替换或用制作偏好覆盖；这些事实不是完整出图参数。丹青在其上补足生产级区分项，新增内容统一标为 **[制作设计/推断]**；若与 crew 基础视觉事实冲突，必须保留 crew 事实并调整制作设计。crew 锚定行缺失时，先提取剧本明示事实并标来源，其余仍按 [制作设计/推断] 补足，不把推断伪装成原文事实。

**身份区分按风险取项**：对每个需要跨格、跨镜或跨批保持身份的角色，先比较本剧实际演员组合与已有参考资产，再选择足以辨认且会持续存在的特征。可从脸部结构、发型、体态、服装轮廓、随身物和其他已确认特征中择要；本镜优先保留当前画幅可见、与同场角色最易混淆、或实测最易漂移的项。没有实际碰撞风险的项不为凑数补写；确有相近角色时才写针对该对象的负向区分。主角、配角或群演称谓不决定锚点数量，已确认的主要/承重角色身份不能因名分或出场频率被降档。

**角色圣经字段**（锚定描述写法，吸收 shipin-fenjing）：每个 CHAR_ID 的 anchor 只组合**已确认的身份事实 + 本角色相关的持久区分项 + 当前风险需要的禁止漂移项**；性别、年龄、种族类型或身体特征未确认时不得补成事实。多格/多镜引用时**逐字复制，禁同义替换**；改写已确认锚点可能增加身份漂移风险。

**身份与状态连续性锁**：锁什么由本角色的辨识风险、当前画幅可见性、跨镜复用范围与状态变化决定。伤势、污损、换装、持物等状态若已由剧本/正典确认，作为同一身份的可追溯变体管理，不另造身份；未确认状态不补写。新建角色参考、明确图种和已有合格分图的选择统一按 §2，不因低频自动降为单张立绘。跨镜/跨批使用仍复用同一 CHAR_ID 的已有综合板或分图，确有缺口才窄补所需综合板、状态变体或清晰度缺项。纯背景群演按 §1 选择场景描述、已有 Panel 或按需多人参考板；需要独立事件身份的角色仍单独建参考。锁项写进原资产卡，提示词继续用 **@资产名 短锚点**引用（如 @lin_wan_v1），全项目不重置编号。

**基础参考与当前状态分责**：干净角色图主要锁身份、体态与服装基础，灾前/未损场景板主要锁结构、地标与陈设；本段已核接续状态决定此刻伤血污迹、损坏、烟火及持物。给每个输入写清职责和冲突保留项，不能让干净/完好参考覆盖已发生的变化；未来状态区域不进入当前事实。若文字与现有参考已经足以表达就直接复用；只有已观察到状态被重置、重要状态看不清，或参考冲突无法消解时，才考虑沿同一身份窄补一张或最少数量的当前状态变体，并实际绑定所需人物/空间基准。先核变体的空间、姿态、伤损位置和可读性，再供视频使用；不是每段必生图，也不把状态图自动当首帧。

**一致性工具按风险组合**：可用角色参考资产与角色圣经共同锁身份；服装、伤态、持物等变化按同一 CHAR_ID 的可追溯状态管理；需要链式生成时只把已验收图传给后镜。发色、瞳色或其他特征只有在已确认且本镜应可见、又确实易漂时才单独重复；坏图不进入参考链，但不把“每次都重生成”当唯一修复方式。

**参数控制不是保证**：同一项目保持目标模型/版本与提示词结构有助于减少变量，平台支持且已记录时可复用 seed；这些手段都不能保证一致，也不能据其缺失断言必然漂移。最终以实际可见身份、状态与当前 provider 结果核验。

**依据标注**：crew 或剧本明示内容标 [事实:crew] / [事实:剧本]；为满足出图与角色区分而新增的结构、服饰细节和禁项标 [制作设计/推断]；确实无法确定且会改变故事事实的内容标 [未知]。不得覆盖 crew 基础视觉事实，也不得把 [未知] 或制作设计写成原文事实。

**数值-视觉双轨**：档案可保留身高/年龄等事实；画面指令优先用「比对手高半头」等可见关系，不堆 cm 级伪精度。台词数字、时间码、已确认空间尺寸和实际接口参数须保留，遵循 prompt-assembly §6.5，不把“纯视觉”误用为删除一切数值。

**参考图有无 → 描述深度**：有实际可用参考图时，用真实资产绑定加必要身份锚点/状态差异，不重复图片已表达的静态细节，不设 20 字硬限；无图时从已确认文字资产补足外形、服装、面部记忆点或场景时代、光线、布局等本镜必要信息，不假造图号/媒体句柄/空占位。文字资产 ID 不代表已上传参考图；文字未明确且涉及故事事实的内容回查，不从正文猜建新身份。

## 4. 场景与按集参考资产

**空场景与拍摄现场分开**：空场景图只锁建筑与陈设，不要求正片清空背景活动。剧情需要的顾客、店员或其他群演照常存在，并按调度保持遮挡、镜面反射与光影可信；新增视角沿同一拓扑，不以空板覆盖现场状态。

**视频参考规划的默认组合与总表交付**：已有独立角色参考用于身份绑定；用户请求整集/整条视频参考总表时，交付一张综合视觉图板，汇集本制作单元必要的关键道具、按地点去重的空场景/必要状态和精选关键构图。文档索引、资产清单、零散图片或完整逐镜故事板不能冒充这张图板；既有素材可作为内部输入复用，不机械另出一批散图。本文“按集”指当前制作单元，也适用于非剧集视频。仅要求重写提示词时先交文本并保持 `prompt_only`；要求实际生成时必须交真实图板，不以提示词完成宣称图片完成。

**人物绑定与分工**：总表默认不重复铺已有角色三视图；用户明确要角色展示区时保留。含人物的关键构图必须实际绑定对应角色参考，逐个注明输入负责身份、衣装、风格或空间，不能只靠文字复述来保持身份。无人场景或道具板只传其真实所需的空间/物件参考，不为占位额外挂角色图；人物关键构图需要身份参考时仍实际绑定。用户要求空场景总表时省去含人物构图，不以默认组合覆盖该选择；已否决素材不得进入有效参考链。构图呈现已锁故事事实下批准的站位、机位、动作起势和空间关系，不能把人物设定板的中性姿势当剧情。

**自适应版式与选材**：根据实际内容决定数量、角度、大小、位置和面积，可以用网格、主画面加辅图区或局部细节；不固定三横带、五道具上限、三构图、等大面板或每件三视角。按叙事重要性、复用需求、结构辨识与动作依赖选道具和视角，简单物件可单视图，复杂交互/装配才多视图或局部。尽量让有效参考内容撑满可用画布：缩小无功能外边距、宽缝、大标题和重复标签，按主次放大有效 Panel，用必要道具、组件或材质细节组织剩余空间；不加无关素材凑满，不裁掉承重结构，不拉伸图像，不取消必要的分区边界与可读标签。可借鉴“整体空间关系＋关键组件＋局部细节”的分工，但不是每表固定三栏，也不重复放同一信息。减少排版浪费与保留镜头内部有叙事作用的负空间分别判断，不能为了撑满把人物的视线空间或孤独感构图裁掉。

**总表、构图面板、首帧三种画幅分别锁定**：先读取项目已定成片画幅；9:16 项目的镜头构图 Panel 采用实际 9:16 内框，16:9 项目采用 16:9，其他比例照项目继承，按该画框安排人物、动作、视线和承重道具。不能只在宽图上标“9:16”，或把宽构图机械居中裁切来冒充竖屏调度；宽图若仅说明场面关系，明确标“空间关系参考”，不作目标构图验收。空场景和道具 Panel 可按结构需要横向、竖向或不等比例展示，其画幅不改变成片设置。

整表画布按内容、图像工具支持尺寸及下游缩放限制选择，可用横版 16:9；容纳多个竖屏构图或长形结构不足时可直接选 21:9，也可选更合适的其他画幅，不强制与视频一致。21:9 必须由当前工具实际支持的尺寸生成或由已有素材按权限合成，不通过拉伸制造；相同总像素或最大边限制下变宽可能降低 Panel 高度，不能把改比例等同提升清晰度。按实际输入尺寸核脸、手、交互面与关键文字；不足时优先去重、重排并在工具支持范围提高输出尺寸，仍不足才按真实缺口拆板或导出区域，不机械缩小所有图块。

镜头投喂只使用当前相关区域，并核实际上传的文件/区域；只写 Panel ID 不等于接口会裁图。需要首帧时，单独提供符合目标画幅与该镜起始状态的有效图像文件，去掉总表边框和标签；现有构图 Panel 足够清晰、比例准确且状态相符时可按已获授权导出复用，否则按缺口制作。整张横版总表不能直接充当竖屏首帧；图像处理仍使用当前环境允许的图像工具。多角度卡只支持已画出并核验的空间关系，不能凭“720°”“永久锁景”字样宣称任意角度、隐藏结构或视频连续性已被保证；复杂动态空间缺口沿既有 blender-previs 条件路由。

**场景、状态与风格**：同地按地点去重，不随每个机位重造场景；确有影响连续性的状态差异时分区标明同一ID及对应时点。空场景只含环境和必要陈设，不混入人物、动物或剧情表演；题材定义所需的固定环境元素按实际内容判断。仅展示本制作单元需用且披露允许的状态，不提前引入后续变化。继承用户已批准的视觉母版、媒介和衣装，外来模板中的画风占位、画幅、颜色及布局不能覆盖既定目标；不固定某种3D/摄影/动画风格、16:9、浅底或语言。无指定时可给清晰的专业默认版式，并按用途调整。

**区域可以直接承担资产职责**：同一文件中的场景或道具 Panel 只要清晰可读，就能分别满足对应视觉参考职责；资产身份、就绪状态和引用可指向 `文件路径 + Panel`，不要求为每项再建独立文件。本集有 N 个实际出镜故事角色时，使用 N 份彼此独立的角色参考；简单场景通常再共享一张按集参考总表。这里描述的是所需参考的组合，不是固定新文件数：实际新生成多少取决于已有角色板、场景/道具 Panel 是否可复用以及具体视觉缺口，也不限制一集只能使用一张总表。

先选本集真正有用的关键构图，再为每个 Clip 只绑定其实际需要的 Panel；禁止按 Clip 重复生成同内容总表、无条件另加场景图/道具图，或再造一套额外故事板。总表不得把后续才出现的道具状态、构图或信息当成较早 Clip 的当前事实：按 `show_now / withhold_now` 使用兼容区域提取、分离输入，确因披露清晰度或 provider 限制不足时才窄补。跨集复用仍以相同 SCENE/PROP 身份及真实状态为准。

**未明确要求总表的自动规划**可以按默认打包偏好复用，不强制重画：现有多图、旧按 Clip 总表、独立场景/道具板或故事板已经清楚承担职责，且 provider 允许分别输入时直接复用，不批量改名或重排；只有本集素材的数量、可见性或参考上限需要集中时才组装新总表。规划阶段只描述待组装内容并标 `prompt_only`；只有文件生成/挂载并核对 Panel/资产 ID、路径、可见性、优先级与控制职责后才是可提交参考。总表及其中构图都不是实际首帧。静态图只证明可见身份、外观、构图及接触关系，不证明可编辑3D绑定、动捕、布料解算或连续动作；动态能力须由对应产物验证。

**空间设计到参考交付的判断顺序**（沿现有资产记录执行，不另设固定产物或审批链）：

1. 从当前正文提取本场必要行动、因果、可见/可知范围和起止状态；缺失的是故事原因、结果或人物选择时按 SKILL 的故事输入三态回源，不能先画图把候选故事变成事实。
2. 先以已定地标检查出入口连通、固定陈设、可通行空隙、接触/承重面和光源世界方向，再排人物起点、路线、落点及机位；多机位从同一空间推导。文字/简图足以核清时直接规划，不以独立场景图存在为前提，不必把整栋建筑或隐藏房间全部生成。
3. 对照已有资产决定：空间和所需状态可读则复用；只有新状态/局部结构缺口则沿同一身份窄补；多个角度互相矛盾或必要路线不可判断时，先修正共同布局依据再出受影响视角。可用场景卡、获批母板或总表内空场景区承担同一职责，不要求三者齐套；没有已有图时，总表场景区可以直接成为首次视觉实现。
4. 只有用户要求总表或现有输入确需集中时，按已定范围组装缺失的总表；含人物关键构图先通过调度核对并实际绑定角色图，无人板不挂角色图。既有总表合格时不再自动追加散图、母板或首帧。总表交付后先核空间交叉一致、道具身份/状态、目标面板画幅与实际缩放可读性，再绑定本次输入职责；标签帮助定位，不能代替空间结构。

进入实际生成前，所用视觉输入仍须达到 `file_ready` 或完成外部挂载核验。新主要资产继续走既有资产确认，包括首次在总表中呈现的新场景；重用或重排已批准资产不重复确认。

**同址先固定可用空间依据**：需要多个机位或状态而已有漂移时，先核同一场景的整体布局、出入口、固定陈设、关键接触面和光源方向，复用获批母板或总表内合格空场景区；不为“锁景”机械另画母板。后续变体沿该依据只改所需状态。图上的说明标签用于帮助定位参考职责，不是让正片复现文字，也不证明未画出的结构或物理解算；“永久锁景”等口号不作为验收。

**单独补图只解决具体缺口**：独立资产请求继续按请求交付，不扩成视频流程。用户另行要求单独场景图、动作承重空间仍未知/不可读、必须锁定精确端点，或真实模型/输入限制无法使用现有 Panel 时，可以单独补场景、道具或状态图；先写清具体缺口，不因“复杂打斗”标签自动加图。侧/反视图、结构细节或 90° 俯视布局也只在隐藏空间、越轴、多人移动、复杂交互、空间谜题或结构可读性确有缺口时补。反打补图先标明哪张/哪个 Panel 是原正面、观察点与反向视域，沿用同一 SCENE_ID；按已锁拓扑改变观看方向，保留同建筑的结构、门窗/出口、街道连接、材质、时段与光源世界方向，不把镜像翻转当反打，也不锁死光在画面的同一侧。已有合格反打 Panel 直接复用。看不到且影响因果的地理保持 `结构待确认`，只退回依赖该事实的内容，不发明新功能区。 当前缺口、拟用图种、可复用来源和先后依赖落在同一作业说明；已被总表承担的空间职责不再派一张同职责母板，图册直接展示原文件及区域。

## 5. 道具资产

关键道具（剧情道具/信物/武器）先复用已有 PROP_ID、外观、材质、磨损与已确认状态；视频参考规划默认在 `按集参考总表` 的清晰 Panel 中呈现本集相应时点的可见状态。只有现有区域看不清关键结构、交互面或状态差异，或披露边界要求分离时，才窄补细节/状态图；新图沿用原 PROP_ID，新文件本身不构成新道具或新剧情状态。真实发生干净/破损/染血等状态变化时按同一身份建立可追溯变体。器械类用中性材质功能描述（如「复古工业电子道具，数字读数」），避安全审核词。 作业说明据缺口写全貌、交互面或状态细节的具体用途；握持细节新制不变更身份，图册按文件去重并保留各 PROP_ID/Panel 职责，不用故事题材猜张数。

**占手与生命周期**：进入分镜前，为本 Clip 实际承重的手持/交互道具写清起始持有者与左/右手（或双手）→可见交接/放置/拾取→每次切镜后的持有者或精确位置→结尾状态。画外不等于消失；背景陈设只保持已锁位置与状态，不为齐模板逐件编造退场。不能为了降低生成难度删除已锁道具，需降级时按 storyboard-craft §14 保留关键接触与结果。

## 6. 九宫格公式（批量出图/质检/选图）

3×3 contact sheet 是需要比较多个景别/角度、批量选图或诊断一致性时的可选工具：可用**行=景别**（特写/中景/全景）、**列=视角**（正/3-4/侧）、中心格纯底 pose-only。没有多角度选择缺口时不自动生成；中性姿势、白/灰底或网格分区只服务筛选，本身不是视频首帧。

## 7. 声音指纹与母音色卡（明确委托声音管理时使用）

默认用户自行匹配人物声音，既有选择直接继承；未选标“用户待匹配”，不要求 YAML、候选生成、试听、冻结或单独剥离音轨。以下方法仅用户明确委托声音筛选/提取/管理时启用，已提供音色不重新筛选；音频 ID 必须来自真实资产或平台，不能由文字方向伪造。普通声画仍由景川职责一体设计；只有实际接口必需的声音输入缺失才阻塞相关调用。

声音拆成两层，禁止混写：

- **声音指纹**：角色怎样说话——句长、用词、语速节奏、重音习惯、停连、语调、拒绝方式与情绪底色；来自 crew 交接或制作侧按台词归纳。
- **母音色资产**：角色实际使用的声音锚——从模型自带音色或开源音色生成结果中筛出的可复用参考片段。`voice_id` 是角色的逻辑声音身份，`mother_voice_id` 才是冻结后的实际母音色资产；两者不得互相代替。

本工作流只使用 `provider_builtin | open_source` 两类来源，不建立真人克隆音色流程，也不在声音卡中设置许可证、授权或 consent 字段。

### 7.1 稀疏 YAML

未知的可选字段直接省略，不得为了填满模板堆叠缺失状态占位。母音色冻结前只写已经发生的事实：

```yaml
voice_id: char_linnuo_voice
voice_fingerprint:
  diction: 短句，少解释，压力越大越礼貌
  speech_rhythm: 先停半拍再回答，句尾常收住
  stress_habit: 重读否定词和对方姓名
  refusal_style: 不正面说不，用条件句封口
mother_voice:
  state: pending_candidates
```

冻结后补真实资产定位：

```yaml
voice_id: char_linnuo_voice
mother_voice:
  state: frozen
  mother_voice_id: mv_linnuo_001
  source_type: provider_builtin
  source_name: 模型内置音色名称或开源音色名称
  provider: 实际供应商
  model: 实际模型
  adapter: 实际接入层
  source_episode: E03
  source_shot: S03-014
  time_range: 00:02.400-00:10.100
  asset_path: 04_声音/mother_voices/mv_linnuo_001.wav
  sha256: 实际文件哈希
  generation_task_id: 实际任务 ID
  frozen_at: 2026-09-02T00:00:00+08:00
```

`source_type=open_source` 时记录实际音色名称、版本或仓库定位、资产路径与哈希；不适用的 provider/model/adapter 字段省略。`provider_builtin` 没有可复用音频输入能力时，仍保存母音色片段作听觉基准，并固定实际 preset/生成参数；若当前视频接口无法回传声音参考，则改走独立 TTS＋对口型链路，不声称已锁定模型内声音。

### 7.2 用户委托筛选时：按角色首次发声起选择候选

1. **起点按角色，不按第一集**：每个角色从其在全剧中首次发声的镜头开始建立候选；角色到后续集才登场，就从该集开始。
2. **候选片段标准**：优先试听约 6–15 秒的干净连续表达（不是硬时长；实际上下限服从工具），至少包含一个完整意群，能听清音高中心、音色、节奏、重音、停连、气息与句尾落点。多人叠话、BGM 盖声、只剩耳语/喊叫或情绪极端到无法代表常态的片段不冻结。
3. **允许向后寻找**：首次发声没有合格片段时标 `provisional`，继续在该角色后续镜头或后续集筛选；未冻结阶段生成的对白只算预览，不得写入正式连续性资产；只做筛选所需的少量候选，不沿整季先生成大批临时对白。
4. **冻结、复用与回填**：用户或制作侧试听确认后标 `frozen`，截取并保存母音色资产。当前 provider 支持音频参考时，后续正式对白镜必须带**已冻结母音色**样本生成；冻结后先核对此前临时 take：**来源候选镜本身**与其他实听匹配且画面合格的 take 可标为正式；不匹配项才按同一参考重生最小受影响 Clip，再进入正式剪辑与连续性账本。不得为了「冻结回填」把合格来源候选无条件重拍。当前 provider 不支持或参考音频实听仍不稳时，按声音维度卡降级到独立 TTS＋对口型，不以相同文字 Prompt 冒充音色连续。
5. **失效处理**：母音色文件损坏、接口不再支持、或实听持续漂移时标 `reseed_required`，重新筛选并只回生成该角色受影响对白；不得静默换声。

状态机：`pending_candidates → provisional → frozen`；只有发生资产失效时进入 `reseed_required`。

**铁律**：① `voice_id` 全剧稳定，`mother_voice_id` 冻结后整剧不换；显示名不放进 voice 字段；②外部 TTS 普通改句按句重录；原生音视频无局部编辑能力时按最小受影响 Clip 重生。首次冻结或重选母音色时先核对既有 take，只修不匹配项；③任意两个高频对话角色音色差异以可听辨为准，优先拉开音高中心、音色质感、节奏与口音中的至少两个维度；④旁白别名自动识别（「他」「那人」指向谁，不新增音色）。

## 10. 抗趋同保护与身份锚点复核

> 解决真实失败模式：同一角色批量出图后，模型会悄悄把已确认设计拉回"大众审美"——方脸拉圆、伤疤消失、老人减龄、旧衣变新。§3 选择本镜需要的身份锚点，本节保护其中实际应可见、又容易被模型修正的特征。

### 10.1 趋同引力七宗 × 保护指令写法

| 趋同引力 | 表现 | 保护指令写法 |
|---|---|---|
| 美型化 | 方脸拉圆、棱角磨平 | 「保持方正脸型与下颌棱角，不柔化」 |
| 伤疤消失 | 缺口被"治愈" | 「左眉断疤必须存在，保持不对称，不修复不美化」 |
| 减龄 | 年龄向 25 岁回归 | 「保持五十岁年龄感：法令纹、眼袋、灰白鬓角」 |
| 比例标准化 | 头身比拉向 7-8 | 「严格 5 头身，躯干厚重四肢偏短」 |
| 服装精致化 | 旧衣变新、皱变挺 | 「外套肘部磨损起球，领口变形，保持旧物感」 |
| 表情甜美化 | 默认表情上扬 | 「默认表情无笑意，嘴角平直」 |
| 体型理想化 | 胖瘦向健美回归 | 写死具体体型词，并在保护指令里重复一次 |

**执行规则**：先从已确认身份事实中判断哪些非标准特征在本镜应当可见、对辨认或状态连续性承重，再写具体位置、形态与保护动作（如「左眉一道纵向断疤，保持不对称，不修复不美化」）。远景、背面或被遮挡时不把画外特征硬塞进画面；但构图应可见的承重缺口不能省略。未确认特征不得为制造辨识度而新增。

### 10.2 身份锚点复核

- 在原 characters.json 资产卡中维护本角色已确认、持久且容易漂移的辨认锚点，不另造固定数量的签名页；
- 生成提示词只复制本镜应可见、与同场混淆或状态风险相关的原锚点措辞，其他锚点继续留在资产卡，不强迫全部入画；
- 生图后核对预期可见锚点、服装/伤态和手—道具状态。应可见却丢失时修复或重生成；本来画外、背向或被遮挡的锚点不因未出现判废；
- 严恪按镜头职责与实际画面抽查，不以提示词逐字出现或固定条数代替身份辨认结果。

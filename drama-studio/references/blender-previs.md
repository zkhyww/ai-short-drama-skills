# Blender 白模预演：空间、动作路径与摄影控制

这是 Studio 分镜阶段的条件专项，不是新总控或每集必经流程。景川判断并统筹预演设计，丹青提供既有资产和空间事实；工具执行者按任务权限实现。只处理命中的片段，沿用分镜、Shot/Clip ID、资产 ID、修订与接续记录。用户没有要求精模、UV、骨骼或完整三维制作时，不扩成建模项目。

## 1. 什么时候读，什么时候执行

出现下列明确缺口时读取本文件，判断预演能否解决：多人交错路线难以核清；连续跨区域移动或镜头绕行需要统一空间；遮挡、过肩方向或信息揭示时机不清；门板、车辆、承重道具的运动与接触关系决定画面成败；已有生成反复出现空间漂移且静态参考不够。

题材叫“动作”“爱情”、存在两个人或换一个机位，都不单独触发。普通稳定正反打、单人情绪特写、已有合格运动参考可直接复用时，不新做预演；纯粹缺微表情读情绪表演库。用户明确要白模预演时可直接进入相应范围，不要求先付费失败。

读取方法不等于执行建模。`planning_only` 只把必要性、所需输入与采用方法写回原分镜说明，除非用户另已明确授权本地预演，不运行建模或渲染。实际制作范围已授权且工具就绪时，可完成所需本地预演，不逐镜增设审批；付费生成仍沿原预算与授权规则。没有 Blender 不阻塞无关剧本、资产和普通分镜工作。

## 2. 工具检查与安装指引

每次实际执行前检查本机事实，不把本文件编写时的安装状态当永久状态：

1. 查 PATH 中的 `blender`、Windows 卸载登记、常用安装目录、用户已提供的便携版路径；找到后用实际绝对路径执行 `--version`。未找到只说“在已查范围未发现”，不声称全盘没有。存在多个版本时先用与现有工程兼容的已安装版本，不静默升级或覆盖。
2. 只选当前需要的控制路线。CLI 用 Blender 自带 Python/bpy，不要求系统 `pip install bpy`，也不要求 MCP、uv 或电脑操控插件。MCP 则分别核服务配置、Blender 侧扩展启用/连接和一次只读场景查询；配置存在不等于连通。界面操作则核当前宿主是否真的开放原生应用控制，浏览器可用不等于可操作 Blender。
3. 缺 Blender：引导至 [官方稳定版下载](https://www.blender.org/download/)，Windows 选匹配系统的安装包或便携包，安装/解压到用户选定位置后确认 `blender.exe --version`。当前只授权检查/引导时，不自动下载、安装、提权或改 PATH。用户此前已经明确授权对应安装时可继续，不重复索要同一许可。
4. 需要实时修改已打开工程才选 [Blender 官方 MCP](https://www.blender.org/lab/mcp-server/)。按官方页分别安装 Blender 扩展、客户端中的服务器组件，并启动连接；只下载扩展 ZIP 不等于 MCP 已配置完成。以当次官方版本和宿主支持为准，不按社区同名插件猜配置。
5. 官方页在 2026-09-14 提供扩展 v1.0.3、最低 Blender 5.1.0，以及支持客户端的 `.mcpb` 包或源码安装入口。这是当日记录，不是永久版本锁。进一步设置页受验证限制时明确未读取，打开官方安装页供用户完成，不编造服务器命令、端口或客户端配置字段。
6. Computer Use 是界面操作的可选路线，不是 CLI/MCP 前置。宿主未开放原生应用控制时说明当前不可用，优先仍可用的 CLI；不得把文章中其他设备的“任意应用/锁屏操作”设置当成本机已有能力。

官方 MCP 会执行模型生成的代码，官方明确提醒缺少保护数据删除或外传的防护。只在已授权项目范围操作，保留源工程，审阅生成脚本的路径及文件操作；按实际风险使用隔离工作环境，不把完整用户目录交作可清理范围。此提示针对官方已说明的实际执行机制，不另建全项目安全流程。

| 控制方式 | 合适用途 | 选择边界 |
|---|---|---|
| Blender CLI + Python | 可重复的白模、相机轨迹、关键帧与分段渲染 | 本专项优先考虑；仍须看实际输出，脚本退出成功不证明画面正确 |
| 官方 MCP | 查询、修改当前打开的场景并交互调整 | 已连通时复用；长渲染与复杂操作拆成可保存的小段，超时先核是否完成，不盲重跑 |
| 原生界面操作 | 确需人工式界面路径、视觉调参或用户指定手动操作 | 当前宿主实际支持才用；不为预演全程逐按钮复刻建模师，也不一并要求三种方式 |

CLI 命令形态如下，仅在替换为已核验的绝对路径后执行；脚本由本次已定分镜生成并审阅，不执行文章中的任意代码。已有工程用副本路径加载，`--factory-startup` 示例仅用于新场景：

```powershell
& '<Blender绝对路径>\blender.exe' --version
& '<Blender绝对路径>\blender.exe' --background --factory-startup --python-exit-code 1 --python '<项目预演目录>\搭建预演.py'
```

`--background`、`--python`、`--python-exit-code` 来自官方命令行文档；具体 bpy/渲染接口依实际安装版本核验。首次使用只做一个简单对象、一台相机、少量帧的保存与渲染验证，成功后再处理目标片段。不因此对每集都做试演。

### 即梦官方白模插件：渲染与上传入口

使用已安装 Blender 制作白模并准备送即梦 Web 时，可选官方「Seedance 2.5 白模渲染上传器」。它负责导出/上传并跳转参考视频输入；不是 Blender MCP，也不替代本文件的空间设计、角色资产、提示词和验收。只需要现成白模视频时无需重新建模或渲染。

安装前先在 Blender 的 Add-ons 与 3D View 侧栏 Jimeng 面板核已安装/已启用情况；无法操作原生界面时，不凭目录存在宣称启用成功。需要安装则从[即梦官网](https://jimeng.jianying.com/ai-tool/home)的插件下载入口取得 ZIP：Edit → Preferences → Add-ons → 右侧菜单 Install from Disk → 选 ZIP → Install from Disk，完成后保持插件勾选。在 3D View 按 N 展开 Sidebar，选择 Jimeng。官网入口或本机界面变化时按实际版本核对；不把截图中的用户名、路径或下载链接当作配置。当前任务只整理方法，不自动安装或上传项目文件。

- **相机渲染**：插件视频上传方式选“相机渲染”，核当前相机、目标分辨率、输出路径及本次 Clip 范围后点击“渲染”；完成后使用出现的即梦链接/“上传至即梦生成”。输出先检查镜头、人物路径和接触，再上传。
- **本地上传**：已有经过核对的白模视频时选“本地上传”，选择该实际文件，再点击“上传至即梦生成”；不要为了走插件重渲相同内容。教程截图显示200M上传提示，仅作所示版本证据，实际限制仍按当前插件和网页验证，不硬写为所有渠道上限。
- 两条路径都会跳转即梦页面，将白模视频作为参考视频输入。进入网页后核视频是否真的挂载、对应片段/时长、当前模型与参数，再按 §5 补角色/场景参考和职责提示词。按钮或页面跳转成功不等于生成完成，更不等于影片合格。
- Web 插件与官方 dreamina CLI 是不同适配入口，不推断插件提供 CLI/MCP 服务或同一登录状态。已选 CLI 且可接参考视频时可沿原全能参考路线；已选 Web 则按网页实际能力执行。缺插件不阻塞已有视频参考路线，不安装无关 Maya 插件。

## 3. 从已有分镜建立最小白模

### 输入与空间基线

继承当前正文、场景拓扑、人物与道具 ID、目标画幅、Shot/Clip 范围、对白与动作时间预算、`show_now/withhold_now`、前段有效出态。缺失的承重地理或接触机制回原责任位；普通非承重几何可作为制作设计明确给出，不让白模悄悄改剧情。

在同一场景坐标系设地面、墙、门窗、通道、主要遮挡和交互道具，尺度相互一致；人物世界位置与银幕左右分开，不能按每镜图片各建一间镜像房间。固定物件保持同一对象和位置；门以真实铰链位置为旋转支点。角色、道具、相机分别命名并绑定原 ID，不以颜色作为唯一身份依据。

群体使用“对象名 → CHAR ID → 实际参考文件/区域 → 当前状态”的稳定对应；队伍的前后排只是当段站位，转角、交错或反打后仍按 ID 认人，不能按银幕左起顺序重新分配身份。同一人物多视图不能计作多人，多人参考图的合影排版不能成为剧情队形。逐人承担行动或回应的角色仍沿 asset-library 的独立身份参考要求；只补当前角色清单缺失的参考，不因群像案例合图方便而省去承重身份。

转弯段先定领行者转向点，再按前后间距和实际路径安排后续成员入弯、过弯与停步；相邻两人有扶持等接触时，联合核内外侧路径长度、手部可达及步伐调整。不能全队同帧原地旋转。转角后接续上一段的领行顺序、实际出入口、持物与未完成动作，不重演已经完成的转弯。

### 先分清参考任务

若已有参考视频，先在原分镜说明中选清职责，再决定是否需要 Blender：

- **只借镜头组织**：提取各段观看重点、景别变化、相机相对主体的位置、切换动机和大致节奏；用当前剧情重新安排角色与路径，不把原片人物、桥段、对白和固定秒数一并复制。没有实际观看或合格时间码资料时，不声称已复刻或逐帧拆解。
- **只借动作**：明确执行角色、源片段起止、目标时间段、执行次数、起势与收势；镜头按本项目设计。深度视频可作可见动作的参考，不等于骨骼数据、动作捕捉或准确三维路径。参考遮住的脚步、接触不能标已锁；目标空间、对手位置或体型不兼容时局部改设计，不强求一比一。
- **锁空间与相机**：用已定分镜在 Blender 搭建可编辑几何与相机；参考镜头轨迹、人物世界路径和最终外观分别承担职责。仅有转绘白模视频时，它仍是二维参考，不能当成可编辑 `.blend` 工程或物理正确的证据。

已经有可用的动作参考、且不缺空间设计时，不为了使用案例再建白模。案例 BLD-006 属于动作参考路线，不能因为收在同一组就触发 Blender。

### 精度由问题决定

- 仅核整体路线与画面构成：方块、胶囊或简单轮廓足够，标明朝向与体量。
- 需要核接触：补可辨的躯干、上肢或手部目标、道具接触面和占手关系；纯方块不能证明牵手、抵门或递物正确。
- 需要核视线与遮挡：设置眼睛/头部目标及主要身体轮廓；近景表情不靠白模证明，最终仍按表演库与实际镜头细化。
- 复杂生物和精细人体：优先已有可用简化模型；未经任务授权不调用付费3D生成或进行完整雕刻、拓扑、UV、绑定。外部3D资产也要符合项目来源与使用边界。

### 动画、摄影与时间

需要起跳、升降或大幅体态变化时，核起点支撑、离开支撑、运动方向与下一个镜头的动作阶段；伸出的肢体、背负物或展开部件必须有足够的轮廓包络与净空。只画质心轨迹不能证明复杂身体不会穿过栏杆、墙面或同伴。

先沿世界坐标完成角色/道具路径和关键接触，再放置镜头验证观看重点；相机的移动与人的移动分开设计。曲线与插值服从动作目的，匀速行走、突然受阻、连续追逐不能全部套平滑缓入缓出。路径可行不等于物理仿真已通过，未模拟的受力明确只为设计。

沿原总表确定切镜、焦点、前景遮挡、轴线与高度变化。合法跨轴可用可读的过渡建立，不机械禁止全部跨轴。既定画幅下检查主目标是否出画、重要手部是否被挡、相机是否穿墙；不要为修镜头擅自移动固定建筑。

按片段实际时间与项目帧率设置关键帧，换算帧号时统一零点和端点计数。对白、同步动作按重叠时间计算，白模人物不会说话不能成为压缩对白的理由。插入慢动作或加镜会改变输出时间，须重算对应后续区间并同步更新白模与提示词，不能一面“严格保留切镜时间”一面任意加时。

变速与加镜先分“插入”还是“替换”：若源动作区间长 a 秒被放慢成 b 秒，后续顺延 b−a 秒；只有真正新插入且不重复已有事件的画面才增加其全长。将源区间、目标区间和事件对应写回原镜头时间记录，音效按同一事件重新对齐。不能用作者“预演后加速”的经验默认全片加速；近处参照的视差、相机跟随和接触反馈也能表达速度，须保住动作与听答可读性。

## 4. 检查、局部修订与跨段接续

先看关键位置的构图，再以实际播放检查目标片段全程；关键帧可查静态关系，不能代替运动、接触和切镜验收。无可用视频查看能力时标“结构/关键帧已查、连续运动未确认”，保留待查范围，不写“完整观看通过”。

重点核：主体是否易辨；站位与朝向是否连续；接触前后的动作是否成立；道具是否只有同一件且有持有/放置/交接依据；镜头是否看见故事关键点；隐藏内容是否提前出现（包含本体、局部、影子、反射和会暴露方位或规模的声音）；切镜是否衔接同一次动作；结束状态是否足以接下一段。

信息揭示依靠真实遮挡与相机朝向共同成立，不能只在提示词写“最后才出现”。画外移动仍保留可行路径与耗时；被误认的两个对象分别建模、分别持有 ID，不能在遮挡后直接变成另一对象。主观视角切到外部仰拍或过肩时，继承同一次动作的高度、方向与阶段，不让角色重新起跳、重新出现。

发现问题只修改受影响对象、机位、关键帧与引用范围，沿现有 Shot ID 修订记录，不整场删掉重建。MCP 超时、后台任务未返回时，先查进程/任务与工程输出，避免重复新增模型或重复渲染。

跨 Clip 沿 `shot-contract.md` 的接续字段：同场共享基线、物件位置、角色路径、持物与动作阶段；跨区域从对应入口接续，转弯与越门槛要可读。规划预演按计划出态连接，正式生成后以所选实际剪辑出点附近连续画面核对；前段偏离承重状态时先修，不能盲把错误继续传下去。

## 5. 向视频模型交付参考

白模是运动与空间参考，不是确定性渲染指令；模型可能改变轮廓、时间、接触与路径。先核本次 provider/adapter/version 是否接受参考视频、数量、时长、画幅与素材类型；沿既有模型卡和原装配格式执行，不凭社交帖子宣称所有渠道可用，也不强迫项目更换已选模型。

| 参考 | 负责什么 | 不自动负责什么 |
|---|---|---|
| 白模预演视频 | 已验收的空间、整体运动、相机轨迹、遮挡与时间范围 | 脸、服装、肌肉动作、自然步态与微表情 |
| 独立角色资产 | 身份、外貌、服装及已确认形态 | 剧情行动与站位不能由资产静态姿势覆盖 |
| 场景/道具参考 | 已定外观、材质、尺寸关系、身份与状态 | 不覆盖已定拓扑或把未来状态提前引入 |
| 原分镜中的表演与声音 | 动机、语气、眼神对象、听答、自然动作及声音连续 | 不通过补台词或动作暗改故事事实 |

映射写在现有提示词参考职责位置：参考视频实际文件/上传序号 → 对应 Clip 和起止区间；各占位对象名及可辨外观 → CHAR/PROP ID → 实际角色/道具参考。不得只写“参考视频某月某日”或用相同颜色混淆不同人物；最终按本次接口实际语法绑定文件，不把示例 `image` 字样当有效附件。

明确保留与重新生成的边界：保留已验收构图、宏观轨迹、接触目标及切镜顺序；重新生成自然步态、呼吸、表情和材质，不继承方块滑行、刚性摆动或辅助标记。精细接触若白模未建，不声称已锁。只有必要的差异与约束进入当前 Prompt，不为“越长越稳”复制全部原文风格和负面词。

正式生成先选一段最有代表性的承重动作，在已有授权预算内比较其空间、动作与表演是否兑现；不预设必须两次成功，不因预演通过就跳过成片QC。失败按原因修空间输入、资产映射、表演表达或参数；预算耗尽沿原停止规则，不无限抽卡。作者“只生成一次”不能替代逐项验收：群体身份、承重鞋饰/配件、画幅与实际事件仍须单独核对。删除坏镜头后复核进出动作、声音和总时长；删掉问题画面不自动修复前后因果或接续。

## 6. 按问题取案例与中性操作示例

### 中性示例：关门被抵住

适用：既有剧本要求甲在门内关门、乙在门外抵门；关键问题是轴线、接触与持物连续，而不是单纯情绪不足。

1. 继承门的铰链与开启方向、甲乙站位和甲手中已有道具；建门框、门板、把手、两个人物代理及持物。若甲一手持物，另一手才可关门，不能同时凭空增加第三只手。
2. 先定门随甲拉动旋转的区间，再定乙手掌到达外侧门面的接触时刻；门不能在接触之前自动停下。接触后乙重心前移与甲后撤各有空间，门不能穿过任一躯干。未经仿真只标几何与时序设计成立，不称受力验证。
3. 用正反打或适当拉宽使关键手掌、门板与脸部至少在承重镜可读；前景肩膀可遮住非关键区域，不能遮掉抵门证据。继承同一扇门与持物，不反打一次就翻转房间。
4. 在现有提示词中写明：白模锁定门、人物与镜头关系；甲乙各自外貌沿角色资产；自然人体姿态、握持、微表情、听答和口型由既有表演设计提供。对白只在原规定位置出现一次。
5. 下一段从门已被抵住、双方既定位置与持续持物接续，不重新演一遍关门。若最终模型生成成未接触即停门，判该接触失败；不能只因脸好看就把该出态继续使用。

同一方法可迁移到递物、车辆穿越或多人绕障，但须重核各自几何和时序，不迁移本例门、人物或故事。普通坐姿对话若无这些空间缺口，直接用原表演/分镜方法即可。

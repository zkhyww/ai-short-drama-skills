# 生成能力供给与外部平台工序（v1.18.0）

> 用途：同时管理 `planning_only` 的方法参考与 `execution` 的生成能力供给。实际生成的**双层供给**不变——第 0 层是本机官方 `dreamina` CLI（默认引擎，OAuth 登录）；第 1 层是外部平台 flova，本机能力不够或用户点名时才路由。旧第三方即梦命令行工具及其浏览器签名状态不参与生产主链。外部 Skill 只在必要范围记录名称、作者、公开摘要、链接、许可与验证状态，不搬运内容进本仓库。

**工具、模型与操作渠道分别继承**：用户本次明确要求优先，其次继承已批准生图配置；视频工具另行路由。调用前在既有预览中核对本次图种/版式、模型/版本、分辨率、资产画幅、画风、按序参考文件及采用版本/职责、允许修改范围；局部改图沿用其余已批设置，不自行换未批准新图。生图画幅不自动继承视频画幅；未定项由执行者按资产用途、工具能力和既有预算给明确相容建议并标来源，不要求用户逐次填参数。CLI、API、网页只是渠道，“用CLI”不授权换模型；渠道不兼容须说明缺口，不能静默改用别的生图引擎。仅所选工具确为 Dreamina 时调用本脚本，并显式传入 `image --model --resolution --ratio`；脚本缺项即拒绝，不用默认值覆盖项目。局部编辑或依赖已批准视觉连续性的任务同时传实际 `--reference` 和 `--require-reference`，缺参考只保留规划，不退成文生图。执行前仍核实时接口、实际文件和用途；需要遮罩时先核接口是否支持，不虚构遮罩能力。已充分授权且配置无冲突时在原授权内推进，不新增重复确认。下述默认供给仅适用于未指定且能力相容的任务，不把单次速度、账号或本机可用性固化为通用能力。

## 2. 方法参考与实际生成路由（接回既有工序）

本节有两类入口，不能混写：

- **方法参考**：可在 `planning_only` 使用，不提交生成任务。方法路由先按「**任务入口 → 项目约束 → 当前阶段 → 当前创作问题**」收窄：题材/类型只帮助检索，不替代当前问题。沈砚确认任务范围、材料可达、既有批准与权限，不替专业角色选做法；丹青、景川、闻笙分别判断观看重点、现有约束与表现机会，再从已核规则/方法形成具体设计并做相称核验。这个判断**不要求用户点名**方法，也**不强迫每次联网**。每个创作问题只选一个主方法；补充方法仅解决另一个明确缺口。已批准的方法和产出继续沿用，返修只重选受影响部分。
- **案例与补搜**：存在 `local-config.json` 绑定时，canonical metadata / local_root / local_view 是本次权威入口；先在 canonical 索引核对所选 ID，再检查其输入缺项、原文完整性、模型声称与依据、来源/取得/观看/复现状态，获准且单条 TXT 可达时才读该条，不整库注入。绑定失效只停止案例消费，不把包内 README 快照冒充权威库，也不阻塞不依赖案例的现有规则原创规划；没有绑定时，公共 metadata 只可帮助发现候选，不得声称已读本地原文。用途标签仅供初筛，不证明适配。已有规则足以解决问题时直接设计；只有缺口涉及会改变故事事实、权限、模型能力或生产可行性的承重信息，或用户明确要求收集参考时，才在已有检索授权内定向搜索。没有检索授权时记录缺项，继续有依据的原创规划。本次任务明确不联网或不落盘时服从限制；取得材料后也只有已有入库授权时才持久化原文或媒体，不为每条材料重复确认。
- **派单与落位**：专项输入只给「**观看重点 + 已锁事实资产 + 目标模型条件**」。沈砚在现有角色模板的规范/方法注入说明中随命中原文写清：本次用途、适用与排除条件、来源定位与版本、具体回填的既有资产/镜头/声音位置、审阅者能看到的结果证据，以及缺文件/条件不符/实作失败时回到哪条现有通用规则或原责任角色。专业角色再把设计落进**现有资产 / 镜头 / `prompt-assembly.md` §2 路由后正文**；方法说明本身不进入剧本或可复制 Prompt 正文，不新增表头、检查槽位、管线、阶段、字段或交付物。方法只作用于承担对应观看功能的段落或镜头：先写出可观察的启用条件再给具体创意；不承担该功能的镜头可不启用，缺少具体职责或启用条件时先保留为可选方案。没有引用专项方法不是失败，只要观看任务已由现有通用技法完成并有可观察证据。
- **实际生成**：沿原有 `execution` 流程做工具、登录态、积分、实时 schema 与用户授权预检，再按下方第 0/1 层供给执行；方法候选、公开说明或接口返回成功都不能替代这套预检。

**方法边界**：外部规则中的动作数、镜数、尺度数等固定计数无当前任务证据时不移植；不能为使用方法补人物、建筑、道具、破坏状态或改结果。除非既有硬边界或当前任务证据已要求，不得把外部方法改写成新的必做项、齐套检查、硬门槛或每镜合同；条件不足只能保留候选，不能靠换措辞启用。读取方法不等于安装、运行脚本、上传或生成，这些副作用分别核对授权。每次仅引用解决当前观看任务的必要范围，不整包强注入成员上下文。QC 只看真实产出是否完成观看职责；方法不相称或失败时，按证据把受影响部分退回原责任角色替换、回落通用技法或局部细化，不据方法名称判通过。

```
execution 预检（SKILL.md 第 0 步）
  ├─ 第 0 层：本机官方 dreamina CLI（默认引擎）——dreamina version + dreamina user_credit + 目标子命令 --help
  │    └─ OAuth 登录有效且有积分 → 先用 scripts/dreamina_route.py 校验并预览命令；耗积分告知后再执行预览中的 dreamina 命令
  └─ 第 0 层不可用（未登录/无积分/能力缺口），或用户点名外部平台
      → 第 1 层：检测 flova 连接器（connector:flova，service.flova.tv/api/mcp/）
          ├─ 已连接 → Read 本文件 → 按下方匹配规则选 Skill → 用户确认 → 指定 Skill 模式调用
          └─ 未连接 → 停留在 planning_only，交付文本产物 + 提示接入方案
```

**匹配规则（三步，缺一不停下来问用户）**：

1. **需求归类**：本批缺的是什么能力？——全流程成片（替代类）/节点能力（增强类）/风格包（导演美学类）。依据=当前工序节点 + 用户原话。
2. **候选锁定**：从本文件能力面表选类别 → 用 `skill_list`（个人库，only_brief=true）与 `skill_feed`（公共库分页）按名称检索，NFKC 规范化后精确匹配；命中多个时列 2-3 个候选带公开摘要让用户选，命中 0 个时报告「无匹配」不强凑。
3. **用户确认**：flova run 每轮一次、关键阶段有确认停点——**选哪个 Skill、交接什么内容，必须用户点头才开跑**；不静默消耗用户积分。

## 2.5 外部 Skill 能力的三种合法用法（v1.15.1 收窄）

> flova Skill 是**云端编排资产，不可下载到本地加载复用**——想在我们的流程里用上 flova 的 Skill 能力，按场景三选一：

- **A. 运行时调用（要它原生效果时）**：flova 连接器指定 Skill 模式（`skill_list` 查个人库 → NFKC 精确匹配 → 用户确认 → run）。积分消耗在 flova 侧；适合全流程成片类/重型编排类 Skill。
- **B. 原创方法归纳（只借鉴思想时）**：仅可结合当前问题、来源与适用条件，用自己的结构和表达归纳公开方法的思想；公开可读不代表可复制发布。无许可证或来源争议先记录待核，不复制第三方长文、资产或脚本进公共仓库，也不把作者提示词的截断版本改写成“优化版”。经实际验证且获得写入授权后，才原位合并进对应 references。
- **C. 自建等效工作流（编排简单时）**：方法思想若只是「分镜提示词→图→视频→拼接」类简单链路，用第 0 层官方 `dreamina` CLI、本地时间线脚本和我们的既有角色原创实现等效能力——不复制第三方正文、资产或脚本，积分花在即梦，产出归我们 QC。**能自建的不外发**。

判定顺序：B > C > A——能原创归纳并验证的方法不跑云端，能本机自建的不外发，只有确需原生编排能力时才运行时调用；该顺序只选使用路径，不授予复制、发布、安装、上传或生成权限。

## 2.8 全流程 Skill → 自建等效工作流映射（v1.15.1 收窄）

> 用户选择「积分用在即梦」后，全流程成片类 Skill 只提供方法思想参考；核对来源、许可和适用条件后，由我们的既有角色与工序原创实现等效能力（路径 C），不复制第三方正文、资产或脚本。下表保留已核能力与我们现有工序的对应关系，不把外部固定计数变成生产配额：

| flova Skill 的编排段 | 它的做法 | 我们的自建等效（已有角色/文件） | 缺口 |
|---|---|---|---|
| 剧本分析拆解 | 解析剧本→分集分场→拆元素清单 | crew 望舒+纪遥（按项目锁定集数的粗纲/人物小传/元素档案） | 无 |
| 角色/场景设定图 | GPT Image 2 出角色卡+场景卡，多宫格锁定 | 丹青按 asset-library §2 复用/建立独立角色参考；视频参考规划再按 §4 复用或组装本集共享的按集参考总表，场景/道具 Panel 可直接履责，独立图只补具体可见缺口 | 无（项目媒介与实际输入职责控制描述深度） |
| 分镜设计 | 多宫格分镜参考图→一镜到底工作流 | 景川六问判读+维度装配+逐 Clip 路由后视频提示词（统一中文八段式） | 无 |
| 视频生成 | Seedance 2.5 逐镜生成 | 景川 `execution` 按输入类型路由官方 `dreamina text2video` / `dreamina image2video` / `dreamina frames2video` / `dreamina multimodal2video` | 无 |
| 时间线合成 | 平台内自动拼接成片 | `scripts/assemble_timeline.py` 调 ffmpeg：先统一编码、帧率、分辨率与时基，再拼接；ffprobe 验证视频流、音轨、尺寸与时长 | 无 |
| 音频链路 | 原生音频或 TTS 配音 | **Seedance 原生音视频联合生成为主**（对白/环境音/动效一次出）——未冻结时用文字音色锚定找候选；已冻结母音色且接口支持时，把该样本作为后续正式对白镜的音频参考；只有音频参考不支持或实听仍失败才走外部 TTS 后备 | 无 |
| 关键阶段确认 | 里程碑暂停等用户点头 | 沈砚停点制（资产确认/首批分镜确认/交付严恪） | 无 |

**纯拼接入口**：已有获用户认可片段且明确只裁切/拼接时，直接按陆离角色卡和 `scripts/assemble_timeline.py --timeline` 合成，不重走下列生成链。

**「一键成片·自建版」串联顺序**：剧本→crew 创作定稿→丹青复用/锁定最低必要的人物身份、场景事实/拓扑和关键道具状态→景川从本集分镜选出有用关键构图→明确需要总表且现有参考存在真实缺口时由沈砚退回丹青窄补组装，场景/道具 Panel 可直接履责，各 Clip 只绑定相关区域并保护未来披露；未明确请求综合图板时，已有合格多图/旧按 Clip 表直接复用→普通声画同一执行者终编、音色继承用户选择→景川按 `prompt-assembly.md` §2 路由终编提示词（台词唯一正文位为第五段（Block 5））→只有设计确认具体视觉缺口后才按已指定生图工具的可用接口生成；仅当前生图工具确认为该适配器时使用 `scripts/dreamina_route.py image` 预检；静态参考不保证连续运动→`scripts/dreamina_route.py video` 按素材路由：纯文本=`text2video`，单首帧=`image2video`，首尾帧=`frames2video`，图/视频/音频混合参考=`multimodal2video`→`scripts/assemble_timeline.py` 先标准化各镜，再拼接并用 ffprobe 验证，成片写入 `05_成片/`。Seedance 默认原生生成对白、环境音与动效，**无需独立配音步骤**。默认用户自行匹配人物音色，不因未选声音自动生成候选、提取或冻结音轨。下述音频资产接线仅已有用户音频输入或明确委托声音管理时启用；**已冻结母音色**且接口支持音频参考后，每个后续正式对白镜把该样本作为 `multimodal2video --audio` 音色参考，并在 Prompt 中按上传顺序**明确绑定音频编号、角色与音色用途**；Seedance 2.0 全能参考同时带角色图或视频，2.5 才允许纯音频输入。此时**仍由 Seedance 原生生成对白与口型**。接口不支持、音色仍漂或口型串音且用户已授权外部声音处理时才走独立 TTS＋lip-sync，并由合成脚本以 `--external-audio` 使用已按成片时间线对齐的外部混音；`replace` 会替换整条音轨，须保住环境声/动效；`mix` 不可把新旧对白叠在一起；**外部 TTS 才是后备**。官方 `dreamina` CLI 不提供独立 TTS 子命令，不得虚构 `dreamina audio`。

**音声设计提示词要点（v1.13.6 校正）**：①模型 Prompt 与投稿剧本排版分层，并服从项目语言锁。按火山方舟 Seedance 2.0 指南，先写角色、动作、表情与发声方式，**台词内容放在 `{}` 内**，音乐用 `（）`、音效用 `<>`、字幕用 `【】`，如 `林晚放下手机，眼眶微红，轻声说{原来是这样}`；多角色逐角色分行。Dreamina 页面示例也接受 `Girl says happily: "..."` 一类引号句式，但它不是覆盖全部接入方的唯一格式；`execution` 以本次 provider/adapter 的当前指南与实测为准。②台词容量与 L-Cut 统一按 dim-audio 的连续声窗核对，画面切换不增加音频时长；③每个独立 Clip 在路由后的声音职责位声明角色声线/母音色绑定一次（通用【声音】/专项 Block 8），组内只写表演变化，不能把重复文字当成已锁母音色；专项 Block 8 不复写 Block 5 台词；④音效写具体可听事件，不写“合适的背景音”；⑤对白、环境音、动效与可选 BGM 的层级按 dim-audio 执行。原生音频翻车时先单镜重生，再按上段外部 WAV/TTS 后备处理。

**官方 CLI 实测约束（2026-09-03）**：`image2video` 接单首帧并从输入图推断画幅；`frames2video` 接首尾帧；`multiframe2video` 用于多帧连续故事；`multimodal2video` 接图、视频、音频混合参考。纯文本与多模态模式可显式传 9:16；首帧/首尾帧模式不传 `--ratio`，输入图必须先做成目标画幅。静态模型卡与实时 `--help` 冲突时，以本次官方 CLI 和后端校验为准。

## 3. 交接格式（我们产出 → flova 输入）

flova Skill 接受自然语言指令 + 上传素材。交接包按目标 Skill 的输入要求组装，基准清单：

- **剧本类**（剧本生视频/多集短剧等）：剧本正文（crew 产出的投稿版 Markdown 原文）+ 集数范围 + 画幅与时长要求 + 风格参考（有则附）。
- **分镜类**（动作预演/武打片段等）：本批 `03_分镜/prompts_SXX.md` 的目标镜头提示词（保留原格式，不加代码围栏）+ 涉及角色的实际可用资产图（`02_资产/` 中已验收的角色综合设定板或既有定妆照/肖像/三视图等分图，按本批职责选择并通过 upload_ticket 上传，不为交接新造上传前置）+ 动作节拍说明。
- **素材类**（视觉开发素材包/拉片复刻等）：剧本或分镜表 + 参考图/参考视频。

**交接纪律**：①一次交接只带本批需要的素材，不整包倾倒；②flova 产出的成片/素材落盘回我们的 `06_临时/`（试看）或 `05_成片/`（定稿），由严恪 QC 双层结论验收后归档；③外部平台产生的积分消耗在开跑前向用户说明量级；④flova 项目链接原样交付给用户，不转述不省略。

## 4. 官方 Dreamina CLI 能力速查（第 0 层默认引擎）

| 项 | 本机实测（2026-09-03） |
|---|---|
| 身份认证 | 官方 OAuth Device Flow；`dreamina login` 登录，`dreamina user_credit` 同时验证登录态并读取当前积分，不把余额写死进规范 |
| 图像 | `dreamina text2image`；有 1–10 张本地参考图时用 `dreamina image2image`。当前公开图像模型为 3.0–5.0Pro，参数以子命令帮助为准 |
| 视频 | `dreamina text2video` / `image2video` / `frames2video` / `multiframe2video` / `multimodal2video`；Seedance 2.0 系列 4–15 秒，Seedance 2.5 为 4–30 秒。未指定模型按 `prompt-assembly.md` §1 的单次 Clip 时长路由，不用单集总长代选 |
| 画幅与分辨率 | 视频分辨率未指定时默认 720p，已明确且兼容的设置优先；生图分辨率/画幅另按上述已批配置与资产用途解析。文生/多模态视频支持 9:16 等公开画幅；图生视频画幅跟随输入图。Seedance 2.5 当前支持 480p/720p/1080p；其他组合按目标子命令实时帮助核对 |
| 混合参考 | 2.0 系列：最多 9 图、3 视频、3 音频、合计 12；2.5：最多 30 图、10 视频、10 音频、合计 50，且允许纯音频参考 |
| 音频 | Seedance 原生音视频联合生成；官方 CLI 无独立 TTS 命令。外部母音色/WAV 可作多模态参考，独立 TTS＋lip-sync 仅为后备 |
| 命令预检 | `python -B drama-studio/scripts/dreamina_route.py image --prompt "…" --model <已解析生图模型> --resolution <已解析分辨率> --ratio <资产画幅>`；需要参考时加 `--reference <实际文件>`（可重复）及 `--require-reference`。`image` 与 `video` 都只输出 JSON 命令预览，不提交任务；核对参数和授权后才执行其中的官方命令 |
| 文件技术检查 | `python -B drama-studio/scripts/dreamina_route.py check-image --path <实际文件> --format <请求格式:PNG/JPEG/WEBP> --ratio <资产画幅>`；请求不透明时加 `--opaque`，需要透明则不加。依赖 Pillow，缺依赖时明确“技术未检查”，用现有可用工具补核。命令只读真实格式、尺寸、比例与透明度；尺寸仅报告 `width/height`，须另与请求分辨率/最低像素核对。`technical_pass` 不替代该尺寸核对及 asset-library §1 的实图内容验收，不修改原图 |
| 常见阻塞 | 某模型首次使用若返回 `AigcComplianceConfirmationRequired`，先在即梦 Web 端用该模型完成首次生成，再回 CLI；这与登录签名无关 |

**纪律**：①命令预览、`--help`、积分查询和本地 ffmpeg 合成本身不提交生成任务；执行生成命令前必须向用户说明预计积分量级；②provider/adapter/version 与参数以当次官方 CLI 实时 schema 为准并写入调用记录；③官方 Dreamina 能力覆盖不到的风格包编排或多 Skill 工作流才升级第 1 层。

## 5. 方法候选与新平台登记

- **方法候选**：只在现有对应条目内记录「触发 / 输入输出 / 适用模型 / 来源版本 / 许可 / 验证状态」。采集、完整观看与生成复现是不同证据，按候选风险和用途选择相称的文字、接口或生成验证；合理方法不必一律付费生成。未复现只限制该候选的可信声明、自动升格与生产注入，未复现不强制付费试制，也不阻塞其他已获授权工序。候选不得写成已安装可运行。
- **已实测平台能力**：后续接入新外部平台（新工具/MCP/生成服务）时，按本文件同构在本节登记能力面表（实测数据 + 统计日期）→ 三类关系判定 → 路由规则 → 交接格式 → 纪律。登记前必须实测能力清单，不凭印象登记，也不把方法候选冒充平台能力。

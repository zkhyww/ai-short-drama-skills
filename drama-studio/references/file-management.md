# 文件管理与清理规范（单一真源、资产复用、按需资料）

> 以用途、当前状态和真实依赖判定，不按文件名、后缀或目录判废。新文件先判断是否已有合适落点；现有目录与路径优先，不自动重排用户项目。阶段/批次收尾可审计，但审计不等于删除；实际删除服从当前授权与宿主逐文件安全规则。

## 0. 过程透明与产生文件的边界

1. 实际产出及时落盘，优先更新本项目既有相应文件/章节，不为一次回传、检查或回复再造一份报告。纯问答、不产生新事实的通过说明留在回复或已有记录，不强建文件。
2. 决策节点展示实际资产、正文/分镜/提示词及真实审核结果；非决策过程在自然节点合并通报。资产批次按“本批工作与下一动作 → 实际资产图册 → 纯提示词引用”呈现，均取自既有索引/复用说明和原文件，不维护第二份清单。图册展示真实可加载图片、用途、ID/Panel、版本、覆盖与来源采用状态，缺图明确占位；不改写原候选/采用标签。路径存在或加载成功不是内容审核；首次转为 file_ready 仍按 asset-library 核验。只改一条提示词等简单任务直接交原文，不强制图册或看板。
3. 独立审核职责不合并成作者自审；可以由主理人在已有验收记录保留不同审核人的原文、范围、版本与结论。并行成员先在各自工作位置写候选，主理人顺序汇入，避免多人覆盖同一文件。
4. `planning_only` 只生成已要求的规划；未生成/试听/剪辑/测量就不造正式音轨、成片或 QC 通过报告。文件名、目录、空模板不能充当完成证据。

## 1. 四类文件及真源职责

| 类别 | 内容与处理 |
|---|---|
| 当前使用 | 唯一标准正文；实际启用的设定/人物/集纲/正典；当前资产索引及所指版本；分镜/提示词；实际声音、剪辑与交付物。保留，修改沿依赖更新 |
| 工作待处理 | 未审候选、未合并增量、生成任务恢复数据、待解决失败记录。按任务/批次隔离，不冒充正式，不纳入常规删除 |
| 历史与来源 | 原始输入、已采用旧版、关键保存点、许可证/来源、审核证据和备份。默认保护；可在已授权归档时退出活动阅读入口，保留路径及覆盖范围 |
| 可清理候选 | 本任务明确产生、已完成用途、确实可再生、无项目或外部已知依赖且不承担来源/回滚/证据用途的缓存、中转与重复预览。须按 §5 逐项核验，不自动等于可删 |

剧本管故事事实；资产索引管身份、文件版本与使用状态；分镜总表管镜头设计；提示词是对应设计的执行表达，不能另立故事事实。各自真源通过原有 ID、路径、修订与引用连接，不互相复制成多套活动记录。 可视图册、作业汇总和 HTML 是派生展示，不回写源记录；展示原有依赖与未决项，不造执行顺序或付费队列。只从显式依赖状态判断未决，未记录不当作已解决。

## 2. 目录按实际工序创建

已有项目沿用当前入口与目录。新制作项目可按下列职责组织，只在首次产生对应文件时建目录，不预建空七件套：

| 位置建议 | 何时使用 |
|---|---|
| 当前执行入口/既有索引 | 指向唯一正文、必要配套、当前资产/分镜/声音、已审范围和下一动作；按需附同源图册或只读 HTML 快照，不抄正文、不另建人工维护索引 |
| 01_剧本 | 同项目直接引用原标准正文；跨项目确需交接快照才保存只读副本及来源路径/修订/哈希，不建立第二活动正文 |
| 02_资产 | 实际启用的资产索引、人物/场景/道具档与参考文件；可用外部已核验路径，不强制复制 |
| 03_分镜 | 实际批次分镜总表与提示词集；按版本对应。实际启用白模时，其必要源工程、有效脚本和采用的预演参考放本区或既有工作目录，原分镜引用；规划不预建空白模目录，过程推导不默认另成套落盘 |
| 04_声音 | 实际需要的声音卡、音轨/母音色、参数及音乐方案；审核可在对应记录留章节 |
| 05_成片 | 实际剪辑工程/依赖、交付媒体和对应 QC；规划任务不填假成片结论 |
| 工作区/历史归档 | 当前候选、未合并增量与历史版本按用途分开；已有路径优先，不批量迁移 |
| 06_临时 | 明确可再生的处理中转与缓存；若既有 uploads 在内仍按用户原件保护，不能因目录名删除 |
| 07_交接（按需） | 默认引用原地有效文件；明确需要离线/外发包才复制，登记源版本且不回写为真源 |

可选离线看板由 `scripts/build_production_board.py` 从明确文本来源导出；无服务、不扫描目录、不生成图片、不打包媒体，图片从原路径加载。适用于多资产/多提示词集中查阅或用户明确要求，不替代原交付与审核。

```powershell
python -B <已安装drama-studio绝对路径>/scripts/build_production_board.py --root "C:/项目" --assets "02_资产/asset-index.json" --record "02_资产/复用说明.md" --image-prompt "02_资产/角色词.txt" --video-prompt "03_分镜/C01.txt" --output "制作看板.html"
```

`--assets` 接受既有 JSON 列表、assets/rows 容器、ID 字典或 CSV；未知结构原样显示并告警。`--record` 仅展示管理记录；每个 `--image-prompt/--video-prompt` 须明确是单条纯正文，混合文档用 `--prompt-range video "03_分镜/多条词.md" 12 35` 指定含端点行范围，不按标题猜边界。两个类别分别复制，正文保留源顺序、字符与换行；来源、案例说明、检查结论不进入复制。自动复制受限时提供只读手动选择，浏览器可能规范化手动复制的换行。

文本仅限项目根内的显式文件；外部图片用 `--image-root "D:/共享资产"` 明确允许目录，工具只核索引引用的本地 PNG/JPEG/WebP/GIF，不加载网络或活动图像。未准入、缺图、格式不符或浏览器无法加载均明示；不因路径存在把未知状态升级。输出只可写项目根内 .html，默认不覆盖；确认更新派生快照时加 `--overwrite`，仍禁止覆盖源输入。快照标来源哈希与生成时刻，源更新后重建，旧板不冒充实时状态。外发需另审来源文本与图片权限，不能直接发布含本机路径的看板。

## 3. 命名规范（防混乱的第一道闸）

| 类型 | 格式 | 示例 |
|---|---|---|
| 角色资产 | `char_{资产ID}_{用途}_v{n}.png` | `char_LN_03_综合设定板_v1.png` |
| 场景资产 | `scene_{资产ID}_{用途}_v{n}.png` | `scene_OY_01_主环境_v1.png` |
| 道具资产 | `prop_{资产ID}_{用途}_v{n}.png` | `prop_JS_01_道具_v1.png` |
| 按集参考总表（新默认） | `episode_E{集号}_参考总表_v{n}.png` | `episode_E01_参考总表_v1.png` |
| 旧按 Clip 镜组参考总表（兼容） | `clip_{ClipID}_镜组参考总表_v{n}.png` | `clip_C01_镜组参考总表_v1.png` |
| 分镜/提示词 | `storyboard_S{集号}.md` / `prompts_S{集号}.md` | `prompts_S01.md` |
| 成片 | `E{集号}_{内容}_v{n}.mp4` | `E01_剪辑_v1.mp4` |
| **临时文件** | 按实际用途标 `_draft/_retry/_preview`，不能据后缀判可删 | `E01_打斗_draft.mp4` |

> 资产 ID 与资产库 JSON 中的 ID 完全一致（asset-library.md 的 ID 体系）；按集形式是新建视频参考的默认，既有按 Clip 文件继续有效，不批量重命名、移动或重组。后缀、目录和修改时间只是查找线索；候选稿、已采用预览、复用来源及证据仍受保护，按 §5 判断存废。

角色资产新命名按实际用途写“综合设定板/定妆照/肖像/三视图/细节/表情宫格/动作宫格”等；本规范更新不追溯重命名、移动或删除任何已有图片，既有文件路径和资产索引继续有效。用户明确要求纠正名称时保留稳定资产ID，以已确认身份/别名、用途、必要状态及版本消歧；记录旧名到新名映射，同步活动索引、提示词输入、声音角色绑定与未提交清单，核文件内容哈希未变。音频文件名不能直接当角色身份，别名确认后显式绑定；历史已提交快照不改写。

## 4. 资产版本与依赖保护

**实际生成与选片记录**：冻结请求与实际命令逐项比对模型、单次时长、分辨率及按序输入文件/职责，连同回执保存在既有调用记录，不用提示词或预览补造实际结果；成本口径见 `models/dreamina.md`。已提交任务状态未知时，下一动作是用原 `task_id` 只读查询；这是恢复既有任务，不是新增付费生成，不因没有增费权限退回 `planning_only` 或等待重新授权。查询工具不可用或仍无确定结果时保留 `unknown` 和恢复信息，只暂停依赖项；重新提交才另核预算与授权，不能盲目重复付费。实际剪辑在既有时间线保留源文件、入点、出点、顺序；沿用已有格式即可，调用合成脚本时使用 `{"clips":[{"path":"clip.mp4","in":0.75,"out":8.25}]}`。此最小记录为重建选片服务，不另建并行账本或强制报告；原始媒体与历史提交保留，未受影响引用不重写。

- 人物/场景/道具沿用 asset-library 的稳定 ID；同一身份变体沿原 ID 管状态，新文件不自动新身份。现有索引/复用说明标当前采用的文件版本及所需场/Clip/声音引用，不能仅凭最新时间戳替换已绑定版本。
- 实际提交采用本 Clip 已确认的精确输入白名单，按类型、顺序、当前路径/版本及必要哈希核验；不遍历整个资产目录或取“最新文件”自动组包。被否决或已删除素材立即退出当前输入链，历史证据继续可读但不得回填生图；同哈希文件删除前仍先核实际引用。清理不是防污染的唯一手段，活动索引先排除才不会误用。
- 候选、采用、被替代/归档是文件使用状态；与 `prompt_only/file_ready/external_mount_plan` 的就绪状态分开。一张图真实可读不代表已获采用，历史图也可能仍被旧集或其他项目引用。
- 新版本确认后只更新实际换用它的依赖；既有分镜、Panel、提示词、音色来源、剪辑工程仍引用旧版时，旧版继续保留。资产替换不能静默让全剧变脸或使旧 QC 为新稿背书。 已导出图册/看板标旧快照，按需从同一来源刷新，不把 HTML 修改当资产版本更新。
- 没有直接上镜不等于无用：参考图、校色/母音色源、剪辑原素材、模型输入、失败证据和授权材料都可能承重。AI 生成有成本且未必能逐字节复现，不能只因可再调用模型就判为可再生缓存。 白模 `.blend`、有效生成脚本和已采用预演视频分别是可编辑来源与模型输入，不能因名称含“预演”归为垃圾；渲染中转帧仍按实际依赖逐文件审计。
- `reuse_asset_ids` 引用原资产，跨项目复用核已知使用方；用途或外部引用无法确认时保留。用户原件、备份、正式报告及已确认版本不因“不够重要”进入常规删除。

## 5. 审计分类与删除条件

先看内容及当前用途：与剧情/人物/规则/制作/审核/授权/来源恢复均无关的新增说明不再生成；已有这类文件先判断来源与依赖。可合并且独有信息已完整保存的资料可在获授权整理时合并并更新引用，旧来源保留历史定位；正文外的文件不自动是垃圾。

| 常见对象 | 默认判断 |
|---|---|
| 不影响选择、因果、辨认或连续性且无已确认承诺的闲置设定 | 不新增扩写；已有内容退出常规派单、按需查阅，不擅自抹掉已确认世界或后季伏笔 |
| 重复自检、过程总结、无新结论说明 | 新结论并入已有对应记录；已有报告先核独有证据，不能以整理取消未解决项 |
| 已合并批次增量/候选正文 | 标合并目标与修订，保留在工作历史；未合并不得清理，不逐次复制全剧 |
| 失败生成、旧图/旧音轨、旧版成片、预览 | 先核是否被引用、用于取证/母音色/回滚；默认工作或历史，不按后缀自动删 |
| 明确本任务产生的可再生中转/缓存 | 用途完成、无引用、非来源/证据/备份且授权覆盖时才可逐个删除 |
| 用户原文件、来源压缩包、正式报告、许可证、备份、其他任务产物 | 默认受保护；即使在临时目录也一样 |

**实际删除的全部前提**：
1. 确认任务根、文件生产者、当前使用状态与实际用途已完成；核索引、正文/配套链接、分镜、提示词、Panel、音轨/剪辑工程及可知跨项目引用。无法核清不删。
2. 确认不是用户原件、证据、备份、未合并候选或不可复现资产。目录、后缀、文件大小、mtime 和“已过期”不能独立证明可删；同哈希也要核哪个路径被引用。
3. 解析精确绝对路径，确认最终目标留在授权根内；链接/目录联接的真实目标不明时不删。不递归、不通配符、不按列表自动批量循环、不跨 shell 拼删除命令。
4. 有现成授权且明确覆盖的单项无需重复问；需多项删除时遵守宿主逐项确认/用户手动清理要求，泛称“优化管理”不等于批准批量删除。无授权先给具体路径、大小、理由与保护检查结果，保留文件。
5. 每次只处理一个确认的文件；删除前复核未被新任务引用，删除后核保留文件与链接。失败立即停止，在已有记录留简短结果。

## 6. 时机与跨会话恢复

- 批次/阶段完成、用户要求整理或空间异常时做本任务范围的轻量审计；活动任务的中间件、恢复数据和候选保留。无需等整剧结束才发现堆积，也不在每个镜头后打断用户。
- 默认审计不删；实际清理由 §5 授权及依赖条件决定，原项目更严格的已确认保留约定继续生效。无候选不生成清单文件、不询问，已有候选记录直接更新，不按轮次新建清理报告。
- 恢复先读当前入口与状态，再沿当前任务依赖读取正文/配套、资产、分镜/提示词、声音、剪辑及审核/未决项；不固定只读 02+03。未完成任务必要的中间文件可读取，但不能变成唯一永久依据；在删除前先固化必要恢复信息。

## 7. 与 asset-library.md 的关系

asset-library 管资产身份、内容、状态与参考链，本文件管文件用途、布局、版本保留和清理。索引与物理文件对应；已采用资产从工作位置转正式时，先确认文件可达及相关引用完整更新再处理原路径，不靠改文件名冒充验收。

## 8. 创作侧衔接与交付

- 同项目只引用 Crew 唯一标准正文，不为放进 01_剧本 再复制活动稿。配套人物/世界/集纲/正典及实际审核材料按交接范围继承，reviewed/unreviewed/not_provided 如实标注。
- 合规、终审与连续性是独立判断，可保存在同一验收文件的分区；来源、审核人、修订、范围、未决项和结论必须可定位，合并文件不等于合并职责或删证据。已有独立有效报告可继续引用，不强改路径。需要外发时仅按接收方需要打包，内部过程不混入正文。
- 输出在原地交付并引用，资产/分镜/声音/成片不重复复制成“汇总版”。Crew 管其工作历史，Studio 管其制作资产，清理其他任务产物须由其负责人确认；不把通用规则更新自动当作当前项目迁移或删除指令。

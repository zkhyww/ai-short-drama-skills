# 文件管理与清理规范（资产归档 + 临时清理 + 过程透明）

> 清理只在**整剧交付时**执行一次：批次中不删、不问、不出清单；整剧交付后确有候选时，**一次审计、一次用户授权、一次清理**。核心原则一句话：**资产（可复用）归档保留，临时（一次性）识别清理，过程产出即时落盘、按级展示（防黑盒）。**

## 0. 过程透明（防黑盒 · 每个阶段产出即时可见）

1. **产出即落盘**：每个阶段产出（资产/分镜/提示词/声音/成片/QC）完成后，立即写入对应保留目录（02_资产/03_分镜/04_声音/05_成片），**不等整剧做完**。
2. **展示分级（v1.10.0 与 SKILL.md 第 2 步统一）**：**决策节点主动 present_files 展示**——资产建档产出、每批分镜+提示词、成片自检与 QC 报告、最终交付四类必展；其他非决策中间文件落盘后不逐个打断，在下一个自然节点合并通报文件名（**落盘 ≠ 打断**，用户要求时展开）。
3. **关键关卡必展**：①资产建档产出（资产确认弹窗前先展示文件）；②每批分镜总表+提示词集（`storyboard_SXX.md`/`prompts_SXX.md`）；③QC 报告（`delivery_check.md`）。
4. **阶段间纠偏**：用户看完展示可随时要求调整（改资产/镜头/提示词），纠偏发生在阶段间而非成片后；临时区文件按第 5 节清理。

## 1. 核心原则

1. **资产保留**：人物/场景/道具/音色/参考图/分镜总表/提示词集/成片——这些是项目资产，跨集、跨会话、跨项目可复用，**永不清理**。
2. **临时清理**：中间生成图/失败重跑/预览试听/草稿/上传下载缓存——一次性产物，**整剧交付时按审计制清理**（批次进行中保留不动）。
3. **清理先审计（v1.7.2 定版）**：清理动作分两步——先出**审计候选清单**（文件路径+大小+删除理由，落盘展示给用户），用户确认后才执行删除；未经确认只清不动。先交付后清理；清理只删临时目录，保留目录禁止动。
4. **uploads/ 与用户原文件永久保护**：`06_临时/uploads/` 内一切文件视为**用户上传原件**，只增不删、永不清理（用户明确要求处理某单个文件时除外，且须逐个确认）；审计清单也不得将其列为候选。
5. **删除执行范围收窄**：单次清理只允许删除**当前任务生成、可再生、无引用**的带后缀临时文件（`_draft/_retry/_preview/_old`），且逐文件执行、一次一批（≤10 个）、失败即停；跨任务/跨会话/来路不明的文件一律保留并写入审计清单备注。
6. **资产库是唯一真源**：文件命名与 `asset-library.md` 的资产 ID 体系一致，禁止另起一套。

## 3. 命名规范（防混乱的第一道闸）

| 类型 | 格式 | 示例 |
|---|---|---|
| 角色资产 | `char_{资产ID}_{用途}_v{n}.png` | `char_LN_03_三视图_v2.png` |
| 场景资产 | `scene_{资产ID}_{机位}_v{n}.png` | `scene_OY_01_四机位_v1.png` |
| 道具资产 | `prop_{资产ID}_{用途}_v{n}.png` | `prop_JS_01_道具_v1.png` |
| 分镜/提示词 | `storyboard_S{集号}.md` / `prompts_S{集号}.md` | `prompts_S01.md` |
| 成片 | `E{集号}_{内容}_v{n}.mp4` | `E01_剪辑_v1.mp4` |
| **临时文件** | **一律带 `_draft/_retry/_preview` 后缀** | `E01_打斗_draft.mp4` |

> 资产 ID 与资产库 JSON 中的 ID 完全一致（asset-library.md 的 ID 体系）；临时后缀是清理时的识别标志，缺失后缀的临时文件按"未标注 = 不清"处理（安全优先）。

## 4. 保留清单（资产 · 清理时禁止触碰）

| 类别 | 内容 |
|---|---|
| 资产库 | asset-index.json、角色三件套、表情宫格、动作宫格、场景资产板、道具档案 |
| 参考资产 | 风格参考图、构图参考、动作源视频、角色参考图（跨集一致性靠它们） |
| 制作中台 | 分镜总表（唯一事实源）、提示词集——**长期保存只此两件为事实源**；六问判读、镜头卡十要素、七段式装配过程作为内部工作记忆，不重复落盘成套永久文件（用户要求追责或出现争议时才补录相关记录） |
| 声音 | 声音指纹卡、voice_id/mother_voice_id 映射、已冻结母音色片段、逐句声音表演参数表、配乐方案 |
| 交付物 | 成片、QC 报告、交付核对清单 |

## 5. 清理清单（临时 · 整剧交付时审计清理）

| 类别 | 例子 | 清理时机 |
|---|---|---|
| 中间生成 | `*_draft.*` 图/视频 | 对应镜头定稿后 |
| 失败重跑 | `*_retry.*` | 重拍成功并验收后 |
| 预览/试听 | `*_preview.*`、配音试听片段 | 成片定稿后 |
| 缓存 | 下载包、临时 JSON（uploads/ 除外，见第 3 节永久保护） | 交付后 |
| 旧版本 | `*_old*`、`*_v0.*` | 新版本验收后 |
| 模型中间产物 | 分割/放大/对齐的中间文件 | 任务完成后 |

## 6. 清理时机与责任人

| 时机 | 责任人 | 动作 |
|---|---|---|
| 批次进行中（含每集成片后） | — | **不动 `06_临时/`**（不删除、不询问、不出清单，避免打断创作节奏；每集成片后也不清，统一延后到整剧交付） |
| 整剧交付后 | 沈砚 | 确有候选时**一次**审计出清单、一次用户确认、一次清理 `06_临时/` → 打包 `07_交接/`（无候选不生成空报告不询问） |
| 跨会话恢复时 | 沈砚 | **只读** 02_资产 + 03_分镜——**临时区不作为事实源**；未完成的 execution 任务确有依赖时，可按需读取**本任务**临时文件（读取≠依赖，恢复后仍按整剧交付时机统一清理） |

**执行规则（v1.7.2 审计制）**：
- **第一步出清单**：扫描 `06_临时/`（**uploads/ 除外，永久保护不扫描**）——仅在确有清理候选且准备删除时才生成 `cleanup_audit.md`（候选文件路径+大小+删除理由+生成时间），present_files 展示，等用户确认；**无候选不生成空报告、不向用户询问**。
- **第二步才删除**：用户确认后，只删清单中**带 `_draft/_retry/_preview` 后缀**且属当前任务生成的文件；保留目录（01–05、07）与 `uploads/` 禁止删除；逐文件执行，失败即停。
- 用户明确说"先留着"的临时文件豁免，但要在文件名加 `_keep` 标注。
- 清理动作在项目文档里留一行记录（清理了什么、留了什么），防误删争议。

## 7. 与 asset-library.md 的关系

- `asset-library.md` 管**资产内容**（ID 体系、角色圣经、一致性锁、参考图链）——本文件管**资产文件本身**（目录、命名、存废）。
- 跨集/跨项目复用：`reuse_asset_ids` 指向 `02_资产/` 下的文件，**复用资产不重新生成、不复制到临时区**。
- 16 项资产锁、一致性五重锁的"锁"最终落在 `02_资产/` 的物理文件上——临时区永远不存在"资产副本"。

## 8. 创作侧衔接（drama-crew）

- 剧本层输入归档进 `01_剧本/` 并按模式验收：**标准交接**核定稿/账本/终审/合规四样及适用的世界观第五样，记 `review_state=reviewed`；**直通交接**核定稿与实际存在的账本/世界观，记 `review_state=unreviewed`，不因缺终审/合规报告拒收；用户裸本记 `review_state=not_provided`。触发口径以 crew 侧 `world-bible.md` 唯一口径为准，制作侧只验收使用，不重新推定是否应该存在。
- 创作侧临时产物（联网检索缓存、候选草稿、废稿）不进交接包，清理由 crew 侧**遵循宿主删除安全规则**处理（先审计列清单、经用户确认、走回收站机制、小批量执行），制作侧不代清不代管。
- **制作输出包**沿用已验收的既有产物：资产（02_资产/）/ 分镜总表 / 提示词集 / 声音文件 / 成片与 QC 报告——不新增交付物、不复制进交接目录，按 file-management 目录结构原地归档即视为交付。

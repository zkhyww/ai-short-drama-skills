# 创作经验库（跨项目自进化 · 顾临维护，改稿后按需加载）

> **解决的问题**：skill 本身是静态的，用户的改稿反馈（「太拖沓了」「名字太通用」「这个套路过时了」）过去只能靠手动改规则才能沉淀。本文件建立**「改稿 → 提取经验 → 升格为规则」**的闭环，让团队越用越贴合用户偏好。
> **借鉴来源**：drama-script-writing 的 S6 自我学习模块（改稿后自动对比初稿 vs 修改版）。去掉其「每步等确认」重交互部分，只留经验沉淀机制。

## 1. 触发时机（写死）

**用户对任何成员的产出做过修改/纠正后，顾临必须主动执行本流程**——不等用户喊、不依赖终审是否通过。

**持久化纪律（v6.8.7 定版）**：普通改稿只在**当前任务内部**提炼经验候选，不落盘、不额外追问；只有用户明确说「记住 / 写入经验库 / 以后这样」或对提炼条目明确认可时，才写入本文件持久化；**写入后不自动删除、不自动压缩清退**（超体量时向用户提示并等裁决）。

| 用户行为 | 处理 |
|---|---|
| 用户手动改了产出，或说「这里改成XX」 | 改稿完成后在任务内提炼经验候选（不落盘不追问） |
| 用户说「写入」/「记下来」/「记住」 | 经验条目写入本文件，持久保留 |
| 用户说「**以后就这样**」/「**以后不要XXX**」/「**改规则**」 | **快速升格通道**：直接改写 references 正式规则 |
| 用户没表态 | 候选只在任务内有效，随任务结束丢弃；不落盘、不暂存、不倒计时 |
| 文茵写批前六行自检触发补缺（联网搜词库/资料） | 补缺产物随账本增量交主理人，顾临审后按升格对照表沉淀进对应 references——运行时补缺是经验库的主动来源（v6.17.5） |

## 2. 提取流程

```
1. Read 本文件摘要（避免重复记录）
2. 索取/比对修改版：用户改过哪部分就收哪部分的最终版
3. 逐段对比：初稿 vs 修改版，标出差异
4. 提炼通用规律（不是个例）——「这次的第3集卡点弱」→「卡点必须带现实代价」
5. 用户已授权（说「记住/写入/记下来」或明确认可条目）→ **直接写入本文件，不再二次确认**；用户未授权 → 条目只在任务内有效，随任务结束丢弃
6. 超体量不打断创作，只在用户主动维护经验库时提示并等裁决
```

## 3. 经验条目格式

```
[YYYY-MM-DD] [维度]
- 观察：初稿与修改版之间发现了什么差异
- 规律：差异背后的通用规律（不是个例）
- 行动：下次写作/核查时应该怎么做
- 置信度：高(验证3次+) / 中(1-2次) / 低(仅1次)
```

## 4. 写入规则（5 条）

1. **只记通用规律**，不记具体案例（案例留在项目成稿里）
2. **只记 AI 常犯的错误与用户偏好**，不记显而易见的常识
3. **与现有规则重复的不记**（写前先 Read 对应 references 核对）
4. **与核心规则冲突的**标记「需讨论」，不直接写入
5. **写入以用户授权为前提**——用户明确说「记住/写入/记下来」或明确认可条目时直接写入不再二次确认；用户未授权的候选不落盘

## 5. 项目复盘仪式（项目交付后顾临必跑 · v6.17.6 增）

项目交付（或用户宣布项目告一段落）后，顾临执行收尾，把项目内沉淀的经验候选固化进仓库——**skill 的进化以项目为节拍**：

```
1. 汇总本项目全部经验条目：已持久化条目 + 补缺产物（词库/语料/资料）+ 终审红灯新模式
2. 逐条判定去向：升格进 references（按第 6 节对照表）/ 留 learnings / 丢弃
3. 跑合同测试确认全绿 → 升 patch 版本（SKILL.md version + CHANGELOG + README + 测试钉子）
4. 提交推送，commit message 列明本项目升格了什么——git 历史即 skill 成长史
```

**单人 vs 团队分流**：
- **单人模式（判定法：`git log --format="%ae" | sort -u` 只有一个作者邮箱，或用户明示"就我一个人用"）**：复盘产物直接提交 main——一个项目 = 一个版本 = 一个进化 commit，无需 PR 仪式。
- **团队模式（仓库出现第二个作者，或用户明示"团队使用"）**：同一复盘产物改走 PR——条目必须带证据（哪个项目/用户什么反馈/置信度），CI（`.github/workflows/contract-tests.yml`）自动跑合同测试，红了机器先拦，人只审「这条经验值不值得进规则库」。默认合并策略 squash，保持 git 历史一项目一节点。

## 6. 升格目标对照表（快速通道用）

| 经验维度 | 升格到哪个文件 |
|---|---|
| 节奏/卡点/情绪/冲突写法 | `references/writing-craft.md` |
| 选题判断/赛道风向 | `references/topic-selection.md` |
| 命名偏好 | `references/naming-rules.md` |
| 分镜/提示词/视觉一致性 | drama-studio 的 `references/storyboard-craft.md`（v5.0.0 起迁出） |
| 评审尺度/评分松紧 | `references/review-scorecard.md` |
| 付费墙/钩子/商业化 | `references/commercial-craft.md` |
| 题材细分赛道资料 | `references/topic-research.md` |
| 战斗动作/情绪语汇/场景质感词库 | `references/genre-and-fight-rules.md`（战戏类）或对应题材规范行（v6.17.5 增） |
| 地域语言/方言俚语/年代语/行话语料 | `references/dialogue-craft.md` 语言资产库（v6.17.6 增） |
| 账本/状态管控 | `references/canon-ledger.md` |

## 6. 体量维护

- **触发**：本文件超过 5KB 或条目超过 30 条
- **动作**：**先向用户提示并等裁决**，不自动删除任何条目；用户同意后高置信度经验可「毕业」升格进 references 正式规则（升格不等于删除原条目，是否清理由用户定）；压缩后在变更记录留痕（日期/处理了几条/保留哪些/原因）

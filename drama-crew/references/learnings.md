# 创作经验库（跨项目自进化 · 顾临维护，改稿后按需加载）

> **解决的问题**：skill 本身是静态的，用户改稿反馈、用户要求借鉴的外部成功/失败案例，以及定向补项取得的新材料，过去只能靠手动改规则才能沉淀。本文件建立**「反馈或案例 → 入库候选 → 项目适配 → 相称核验 → 授权升格」**的闭环，同时不把案例声量、公开可读或作者说法冒充已验证规则与再发布许可。
> **借鉴来源**：drama-script-writing 的 S6 自我学习模块（改稿后自动对比初稿 vs 修改版）。去掉其「每步等确认」重交互部分，只留经验沉淀机制。

## 1. 触发时机（写死）

**用户对任何成员的产出做过修改/纠正、明确要求吸收外部案例，或一次定向补项取得了会改变后续判断的新材料后，顾临必须主动执行候选评估**——不等用户重复提醒、不依赖终审是否通过；普通问答不触发，不把随口讨论自动沉淀。

**持久化纪律（v6.8.7 定版）**：普通改稿只在**当前任务内部**提炼经验候选，不落盘、不额外追问；只有用户明确说「记住 / 写入经验库 / 以后这样」或对提炼条目明确认可时，才按 §4 的项目隔离规则持久化；**写入后不自动删除、不自动压缩清退**（超体量时向用户提示并等裁决）。

| 用户行为 | 处理 |
|---|---|
| 用户手动改了产出，或说「这里改成XX」 | 改稿完成后在任务内提炼经验候选（不落盘不追问） |
| 用户说「写入」/「记下来」/「记住」 | 按 §4 区分项目记录与通用条目后持久保留 |
| 用户说「**以后就这样**」/「**以后不要XXX**」/「**改规则**」 | **快速升格通道**：直接改写 references 正式规则 |
| 用户要求借鉴，或定向补项取得外部材料 | 先查 Studio 单点共享 metadata；重复来源补全既有 ID、来源与未核状态，新来源才建稳定 ID。材料先是入库候选，项目适配与相称核验后仍须取得持久化/升格授权；公开可读不等于可再发布全文 |
| 用户没表态 | 候选只在任务内有效，随任务结束丢弃；不落盘、不暂存、不倒计时 |
| 文茵六行自检触发定向补项 | **运行时补缺是经验库的主动来源**，但产物只随账本增量交主理人并标候选；顾临做项目适配与相称核验，获授权后才按对照表升格，不因一次搜索直接写正式 references 或 push |

## 2. 提取流程

```
1. Read 本文件摘要（避免重复记录）
2. 先按用户最新决定核反馈状态：最终采用 / 已撤回或被替换 / 待定；只从最终采用且有修订证据的结果提炼正式候选，早版解释不能覆盖晚版。采用证明文本选择，不证明方法普适或成片效果。项目特有名称、剧情、词表与固定数量留在项目；通用验证改用新编中性情境。再定位主责原段与薄弱点，先判根因是方法缺失、已有规则漏执行、规则冲突、输入/版本漂移，还是工具/证据限制；只有方法缺失才补创作规则，漏执行补原派单或验收入口，冲突统一主责，漂移修真源/状态，能力不足保留未验证结论，不把这些都改写成新的审美禁令；反馈型只索取/比对用户改过部分的最终版，案例型先查 Studio 共享 metadata 并优先消费用户已给资料/样本
3. 重复来源按既有稳定 ID 补空值，新案例才新增 ID；正常新增/同 ID 补缺统一走 `case_library.py add`，不得改历史 `snapshot.original_case_count`，只有经批准的非空事实更正才手改 canonical metadata 并复核 diff、`validate`、`build`。每条取得原文独立保存为纯原文 TXT，不加我方标题、出处、许可、分析或猜补尾文；来源、授权、取得状态进对应 metadata，字段不足时进同 ID 本地来源旁档。我方归纳另存并标明，成果只以 ID 与 locator 回指唯一原文，不造第二份混合真源；回复、媒体与复现记录仍留本地，采集/观看/复现状态不能互相代替，公开 Skill 只保留 metadata 与原创中性简述
4. 区分「已见事实 / 作者声称 / 我方推断」，记录模型输入与后期条件、资料缺项、适用 / 不适用范围；资料截断属于采集缺项，不能据此改写作者提示词或推断精简能优化效果
5. 候选写成「在何种条件下解决什么问题、依靠什么机制、怎样核验」，不从案例抽取动作、镜数、尺度等数量配额；无复现不宣称可复现
6. 用户已授权（说「记住/写入/记下来」或明确认可条目）→ **按 §4 直接写入项目记录或本文件，不再二次确认**；用户未授权 → 条目只在任务内有效，随任务结束丢弃
7. 超体量不打断创作，只在用户主动维护经验库时提示并等裁决
```

## 3. 经验条目格式

```
[YYYY-MM-DD] [维度]
- 来源与授权：来源 URL / 作者或发布者 / 版本日期 / 授权状态；案例资料区同时定位已取得原文、关键回复、关联参考媒体、未取得范围及采集/观看/复现状态；用户反馈型的具体项目与反馈定位只写项目记录，通用条目保留不含剧情的归纳依据
- 观察：区分 已见事实 / 作者声称 / 我方推断；不把热度、点赞或转发写成效果证明
- 规律：在何种条件下解决什么问题、依靠什么机制、怎样核验
- 适用范围：题材、节点、载体、目标模型，以及输入与后期条件、资料缺项和适用 / 不适用范围
- 例外：哪些条件下不适用，现有硬边界是否仍须保留
- 行动：可选机制、实际验证与迁移去向；未验证时写待验证，不直接下发生产
- 置信度：高 / 中 / 低；按证据具体性、适用边界与复现状态判断
```

## 4. 写入规则（8 条）

1. **不把一次经验普遍化**：具体案例的可取得原文、关键回复、关联参考媒体与各证据状态留在项目或用户案例资料区，不只存 URL；候选须写条件、问题、机制、核验、适用范围、例外与证据，不足时维持低置信。测试剧的人物、剧情、专用词表、固定集数与所选画面风格只留项目，不写进本库或正式 Skill；仅换人名仍属于剧情迁入。通用层保留判断方法、触发条件、例外与验证办法，授权记录不等于授权把项目内容升格成通用规则
2. **只记会改变后续判断或产出的经验**：包括 AI 常犯错误、用户偏好和用户授权吸收的外部案例机制，不记显而易见的常识
3. **与现有规则重复的不记**（写前先 Read 对应 references 核对）：修订优先覆盖主责原段并核实际派单、验收和下游消费是否可达，清理被取代的冲突口径；已覆盖却漏执行时修执行入口或回归核验，不另建平行清单。防改回去依靠原问题不再复现、原有合法情形仍可通过，不依靠每次保留同一句台词
4. **与核心规则冲突的**标记「需讨论」，不直接写入正式规则或下发
5. **写入以用户授权为前提**——用户明确说「记住/写入/记下来」或明确认可条目时按项目隔离规则直接写入不再二次确认；用户未授权的候选不落盘
6. **不因纠正一个过度硬约束就禁止所有硬约束**——事实锁、知情边界、世界规则、授权、合规与格式契约等必要硬边界按各自主责文件保留
7. **升格看具体证据与适用边界**——不依点赞量或重发次数计高置信；采集、完整观看与生成复现是不同证据，按风险用相称的文字、接口或生成验证；允许只适用于特定模型和后期条件的打斗、巨物、玄幻方法，不强求普适。无复现不宣称可复现，但不强制付费试制，也不阻塞项目其他已获授权工序。改判断方法时，用新编且跨情境的中性材料同时核应触发与不应触发的情况，明确预期行为、实际判断与剩余缺口；回归材料放维护测试区，不随 Skill 加载。区分静态格式检查、文本情境演练、独立行为测试、读演/粗剪与实际成片证据，缺哪层就保留哪层未验证；不得凭通过合同测试或用户采用承诺留存提升
8. **写入、复盘、升格共用同一授权边界**——只认可方法价值不等于允许发布原始案例；低置信或待讨论条目不得自动作为生产或终审规则下发，保留用户已授权条目，不自动删除

## 5. 项目复盘仪式（项目交付后顾临必跑 · v6.17.6 增）

项目交付（或用户宣布项目告一段落）后，顾临执行收尾，把项目内沉淀的经验候选固化进仓库——**skill 的进化以项目为节拍**：

```
1. 汇总本项目已获用户授权的经验条目：已持久化条目 + 已完成项目适配与相称核验的补缺候选 + 终审红灯新模式 + 外部案例方法候选
2. 逐条按来源、条件、证据、验证状态和授权判定去向：升格进 references（按第 6 节对照表）/ 留 learnings / 丢弃；低置信或待讨论不自动注入生产或终审
3. 确有获准的通用规则/执行指引变更时，按影响运行合同检查和中性情境回归，复核原有例外 → 升 patch 版本并同步 SKILL.md version、CHANGELOG、README；只有项目修订、候选评估或已有规则复用时，不为复盘制造补丁版本
4. 纳入正常版本发布流程并记录变更；单次补搜、入库候选或 metadata 补缺本身不自动 push
```

**发布授权与检查（不由账号身份自动决定）**：
- 是否提交、建 PR、合并或推送，服从当前任务的明确授权、目标分支保护与项目发布流程；仓库所有者身份、本机账号或项目复盘完成都不自动授予直推 `main` 权限。
- 获得发布授权后，条目仍须带来源、项目反馈、置信度与适用边界，运行相称测试并检查工作树、目标分支、CI（`.github/workflows/contract-tests.yml`）、敏感信息与本次允许范围；失败时保持未发布并修复或上报，不用重推掩盖红灯。
- 协作方式按仓库当前规则选择 PR、squash 或其他已批准路径；经验库只记录创作方法，不越权覆盖 Git 与发布门禁。

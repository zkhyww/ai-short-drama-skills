# 单一标准剧本与按需格式导出（submission-format）

> 主责：顾临整合与交付，文茵负责内容修订。默认只有一份活动标准剧本正文，阅读与 drama-studio 制作共用；必要环境、站位、动作、表情、眼神、声音与反应自然融入剧本。设定、集纲、正典、版本及验收记录分别存放在已有配套位置，不嵌入正文，不再强制内部制作版与纯净版双稿。

## 1. 何时生成

- **4A 标准正文交付**：沿用已有确认的正文路径；新项目可用 `{项目名}_剧本.md`。不因历史文件名含“纯净版”而另造母稿。按本次范围交付，不为局部修改重新生成全项目。
- **4B 按需格式导出**：仅接收方或用户明确要求 DOCX/PDF、专用模板或附件包时执行。普通阅读、投稿和制作不触发第二份 Markdown；专用模板优先。格式与创作方法分别裁决：用户选定的格式覆盖团队默认排版；同批提供的课程、注意事项及示例仅作参考，不连带替换已有创作体系、题材约定、字数目标或审核节奏。借鉴只补实际缺口，冲突时遵循用户已确认口径。
- 分批工作只维护当前明确覆盖范围，合入后以唯一活动正文为准；其他版本标明候选或历史，不并列续写。

## 2. 唯一真源与版本链

1. 在已有状态/交接记录中登记活动正文路径、`project_id`、`script_rev`、SHA-256、实际已审范围与 `review_state`、目标时长和用途；内部字段不写入纯净正文。
2. 直接修改唯一活动正文，内容变化提升修订号；同时核对受影响梗概、人物档、集纲、连续性、后续接口与可选导出，逐项标已同步或待重编。文件同名或新时间戳不能代替内容一致。
3. 制作已开始时，将修改定位与新版本交 Studio，只使受影响资产、分镜、提示词、音轨、时长与 QC 结论待复核，未受影响部分沿用。
4. **历史双稿迁移**：先备份并确认当前有效正文；把旧母稿独有设定、人物、集纲等归入配套资料并核对完整性。旧母稿保留为历史备份或指针，更新入口、索引和实际读写工具，禁止旧同步器反向覆盖。只读诊断不自动迁移文件。
5. 原始来源、活动稿与未重编旧资料保持可辨和可达；不得仅因版本旧删除原始资料。导出内容有误时回唯一正文修订，不让导出稿成为第二真源。

## 3. 正文与配套资料的内容边界

| 内容 | 放置位置 |
|---|---|
| 集场标题、出场人物、自然环境、相对站位、动作过程、道具状态、对白与必要表演/声音 | 唯一标准正文；用可看见、听见、表演的编剧语言，不写字段清单 |
| 卖点、梗概、完整人物小传、基础视觉事实、世界规则、粗纲、逐集集纲 | 已有设定/人物/规划资料；按实际范围核完整性，不能因拆离正文漏交 |
| 故事日、伤势、知情/观众披露、道具与伏笔追踪 | 既有正典或适用的配套记录；当前场承重事实仍须自然写在正文 |
| 动作节拍索引、时长预算 | 确有核对/交接需要时在既有工作记录引用正文；不每场附段，不重复描述 |
| 版本、哈希、审核、返修、自检、估时证据 | 既有状态/验收记录；不污染正文 |
| 景别、机位、镜头切点、生成提示词与参数 | 完整镜头方案归 Studio；已选模板允许或要求的必要景别可在正文以【】标注关键故事信息；默认不加粗，专用格式另有明确要求时从其约定，不扩成逐镜制作表 |

**保真底线**：整理不是删戏。事件、证据、人物/观众知情边界、关系、选择、行动路径、状态结果、因果及悬念不得因去标签丢失；内容问题交内容修订流程。不得虚构审批编号、版权主体、联系人或平台受理状态。

## 4. 默认交付结构

正文直接使用每集标题、场次、人物、自然动作与对白，按 §4a 已选格式排版。从场首一至两句建立空间与当下状态，后续随行动表达变化。每集尾与下一集首成对核对，切在承重的未决行动、选择、揭示或回应上并有效续接；完结集可收束，不为钩子无因撤销已兑现的安全与回报。

完整项目的配套集纲应非空并覆盖实际全稿，已有核心人物和设定不能因正文纯净而丢失；局部任务只核其影响范围。接收方明确索要封面、卖点、梗概、人物及集纲时按需打包，内部审核与制作字段仍不进入剧本正文。

### §4a 标准剧本排版（仅场景头加粗）

**默认采用用户确认的简洁格式**：仅场景头加粗；集标题、人物名单、动作内人名、说话人、语气、OS/VO、景别和闪回标记均用普通文字，不使用 Markdown 标题语法让集标题被渲染成粗体。用户后续明确指定其他格式时按该次要求覆盖，并记入已有项目记录；旧稿或外部模板不得自动恢复人物名加粗。格式服务内容，阅读与制作共用唯一正文。

| 要素 | 格式 |
|---|---|
| 集标题 | `第1集：`，不加粗 |
| 场景头 | `**1-1 日 内 具体地点**`；集-场号、时间、内外、地点完整，只有本行加粗 |
| 人物行 | `人物：姓名（首次出场身份）、姓名`，不加粗；身份取自既有设定，不自动成为画面字幕，不泄露秘密 |
| 动作与神态 | `△姓名……`，自然短段；叙述使用已锁定称名或无歧义代词，不为省字擅缩成单字 |
| 台词 | `姓名（语气）：台词`；按 dialogue-craft §9.3 逐句检查并补足有依据的语气提示，不加粗 |
| 心理独白 | `姓名OS（语气）：内心语言`，无必要提示时可省括注；OS 为内心发声，场内其他人听不见 |
| 画外人声 | `姓名VO（语气）：台词`，无必要提示时可省括注；只闻其声不见发声者，环境音不一律归 VO |
| 景别（必要时） | `【特写】` 等，不加粗，不为每段指定完整镜头方案 |
| 回忆 | `【闪回】` 至 `【闪出】`，不加粗；内部时空准确，想象不能冒充真实回忆 |
| 字幕/转场（按需） | 只保留已确认的可读信息或叙事需要；不机械逐场添加，不加粗 |

**排版与保真检查**：
- 保留完整动作与自然对白，段落之间可适度留白；不通过碎行伪造节奏，不混入五字段清单、审核或预算。
- 每场前一至两句自然交代环境、关键人物相对站位及承重道具初态；后续随行动变化，不罗列库存。重要可见动作另写 △ 行，不塞进语气括号。
- 逐句核说话对象、意图、当下压力与发声方式；需要提示的写短而可执行的语气，不让整段承重对白都靠读者猜。表达已明确的普通应答可以省略括注；不为比例堆“冷冷地/愤怒地”，用户明确覆盖目标则只在该项目记录并执行。
- 场号按实际时空划分连续编号；分场后核前后场、上下集入口与引用，不为格式改结果。首次身份、OS/VO含义与披露边界不因换排版改变。
- 格式符号不计正文字符；语气括注、OS实际语言等按既定项目口径计入相应统计。正文、净发声与总阅读字符不可混用。
- 外部模板中的“选送10集”只约束明确要求的送审选集，不缩减全剧正文。

**中性格式示例（仅演示行制，不是新故事模板）**：

```text
第1集：
**1-1 日 内 值班室**
人物：许宁（值班员）、周齐（同事）
△许宁站在窗边，周齐停在门口，手里的文件尚未放下。
许宁（放轻声音）：先坐下，把话说清楚。
△周齐拉开椅子，坐下前又看了一眼门口。
周齐（迟疑）：我怕说了，你不信。
```

## 5. 可选 DOCX 排版（明确要求时生成）

仅在用户或接收方明确要求时，从已核对的唯一标准正文导出 DOCX/PDF 或专用模板。正文内容继续只在活动 Markdown 修改，导出文件不成为第二真源。按接收要求另附策划资料，不强制生成另一份 Markdown 剧本。以下通用设置以耐读、便于批注为目标：

| 项目 | 通用默认 |
|---|---|
| 纸张 | A4 纵向 |
| 页边距 | 上下左右约 2.5 cm |
| 正文字体 | 中文宋体或等效易读字体，12 pt；英文/数字使用兼容字体 |
| 剧名 | 居中、加粗，20–22 pt |
| 集标题 | 常规字重，字号可区分层级，不加粗 |
| 场景头/人物行 | 仅场景头加粗；人物行常规字重（§4a 格式） |
| 动作与台词 | 12 pt，`△` 保留；人名、语气及台词均为常规字重 |
| 行距 | 1.35–1.5 倍；场次行前保留适度段前距 |
| 页码 | 页脚居中；封面可不显示页码 |
| 分页 | 每集前插入分页符，不用连续空行顶到下一页 |

不要为了「像正式稿」虚构版权声明、机构抬头、审批章、编号或项目联系人。没有专用模板时，也不声称上述通用样式必然满足某个平台的收稿要求。

## 6. 交付前核对

- 唯一正文路径、修订、哈希与实际审核状态已在既有记录对应；场号、角色、剧情状态和配套资料按当前范围核对。
- 正文符合 §4a 中实际选定的格式，保留承重动作、表演与反应；无五字段清单、场末节拍附段、审核/预算/生成参数混入。
- 当前随包检查器支持 §4a 的普通集标题、仅场景头加粗、人物行、△动作及OS/VO，并兼容历史稿。先核运行的是本包版本；外部旧检查器或接收方特殊格式未适配时，按 §4a 核真实文本并明示自动覆盖缺口，不为过检另造机器稿。使用单文件接口：`python <已安装drama-crew绝对路径>/scripts/audit_screenplay.py --submission "<唯一标准正文路径>" --submission-scope body-only --expected-episodes <实际集数> --json`。参数名 submission 是历史接口名称，不要求另造投稿稿；不同时传 --master。确定性错误修复后才交付，警告按真实语义核对。
- body-only 检查不验证外置集纲、完整人物档、行动保真或审美：必须另按本次范围阅读实际配套资料和前后承接；不能拿退出码 0 代替终审或宣称成片验证。
- `--master` 与成对预检只保留给明确要求核历史双稿的任务，不是默认流程。专用模板解析不支持时，区分解析限制与内容错误，按接收模板核验保真。
- 发声秒数仅是净发声字符估算；默认轻量文本自检，不逐集真人试演、录音或制作额外时长表。仅明确要求、硬时长冲突或具体风险未解时对命中片段补证；同步片段只计一次，互斥行动和表演反应保留实际时间。
- 生成 DOCX/PDF 时做实际可视排版检查；无法渲染则明确未完成视觉 QA。内容修订回唯一正文，展示调整不建立第二正文。

## 7. 产物必要性判定表（实际内容与工序决定，按需拆并）

> 解决「哪些产物必须有、哪些可以并入、哪些可以免」的自由裁量不可比问题。**先判入口与承重风险、再判档位**：快写/单集预览只新产本次命中内容；尚无全季人物规划时，不为一句话试写反向强造全季阵容。若上游已有世界观、正典、人物或制作资产，必须继承本次命中片段，不因预览、短体量或角色名分降档、免核或清空；用户明确只要求展开指定人物档案时按该范围交付，不扩写其余档案，也不把未展开者降格或删除。已有稿改写、续写、诊断只产命中范围，不补跑市场与选题。直通跳过独立终审，涉 IP/敏感题材的合规例外仍按主流程执行。以下表格适用于完整创作项目；世界观、正典与制作资产是否启用以其承重风险和既有资产为准，档位只决定命中产物的拆并。**文件数不等于完成度**：先问这份资料支持哪项已确认创作/制作判断、是否有唯一内容、后续谁读取、现有文件能否承载；无实际用途不生成。人物/世界/集纲/正典可以在已有设定集内分区，按稳定章节引用并保持职责与当前修订清晰；内容完整不等于必须拆成独立文件。与当前批次无关的已确认后季设定按需加载，不删除。只记录实际发生的审核，重复通过声明不另起报告。

**判定先于产出**：主理人在第 0 步确认行落定已知条件后，按本表判定产物清单，随第 3 步起执行并在交接单头部记录命中、并入、可免与继承项。

| 产物 | 必产条件（不满足则可免/并入） | 依据 |
|---|---|---|
| 市场简报 / 选题候选主题卡 | 从零策划完整项目时必产；快写/已有稿直达不补造 | 主流程入口路由 |
| 候选结构查重 | 默认并入候选主题卡「查重结论」行；仅补充检索时拆独立 `02A` 文件 | SKILL.md 第 2.5 步留痕口径 |
| 世界观档案 | 按 world-bible.md 头部唯一口径：世界事实承重时建完整或轻量版；实际低风险且无既有资产时可免新建；已有档案/规则在任何入口均继承命中片段 | world-bible.md（唯一口径） |
| 人物档案/圣经 | 按任务与既定人物范围保留实际档案；可并入已有设定集，规模大或独立维护时再拆，不按集数强拆；只做局部改稿不强造全季人物 | character-bible.md |
| 梗概与粗纲 | 完整项目保留；可与人物/规则合入已有策划或设定文件，规模和读取需求确需时再拆；不按固定集数强制两文件 | 交付文件数服从真实用途 |
| 逐集集纲 | 完整项目必产；已有稿按本次范围核对；快写预览不补全季集纲 | 创作承重结构 |
| 分批正文 | 实际分批写作时保留候选与合入状态，不逐轮复制全稿；批粒度按 canon-ledger §5（10-20 集/批自适应；短篇可单文件） | canon-ledger.md |
| 正典账本 | 多集续写、多人多线、跨时段、复杂知情/道具/伏笔、跨会话或高密度状态变化等连续性风险命中时启用；低风险且无既有账本时可并入交付记录，已有账本始终继承 | canon-ledger.md 头部 |
| 账本增量独立文件 | 在工作区按批次保留待合并原文，合并后转历史引用，不在项目根不断铺开；已启用账本的续写批独立产出 `{项目名}_增量_E{起}-E{止}.md`；低风险且未启用账本时可并入交付记录，不因集数决定 | canon-ledger.md §2 |
| 连续性核查报告 | 质检批/用户要求/跨会话恢复时按节奏产出；全稿终审模式中途不产 | 质检节奏表 |
| 合规 / 终审记录 | 标准模式保留独立审核职责及真实依据，可用已有验收文件不同章节，也可沿用独立报告；结论、来源、修订和范围均须可定位，直通不伪造 | 第 3.8/3.9 步 |
| 时长检查与证据 | 默认并入既有自检，区分正文容量、净发声估算和实际测量；仅明确要求、硬时长冲突或局部风险未解时补命中片段的读演/试剪证据，不按载体强制逐集秒数表，不用固定动作点折算 | commercial-craft §5 |
| 标准制作交接单 | 进制作链时记录唯一正文路径、版本、哈希、实际已审范围及必要配套资料；不进制作时沿用已有交付记录 | 第 4A 步 |
| 唯一标准剧本正文 | 所有正文交付只维护一个活动真源，沿用项目已确认路径；完整项目核配套资料，局部任务只核影响范围 | 本文件 §1 |
| 按需格式导出 | 用户或接收方明确要求 DOCX/PDF、专用模板或打包时生成；一般阅读、投稿与制作直接共用标准正文 | 本文件 §1/§6 |

**档位速查**：全量档、标准档与轻量档只决定已经命中的产物怎样拆并，不按集数、载体、题材、预览入口或主配角名分新增/免除承重核查。世界观按其风险口径；已启用账本的续写批增量独立落盘；低风险且未启用的记录可并入交付。直通稿不补造终审，已有稿不补造选题；尚无全季人物规划的快写不强补全季阵容与完整档案，已有规划/档案仍继承并按本次任务核对，用户明确只展开指定档案时不扩张交付范围。**轻量≠缺核心产物**：当前范围真实内容、版本和实际启用的核查不省，不以档位表强开未命中流程。

## 8. 剧本工作文件与安全整理

- 项目入口只指当前正文、必要配套、实际审核范围及下一动作。文件名含“最终/旧版/汇总”不决定权威性；版本由已确认路径、修订与实际内容决定。
- 新内容优先原位更新，设定集只补实际约束人物选择、事件、世界规则、识别与连续性的内容；没有承重作用的补充不主动扩写。对未来季有已确认作用的事实保留，按需加载，不把“当前没用到”等同废稿。
- 角色回传、未合并增量和完整修订候选在现有工作区隔离保存；通过后合入唯一正文/配套，记录目标修订，候选转工作历史，不作为第二活动真源。重要已确认稿、原始资料和审核证据保留，不每次小改复制一份全剧备份。
- 报告只记录本次实际检查的独有证据、定位、版本与结论；同一问题的后续复核在原记录补状态，历史结论标其原修订，不能被无痕覆盖或用于新版本。合规、连续性、质量分区可共一文件，独立审核职责不变。
- 当前项目资料归并需先核独有信息完整保留、更新实际引用及读写工具；只读审计不自动改项目布局。来源压缩包、用户原稿、正式报告、候选、备份及其他任务产物默认保护；未决和未合并文件不能清理。
- 批次/阶段结束可在本项目根审计临时缓存，不必等整剧结束；默认不删。只有明确本任务生成、用途完成、可再生、无引用、非证据/来源且授权覆盖的文件才逐个处理；不凭后缀或“与剧本正文无关”判废。遵守宿主禁止递归/通配符/批量删除规则，多项须逐项确认或用户手动处理；已有明确单项授权不重复问。无候选不另出报告。制作资产存废遵循 Studio file-management，不跨任务代清。

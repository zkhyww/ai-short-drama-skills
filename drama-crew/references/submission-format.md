# 双轨成稿与投稿排版（submission-format）

> 主责：顾临负责从已锁版内容机械派生；内部制作母稿与标准投稿阅读稿始终先以 Markdown 落盘。命中投稿、送制片人或对外阅读意图时，必须从锁版母稿生成标准投稿 Markdown；DOCX 仅在用户或接收方明确要求时生成。文茵不在排版阶段改内容，季衡不重复终审。
> 核心边界：`{项目名}_完整制作母稿.md` 是**唯一内容真源**，`《剧名》_标准投稿阅读稿.md` 是**派生阅读视图**；二者必须是**两个不同文件**，不得用同一文件改名、复制内部字段或并列续写。排版不是再创作，也不是审批、备案或发行资格确认。

## 1. 何时生成

- **4A 始终生成**：完整项目终稿或直通稿进入交付时，先生成 `{项目名}_完整制作母稿.md`。
- **4B 按意图触发**：用户表达投稿、送制片人/平台编辑、对外阅读、需要 Word/DOCX，或明确要「制作版 + 投稿版」时，先生成 `《剧名》_标准投稿阅读稿.md`；由已有语义直接路由，不新增用户弹窗。
- **分批不反复导出**：正文尚未锁版时只维护活动正文与账本；除非用户明确要阶段阅读稿，否则不为每批生成早版投稿稿或 DOCX。
- **专用模板优先**：接收方提供模板、字体、页边距或字段清单时，按其模板派生；通用模板只在没有专用要求时使用。
- **载体路由不新增弹窗**：标准投稿 Markdown 是 4B 的必需交付，不因 DOCX 工具状态改变。**DOCX 仅在用户或接收方明确要求时生成**，并且只能从已通过预检的标准投稿 Markdown 派生；PDF 只在用户或接收方明确要求时生成。

## 2. 唯一真源与版本链

1. 母稿头部记录：`project_id`、`script_rev`、`review_state`、目标成片时长、主画幅与用途。
2. 派生前对母稿正文计算 SHA-256，在母稿交付记录登记 `source_script_rev` 与 `source_sha256`；明确要求 DOCX 且工具支持自定义属性时，再把二者写入 DOCX 属性。投稿正文不得因溯源而混入内部字段。
3. **母稿内部同步**：正文发生内容修改时，在同一 `script_rev` 内同步受影响的故事梗概、人物档案、粗纲、逐集集纲与正文；导出前核对关键事件、人物状态、集数与结尾卡点，任何一处仍指向旧剧情都不得导出。同步是同一母稿内部的一致性维护，不另造内容真源。
4. 投稿稿只改展示，不改字义。收到「顺便把这句也改了」的反馈时，**先回完整制作母稿修改**，`script_rev +1`，同步母稿内受影响段落，重跑受影响的青梧局部复核、素弦/季衡门禁，再重新生成标准投稿阅读稿并预检。
5. `drama-studio` 只消费母稿；不得把标准投稿 Markdown 或可选 DOCX 反向当作剧本输入，不得让两个不同文件各自继续修改。

## 3. 两种视图的字段映射

| 内容 | 完整制作母稿 | 标准投稿阅读稿 |
|---|---|---|
| 剧名、一句话卖点、梗概、主要人物 | 保留 | 保留 |
| 粗纲与集纲（v6.17.0 增） | 粗纲、逐集集纲（含卡点标注）随批次整合进母稿 | 保留：粗纲（剧情阶段概览）与集纲逐集收录，与成稿阅读体例一致 |
| 人物小传档（v6.17.0 增） | 主角十二件套/配角五件套小传以「人物档案」节并入母稿正文前部 | 投稿版只保留阅读性人物表（姓名+身份+核心欲望+矛盾），完整小传档不出 |
| 人物视觉锚定（v6.17.0 增，v6.17.1 划界） | 主要角色各附一行**基础视觉事实**（年龄段+性别+已有外貌记忆点+常服+剧情必需标识，措辞与人物小传/外观状态行一致）；它只锁定创作侧不可擅改的事实，不承担完整出图参数 | 删除（制作专用）；制作侧逐字继承基础视觉事实，再补生产级结构轴、差异化禁项与 anchor，补充项标「制作设计/推断」，不得覆盖 crew 事实 |
| 集号、场号、内/外、地点、日/夜、出场人物 | 保留原字段 | 合并成易读场次行 |
| 场景五字段 | 保留，供制作读取 | 去掉字段标签，把必要环境与人物状态化成自然动作说明 |
| 动作、必要表情、可见道具 | 保留 | 保留，去掉纯机器指令口吻 |
| 对白、必要的承重台词表演提示 | 保留 | 保留；提示简洁置于人物名后或台词前 |
| 动作节拍、镜头建议、情绪强度数字、时长预算 | 保留 | 删除制作专用标签；若动作本身影响剧情，只保留自然动作正文 |
| `romance_axis`、质检节奏、review_state、账本增量、source_locator | 保留在母稿/交接头 | 正文删除 |
| 返修表、红线、评分、AI 痕迹、合规工作底稿 | 独立报告保留，不混进正文 | 删除 |
| 提示词、模型名、生成参数、AI 出图/配音指令 | 制作需要时保留在相应内部位置 | 删除 |
| 许可证号、批准文件编号、节目编号、审批结果 | 只有收到正式上游输入才可原样附入 | **不得生成、推断或预填**；收到正式字段且接收模板要求时才原样加入 |

**转换底线**：去标签不等于删戏。任何会改变事件、证据、知情边界、关系、人物选择、因果或季终悬念的删除，都不是排版，必须退回内容流程。

## 4. 通用投稿阅读稿结构

没有接收方专用模板时，按以下阅读顺序：

1. 封面：剧名；可选副标题；作者/团队、联系方式、日期仅在用户实际提供时填写，未知字段省略，不写占位符。
2. 一句话卖点：一句话交代主角、核心困境与独特看点。
3. 故事梗概：完整说明故事发动机、主要冲突、发展与结局承诺，不搬运内部分析过程。
4. 主要人物：姓名 + 年龄段/身份 + 核心欲望 + 与主线直接相关的矛盾，控制为阅读性介绍，不搬运完整内部人物账本。
5. 粗纲：剧情阶段分段概览，含覆盖集数区间、核心任务、冲突升级与段末转折。
6. 逐集集纲：**逐集集纲非空且覆盖到最后一集**，每条含核心事件与结尾卡点；标题存在但内容为空同样不得交付。
7. 正文：每集标题、场次行、动作与对白，按 **§4a 标准剧本排版**执行。

> 选题分析结论只作可选策划附件，不默认并入投稿剧本正文；只有用户或接收方明确索要策划判断时才另附。接收方只要正文时可在交付行里说明省略了前置段，否则默认按上述完整体例输出。

### §4a 标准剧本排版（v6.16.0 增 · 无指定模板时的团队通用投稿阅读格式）

正文部分采用本团队的**通用投稿阅读排版基准**：4B 产出时把母稿正文机械转换为本格式；它不宣称代表所有机构的行业标准，**接收方模板优先**。无指定模板时，声音标记采用火山引擎「剧创」[《标准剧本格式参考》](https://www.volcengine.com/docs/87744/2277069)（2026-03-24 更新）的国内微短剧口径：`OS = 角色内心独白`，`VO = 画外音（只有声音，角色不出现在当前画面中）`。这是一套平台解析约定，不外推为英文影视剧本中 `O.S.` / `V.O.` 的通用定义；全稿只使用接收方选定的一套含义。

**格式要素（适用项缺失即排版返修）**：

| 要素 | 格式 | 示例 |
|---|---|---|
| 集标题 | `# 第 X 集`（只写集号） | `# 第 1 集` |
| 场次行 | `**场{集}-{场} {日/夜} {内/外} {地点}**` 加粗 | `**场1-1 夜 内 盛氏集团顶层宴会厅**` |
| 人物行 | `**人物：{名} {名} {名}**` 加粗，**空格分隔**，不用顿号/逗号 | `**人物：苏晚 苏曼 众高管**` |
| 字幕行（按需） | 接收方模板或制作需要启用；新人物首次出场且**身份不能从当下画面或对白快速读明**时，紧随首次出场位置写 `【字幕】{身份}，{名}`。身份已自然读明或接收方不要求时可省略，重复出场不再标 | `【字幕】禁军统领，霍擎` |
| 动作行 | 以 `∆` 开头，一行一个可见动作 | `∆水晶灯下庆功宴觥筹交错。` |
| 台词行 | `角色名：（提示）台词`；括号只放可表演、可发声的情绪/语气提示，**自然短语即可，不设字数硬上限**（如 `低声` `压着火` `OS，带着自嘲`），可见动作另写 `∆` 行 | `苏曼：（压低声音）是我弄丢的。` |
| 内心独白 | `角色名：（OS）台词` 或括号组合 `（OS，情绪/语气）`；按本节口径，OS 只给观众听见，场内其他角色听不见，并计入净台词字数 | `纪夏：（OS，带着自嘲）我审过的史书里，三天后死的就是我。` |
| 画外音 | `角色名：（VO）台词`；按本节口径，只听见声音，角色不出现在当前画面中，并计入净台词字数 | `母亲：（VO）记住，别回头。` |
| 闪回 | `（画面闪回：∆……）` | — |
| 转场 | 场末按需：`（切至）` / `（淡出）`，非每场必写 | — |

**排版纪律**：
- 行间不留空行——场次行、人物行、动作行、台词行一律紧排；集与集之间空行分隔。
- 重要动作不塞进台词括号，单独出 `∆` 行；括号只放导演、演员或配音可执行的情绪、语气与发声方式，长度以一眼能执行为准，不为凑短砍掉必要副语言。`瞳孔骤缩`、`转身`、`拔刀`等可见动作另写 `∆` 行，不能与 `OS/VO` 混成声音提示。
- 【字幕】行启用时只标身份与姓名，不写剧情信息；与人物行的区别是它出现在人物**首次登场的位置**而非场首清单。是否启用服从接收方模板与身份辨认需要，不给每个新人物机械加字幕。
- 场号按 `{集}-{场}` 连续递增，全稿不重不漏。
- 删除母稿中的 `【场景设定】`、`【动作节拍】`、`Beat`、情绪强度分值等内部标签（转换底线见 §3）；场景设定段的必要环境信息并入该场开头的 `∆` 动作行。
- 不为齐版改台词、不为凑格式加戏；内容性差异一律回母稿（§2 底线）。

**场次转换示例**（母稿 → 投稿阅读稿）：

```text
# 第 1 集
**场1-1 夜 内 盛氏集团顶层宴会厅**
**人物：苏晚 苏曼 众高管 侍应生**
∆水晶灯下庆功宴觥筹交错，身着保洁工装的苏晚推着清洁车贴墙而行，低头擦拭地毯酒渍。
∆苏曼端着红酒迎面撞上清洁车，酒液泼了苏晚满身。
苏曼：（讥笑）哟，这不是苏家大小姐吗？怎么，沦落到擦地毯了？
苏晚：（拧干抹布）盛氏的保洁，也是一份工作。
苏曼：（凑近，压低声音）那你就好好擦。这地板，你们苏家当年跪着也没保住。
∆苏晚直起身，不看苏曼，继续擦拭。宴会厅大屏亮起，全场高管转向入口肃立——盛老爷子在侍应生搀扶下进场。
（切至）
```

## 5. 可选 DOCX 排版（明确要求时生成）

内部制作母稿与 `《剧名》_标准投稿阅读稿.md` 都必须保留。**DOCX 仅在用户或接收方明确要求时生成**，文件名为 `《剧名》_标准投稿阅读稿.docx`，内容只能来自已经通过预检的标准投稿 Markdown；DOCX 是额外包装，不替代 Markdown，也不成为内容真源。以下通用设置以耐读、便于批注为目标：

| 项目 | 通用默认 |
|---|---|
| 纸张 | A4 纵向 |
| 页边距 | 上下左右约 2.5 cm |
| 正文字体 | 中文宋体或等效易读字体，12 pt；英文/数字使用兼容字体 |
| 剧名 | 居中、加粗，20–22 pt |
| 集标题 | 黑体或等效无衬线字体，16 pt |
| 场次行/人物行 | 加粗，12 pt（§4a 格式） |
| 动作行 | 12 pt，`∆` 保留；台词行人物名加粗、台词常规 |
| 行距 | 1.35–1.5 倍；场次行前保留适度段前距 |
| 页码 | 页脚居中；封面可不显示页码 |
| 分页 | 每集前插入分页符，不用连续空行顶到下一页 |

不要为了「像正式稿」虚构版权声明、机构抬头、审批章、编号或项目联系人。没有专用模板时，也不声称上述通用样式必然满足某个平台的收稿要求。

## 6. 导出前核对

- 母稿 `script_rev` 与 SHA-256 已记录；
- 剧名、人物名、集数、场号与母稿一致；
- 制作母稿与标准投稿阅读稿已分别落盘为两个不同文件，且逐集集纲非空且覆盖到最后一集；
- 正文符合 §4a 标准剧本排版：场次行/人物行加粗齐全、人物行空格分隔、【字幕】身份行按需、动作行 `∆` 开头、台词括号只留可表演/可发声提示、OS 内心独白与 VO 画外音含义全稿一致、场号连续、行间紧排；
- 内部审核字段、Beat/预算、账本提示、AI 制作标签已移除；
- 动作去标签后仍保留剧情事实；
- 没有自行添加审批编号、备案结论、版权主体或联系方式；
- 在项目根目录运行成对预检：`python drama-crew/scripts/audit_screenplay.py --master "{项目名}_完整制作母稿.md" --submission "《剧名》_标准投稿阅读稿.md" --expected-episodes {总集数}`；**预检退出码为 0** 才可交付。脚本只判确定性错误与提示人工复核线索，不自动改写台词或替代季衡评分。
- 明确要求并生成 DOCX 时，每集另起一页，并逐页渲染为可视页面检查：无缺字、重叠、溢出、异常空白、孤行、错误分页或场次断裂；人物名、动作与对白层级清楚。任何排版修复后都重新渲染，不能只读正文或 XML 就宣布完成；宿主确实无法渲染时，交付时明确标注「未完成视觉 QA」。

任一内容性差异都要回母稿处理；只允许在本步骤直接修复字体、分页、缩进、页码、标题层级等展示问题。

## 7. 产物必要性判定表（题材 × 体量 → 必产 / 可并入 / 可免 · v6.14.0 增）

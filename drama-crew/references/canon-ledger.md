# 长篇状态管控（正典账本机制 · 融合版）

> 使用场景：连续性风险需要时先 Read 本文件，例如多集续写、多人多线、跨时段、复杂道具/知情/伏笔、跨会话或高密度状态变化。单集时长、总容量、叙事形式与复杂度共同决定是否启用，不只看集数；低风险预览可随交付顺带存档，不额外展开。
> 不写长篇正文时通常无需加载账本规则；持续项目的执行入口与跨会话恢复仍按 §4，策划阶段不因此强建账本。

**设计原则：管控动作嵌进交付物，不新增流程环节。** 团队跑法（角色、弹窗、节奏）与预览规模完全不变。
**责任人定版（v6.12.1 收口）**：**文茵**（编剧）产出本批正文、账本增量与自检声明 → **质检批由青梧**（正典官）同时读取当前批完整正文、对应集纲、必要前文事实、活动账本与增量，合并经正文举证的状态并跑冲突核查；正文与增量不得二选一，作者自评不作通过证据。**非质检批由主理人机械粘贴合并**，不读正文提炼、不做冲突核查 → 主理人除此之外只调度与验收，不改写账本内容。

## 1. 账本 Schema（核心六栏 + 按实际需要启用的第七栏，编剧初始化、随批更新）

活动账本可保留为既有 `正典账本.md`，也可在已有设定集的独立连续性章节承载；入口记录唯一路径/章节，按需要读取，不强制拆文件或搬到正文同目录。**账本章节或文件头部须有进度头，一眼可验是否最新：**

```
当前进度：正文已写至第 {X} 集｜账本最后更新：第 {X} 集
```

**核心六栏**（所有题材必填）：

| 栏 | 记什么 |
|---|---|
| 人物状态 | 每个主要人物当前身份/处境/位置 |
| 知情范围 | 谁知道哪些秘密（防知情穿帮的核心栏） |
| 关系变化 | 每次关系转折的触发事件与当前关系 |
| 关键道具 | 持有人/状态/去向（转手、损坏、公开、消耗必记） |
| 伏笔 | 埋设集 → 预定回收集，超期标红 |
| 集末状态 | 最新一集结束时明线/情感线/暗线各一句快照 |
| **成长体系**（**可选第七栏**：项目存在承重的能力、资源、地位、装备等成长系统，或这些状态确需跨集追踪时启用） | 继承主角及关键角色已经成立的成长状态，按当前模型只记实际相关维度，例如 `境界/等级：E01 炼气三层 → E05 筑基`、势力资源、声望地位或装备道具；不按题材标签强制四线并行，也不因现实题材免核承重的能力进展（见 world-bible.md 第 2 节） |

> 是否启用本栏只看实际成长系统与连续性需要：没有独立承重状态时可省略；一旦启用或继承既有成长记录，就随批保留并更新命中维度，不因题材、换季、换地图或预览档位清空。

**知情判断证据链（仍写入「知情范围」栏，不新增栏）**：每次认定角色或观众已经知道某事实，先按三步写清：`可见/可听载体 → 直接支持的最强结论 → 尚未证明的推断`。角色看到血迹，只能直接支持「这里发生过流血」，不能自动升级成「某人已经死亡」；角色听见半句通话，也只能取得半句实际支持的信息。推断可以成为人物行动依据，但必须标为推断，不得当作已证实正典，也不得让后续角色凭空共享。角色所见所闻与观众所见所闻分别判断；同一声音/动作跨视点或切镜时，标明同一事件的时间归属与各人的可感知范围，不把重复呈现算成第二次发生，也不因听见声音就知道画外详情。

## 2. 回写：文茵出增量 → 青梧合并（主理人只调度）

- 已启用账本的项目，文茵每批交付物固定多附「账本增量」（只列本批变更行）+ 一份自检声明。**质检批次**须把当前批完整正文、对应集纲、本批直接依赖的必要前文事实、活动账本和增量一起交青梧；只有正文与依据支持的增量才能合并为已验证状态。缺件时青梧列明未核范围、缺件和补核动作，不能用自检声明替代，未核范围继续阻塞；**非质检批次**由主理人直接粘贴合并（不读正文提炼、不做冲突核查），状态仍待后续约定质检窗口核验。
- **增量落位口径（唯一 · v6.14.0 收口）**：账本增量在本批工作区**随批落盘为独立文件** `{项目名}_增量_E{起}-E{止}.md`（与「正文真源分批落盘」对称，质检批交接与跨会话恢复直接读文件，不翻正文批次尾部找增量段）；增量文件随批次递增归档，合并完成后在文件头部标一行「已合并至账本（第X集）」，避免误当未处理增量。**禁止只在正文文件尾部内嵌增量段**——正文真源与账本增量是两类交付物，混写会让下游（交接单引用、青梧质检、跨会话恢复）多一次解析成本（实测五项目两种口径并存导致交接引用不可比）。
- **冲突处置顺序（v6.15.1 收口）**：先确定权威事实——用户最新确认的正文或明确修订指令优先，账本只是记录层，不得反向覆盖已锁定正文；再定位**首次偏离权威事实的可编辑位置**。账本记录错误就修账本；未锁定正文写错时由青梧标注、交文茵返修；用户已确认正文不得自动修改，只能报告冲突。两份同级已确认材料互相矛盾、无法判断哪份更新时，无明确权威时才上报用户裁决。处理后沿后续批次顺链核对受影响行，避免只修晚期症状。
- **显式时间锚核查**：正文出现具体钟点、日期、倒计时或“第 N 天”等锚点时，账本在人物状态或集末状态中保留当前时间进度。跨集重复同一句时间动作不因文字相同自动判错，但必须与账本推进一致；账本已经跨时段而正文仍批量停在旧钟点，定位首次冻结处交文茵修正文与后续受影响行，禁止只在末集改一个数字。
- 一个项目一份活动账本（独立文件或明确章节），旧版标「归档」。
- **世界观档案联动**：项目实际启用或继承 `world-bible.md`（世界观档案）时才与账本并行维护——账本记剧情连续性，世界观档案记世界真实性；本批确有命中模块变化时，文茵同时附「世界观增量」（如新地点、新规则、权限或境界变化），随账本同流程合并（质检批次青梧并、非质检批次主理人并）。未启用且没有可继承世界资产时不按题材标签强建档案或增量。

## 3. 下发前强制 3 件事（查账本不需要引导，规则强制）

任何续写/修改/分镜任务下发前，编排者固定执行（不允许凭记忆带状态）：
1. **Read `正典账本.md`**，核对进度头与目标集一致，粘贴最新账本原文（核心六栏+适用第七栏）进下发模板；
2. **Read 成稿 md 的上一集结尾场次**（制作侧景川承接时则读锚定表+已用 S 序号），粘贴承接段；**局部修改另核边界**：读替换起止的完整场、前后场及有承接的上下集原文，区分明确删除与摘录未包含；保留后文依赖的首次事件、动作结果和知情前提。修后沿真实依赖核对，不只自检新段，不无因撤销既有兑现。
3. 确认硬设定原文在模板中未缺项。三件齐了才发任务；账本进度头落后于正文时先补回写再发。

## 4. 执行入口与跨会话恢复

顾临在已有接稿/进度记录中维护唯一执行入口；持续项目确无记录时才新建轻量入口，纯问答与一次小修改不强建。它只保存：当前阶段与本次范围；活动真源路径/修订；已写范围与已审范围、审查者/报告定位及其对应修订；当前方法/适用范围/实际落点；未决问题、下一动作；用户决定的原文定位。已启用账本的事实仍留账本，正文仍留唯一活动标准正文，不复制成另一份 story bible，不提前生成 overview 或制作交接单。

每次交付、用户改变要求或审查完成后更新命中状态。只有方法计划时标计划，只有正文完成时标已写；未审批次不能因账本已合并而变成已审。正文修订使受影响范围的旧审查待复核，无关范围的证据可保留。

恢复先读入口，再读其指向的实际原文、用户决定和报告修订；有账本时读命中栏与承接场，按 §3 续跑并交青梧核脱节。入口与真源冲突时核文件来源与用户最新决定，修正入口，不用摘要覆盖真源。回显当前阶段/范围、已核与未核、下一动作；资料暂不可达时只暂停依赖部分，不凭记忆补完。


## 5. 批量续写（批次粒度 · v6.14.0 收口）

**批次粒度（唯一口径）**：**正文 10-20 集/批为基准，按体量自适应**——总集数 ≤24 时可全程单批或 12 集/批；30-40 集 2-3 批；60 集及以上每 20 集一批（与分批质检节奏对齐：质检批 = 正文批边界重合，青梧一次进场同时并账本+核冲突，不额外拆批）。用户明确指定批大小时从用户，但**不建议低于 5 集/批**——批过小会成倍增加增量文件、质检进场与合并次数（实测 5 集/批 × 12 批 vs 20 集/批 × 3 批，前者交付成本显著更高而质量无增益）。

**下发模板（固定复用）：**

```
你是短剧创作团的编剧文茵。继续创作《{剧名}》第 {起}—{止} 集正文。
【硬设定】{题材/风格/受众/集数/载体/平台/选题方案要点；用户原始需求原文及后续明确调整/确认原文分别附 source_locator，作者摘要另标来源，不得替换或弱化用户承诺}
【正典账本（当前状态，账本原文）】{核心六栏+适用第七栏}
【上一集结尾场次原文】{承接用}
【集纲（本批对应集的行）】{集纲对应行，连同本批每集须回应的原始承诺与单集要求逐字保留；未提供项标待确认，不擅自补写}
【本次方法与验证】{按 method-routing.md §1 填问题、主方法/章节、输入修订与命中原文、正文落点、验证证据及失败责任层；不能仅给空引用}
【你的任务】交付：1) 本批各集正文（标准剧本格式，每集结尾落在集纲标注的卡点上）
2) 账本增量（核心六栏中本批变更行；成长体系栏已启用且本批命中变化时一并更新相关维度；随批单独落盘 {项目名}_增量_E{起}-E{止}.md）
3) 自检声明：逐集确认无知情穿帮、无道具去向矛盾、伏笔是否按期回收，发现问题先自行返修再交付。
```

非质检批主理人按 §2 机械合并增量、扫自检声明后进下一批，仍标未核；质检批须青梧按 §2 读取正文及依据核查合并，再按既有质检节奏流转。方法路由不新增检查轮次或审批仪式。

## 6. 明确不采用的机制（防流程膨胀）

不建多目录项目体系、不做三层编辑链与双代理、不跑程序硬闸、不设评分表。是否增加连续性交付基建取决于实际风险、总容量与叙事复杂度，不以某个集数自动判定。

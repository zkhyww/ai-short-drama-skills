## 适用场景
用户要创作短剧（梗概/粗纲/集纲/剧本），期望走「情报 → 选题 → 梗概 → 粗纲 → 集纲 → 正文 → 台词桌读精修 → 合规初核 → 质量终审 → 制作母稿 / 投稿阅读稿」的标准流程，由多个专业角色分工完成。**剧本定稿后的分镜与视频制作归 `drama-studio`**，本 skill 只把内部制作母稿按交接契约移交；投稿阅读稿是对外阅读派生视图，不进入制作链。

**有稿直达（不做从零策划时不跑全流程）**：用户已有明确集纲或正文，或只是改写/续写/诊断剧本时，直接进对应环节——改写进文茵，续写按 canon-ledger 批量机制；成品稿若要锁版交付，先从第 3.7 步做台词桌读精修（需要连续性核查时先调青梧），再按模式进入 3.8/3.9；只要求诊断时可直接调青梧或季衡，不先改稿。以上均跳过市场情报、选题发散与选题确认关。只有从零策划新剧才从第 0 步与阶段 1A/1B 跑起。

## 核心原则
1. **主理人不代写**：专业产出必须由对应成员输出后才采信，主理人只做编排与汇编。**唯一例外：快写分流**（用户只给一句话创意/试写/单集速出时，主理人临时兼任执行角色直接出 E01 候选，不建团队——不视为代写违规，也不因此增设团队成员）。
2. **事实与判断分离**：检索（事实）归风聆，决策（判断）归纪遥；两者不合并到一个角色。
3. **写与查分离**：创作归文茵，核查归青梧；**创作者自检不等于独立审查**（自检照跑，放行权归第三方），长篇一律第三方核查。
4. **审查分层**：连续性核查（青梧，查「对不对」）与质量终审（季衡，查「好不好」）是两层，不合并；制作侧只接收已明确 `review_state` 的完整制作母稿，不接投稿阅读稿。
5. **硬设定传递**：用户确认的 题材/风格/受众/集数/载体/平台/创作灵感 必须原样写进每位成员的任务，成员不得改动、不得向用户重复提问。
6. **信息流经主理人中转（原文收窄注入 · v6.9.0）**：上一阶段产出传给下一阶段时，**保留完整原文落盘作为可追溯真源；下发只注入当前任务直接依赖的原文片段 + 来源文件名/稳定 ID**（如「详见 `{项目名}_03集纲.md` 第 X–Y 行」），不改写事实、不摘要变形、不复制无关历史全文；跨角色信息依赖（如终审要采信合规报告）必须传结论所在原文段。禁止摘要化传递（摘要=信息变形源）；成员之间不直连。**规范文件粘贴铁律不变**：references 规范仍按命中条目原文粘贴（规范是执行合同，不是阶段产出）。
7. **过程透明化（防黑盒）**：每个阶段产出 = 一个独立文件，**产出即落盘**给用户留档可查；**决策节点主动展示**（见下节机制），用户可阶段间纠偏。

## 过程透明化机制（防黑盒 · 用户全程可见可纠偏）

**用户看到"在工作"却不知道在写什么 = 黑盒，禁止。** 每个阶段产出必须让用户即时可见：

1. **即时落盘**：成员回传产出后，主理人立即把产出**原文**写成独立 Markdown 文件，写入项目工作目录，命名：`{项目名}_01市场简报.md`、`_02选题候选主题卡.md`、`_03集纲.md`、`_04_E01正文.md`、`_05合规报告.md`（合规初核在前）、`_06终审评分报告.md`（按阶段递增编号，用户一眼知道看哪个）。
2. **展示分级（落盘不等于打断 · v6.9.0 收窄）**：**决策节点主动 present_files 展示**——候选主题卡（选题拍板）、每批集纲与正文（批次确认）、终审评分报告、合规报告；**其他非决策中间文件**（市场简报、账本、世界观档案、中间草稿等）落盘保存后**不逐个弹展示**，在下一个自然节点合并通报文件名，用户明确要求时再展开——落盘 = 可追溯真源始终在，展示 = 只在需要用户拍板或纠偏时打断。
3. **关键关卡必展**：候选主题卡（选题确认关）、每批正文、终审评分报告、合规报告——这四类必须展示文件，不能只贴摘要。
4. **阶段间纠偏**：用户在任意阶段产出展示后可要求调整（改主题/改载体/改集纲/改台词/改剧名），纠偏发生在阶段间而非最终；调整后受影响的下游产出作废重做（沿用「调整规则」表，逐集续写可只改本批）。
5. **派生汇总文件只在交付时生成（禁止中途写早版）**：`{项目名}-制作交接单.md` / `overview.md` 是**第 4A 步交接产物**，投稿阅读稿是命中第 4B 步时才生成的派生视图；中途绝不预写——早写必与真实进度脱节（实测曾出现交接单写「正文第 1 集」而账本已到第 11 集的矛盾）。中途可见性靠每批落盘**实际交付物**（剧本/账本/终审报告/合规报告）实现，不靠汇总文件。
6. **阶段边界强制同步活文件（账本每批更，终审报告按触发建）**：每完成一个批次 / 一批续写，主理人必须重读并**重新落盘** `正典账本.md`（进度头更新到当前集）——账本是唯一每批必更的活文件；`终审评分报告.md` **仅在实际触发季衡终审后才创建或追加**（全稿终审模式下中途批次禁止预写空报告；分批质检模式在实际跑过关卡的批次追加记录），绝不滞后。
7. **成员结论写文件、主理人读文件（不依赖回传消息）**：三关卡等成员必须把结论写成独立文件并 present_files，主理人**从文件读取归档**，不依赖 SendMessage 回传文本、也不靠 TaskOutput 检索任务记录（实测 TaskOutput 常只回初始记录、结论易丢失，导致反复要求成员重推）。成员未落盘文件 = 产出未完成。SendMessage 允许作**轻量通知**（文件名+一行结论），不承载结论文本。
8. **最终交付**：第 4A 步先整合并展示完整制作母稿；命中第 4B 步时再展示投稿阅读稿。用户要进制作时，交接块四/五样只围绕完整制作母稿打包。

| 3.5 | **青梧**（正典官） | **按需**：按质检节奏在批次节点跑（长篇建议每 10-20 集 1 次）/ 用户要求质检 / 跨会话恢复；非质检批账本增量由顾临机械粘贴（不调青梧）；3.7 后仅复核改动场 | 合并账本 + 八项冲突自检；台词精修后只核事实锁，只报不改 |
| 3.7 | **文茵**（台词精修，沿用编剧角色） | 全稿或质检批正文完成、青梧前置核查（如启用）之后；快写在原任务内轻量自检 | 桌读对话回合，输出完整修订稿 + 变更表，不新增角色 |
| 3.8 | **素弦**（合规官·初核） | **关卡**：全稿/本批写完后、季衡终审**之前** 1 次（与终审同批连续）；用户可关（涉 IP/敏感题材不可关） | 五项合规核查（题材黑名单/平台审核差异/IP授权/敏感词/政治民族未成年红线），出合规报告，只判不改 |
| 3.9 | **季衡**（总编·质量终审） | **关卡**：素弦初核后跑（默认全稿写完后 1 次；长篇可选分批每 10-20 集 1 次）；用户可关 | **8 维百分制评分，≥90 放行**（88-89 符合 3.10 条件可带条件放行），红线命中封顶 84，红线第 7 条**采信素弦报告**，只判不写 |

> 角色卡与完整下发模板见 `references/role-cards.md`，调度前按角色取用。
> **工具匹配铁律**：需联网的角色（风聆）默认 `general-purpose`；所用类型无对应工具时降级换类型，绝不带着缺工具硬跑；再不行由主理人代检索并把结果塞进输入。

## 流程总览

### 第 0 步：需求确认（一轮搞定，禁止反复追问）
用 AskUserQuestion 弹窗（不支持时降级为文字列表），只问缺失的维度：

| 维度 | 选项集（推荐项放首位） |
|---|---|
| 题材 | 都市 / 古装宫斗 / 玄幻 / 悬疑（表外题材靠用户打字给） |
| 风格 | 爽文打脸 / 复仇虐渣 / 甜宠闪婚 / 悬疑反转 |
| 受众 | 通用 / 男频 / 女频 |
| 创作灵感 | 仅当用户没给任何故事方向时问：按我的思路来 / 我自己描述 |
| 质检节奏 | 写完统一终审（默认，速度优先）/ 分批质检（每 10-20 集 1 次，长篇推荐）/ 直通交付（跳过质检） |

- 用户 prompt 里已明确的维度直接采纳，不重复问。
- 集数未提默认 30 集（**可参数化**：24/40/60/80 均可——大卡点、付费墙、分批质检批次全部按集数比例自动换算，见 writing-craft 第 11 节与 commercial-craft 速查表）；平台未提默认 **红果**；质检节奏未提默认 **全稿终审**（写完统一质检，中途不打断）——三项在确认行说明即可，**不为它们单独开问**。**载体不设默认**：全程 `carrier=pending`，选题确认关（第 2.5 步）由用户锁定后才写进确认行——载体决定台词/动作/体量全部参数，禁拍脑袋代选。
- 用户选「我自己描述」→ 停下等用户发想法，禁止自己编灵感抢先开工。
- 确认后立即开工：
  > 已确认：题材 [X] / 风格 [X] / 受众 [X] / 集数 [X] 集 / 载体 [X] / 平台 [X] / 创作灵感 [X] / 质检节奏 [X]，现在开始。

**快写分流（重要）**：用户只给一句话创意、试写、单集速出时，**不建团队、不跑风聆、不出集纲**——主理人**临时兼任执行角色**（此为「主理人不代写」的唯一例外）直接给 E01 候选（梗概+首集正文）。用户认可再升级为完整流程。

### 第 1 步：建团队
TeamCreate，命名 `drama-<题材>-<风格>-<集数>`。角色按「角色编排」表依次 `Agent` 调度，`name` 传角色名，子任务名写中性描述，不带任何第三方视频模型名。

### 第 2 步：阶段 1A — 市场情报（调「风聆」）
**下发前**：Read `references/role-cards.md` 取风聆角色卡；Read `references/topic-selection.md` 核对搜索清单与信源优先级（把 6 条关键词与当前日期填进模板）。
**产出**：市场数据简报（数据基准行 / 大盘用户结构 / 政策红线 / 当期爆款样本 / 平台差异 / 载体线索 / **赛道拥挤度与同题材样本基线**）。开放选题此时尚无候选结构，`候选结构查重=pending`，不得用题材标签冒充结构查重。
**简报关**：向用户通报当期风向要点（1-2 句，含数据时间），**简报落盘为 `{项目名}_01市场简报.md`**（下一自然节点合并通报，用户要求时展开），再进 1B。

### 第 2 步：阶段 1B — 选题决策（调「纪遥」）
把风聆的**简报原文整段**作为输入下传；开放选题时纪遥只消费赛道拥挤度与同题材样本基线，不等待、也不消费仍为 `pending` 的候选结构查重。
**下发前**：Read `references/topic-selection.md`（黑名单 + 选题生成方法 + 选题发散池 + 载体平台适配 + 候选主题卡）、`references/naming-rules.md`、`references/title-naming.md`（候选主题卡出剧名候选）、**必读** `references/hit-craft.md`（CORE 四核心判定 + 引擎选型）与 `references/genre-and-fight-rules.md` 的「题材契约五问」（**所有题材均贴**）；目标题材命中专属规范表时再贴对应题材行，涉动作戏时再贴「动作戏判断」全文；**多季/长线项目**另读 `references/story-structure.md` §5/§6 贴多季规划（世界观容量判定 + 第一季收束点/续季悬念锚 + 凡人式升级纪律）。
**产出**：选题分析报告 11 项（含 CORE 四核心判定、五维打分 3 选 1 排名榜、前三集钩子、人物公式、命名候选、商业化锚点）→ **立即落盘为 `{项目名}_02选题候选主题卡.md` 并 present_files 展示**（含 3 张候选主题卡+剧名候选），供选题确认关使用。

**题材深耕触发（按需，可调「望舒」）**：纪遥判定目标题材为细分赛道且现有 references 数据库未覆盖（如「虐渣」「系统流」「海外本土」），或用户主动要求深耕时——调望舒联网深搜（5-8 条检索），出**题材深耕资料包**（格式见 `references/topic-research.md`：题材定义/经典桥段库/题材红线/受众画像/付费偏好），资料包原文回传纪遥修正选题方案后，再进阶段 2。常规题材跳过本步。

### 第 2.5 步：选题确认关（方向关卡 · 必停，用户拍板后才进创作）

**触发**：纪遥选题报告产出后、进阶段 2 之前——**必须停下来**，不允许直接闷头创作。方向错了后面全白干。

**候选查重回调（开放选题时 · v6.12.1 收口，v6.14.0 统一留痕口径）**：一句话梗概由纪遥在 1B 产出，候选结构查重必须等三卡形成后才有合法输入——**主理人在展示候选前，把 3 张候选卡的一句话梗概回调风聆并行查重一次**（复用风聆卡「第 3 轮：查重」模板，freshness=m3，一次并行查三卡，不逐条串行）；查重结论（同结构剧数量与相似度）随候选卡一并展示。用户已给现成梗概/明确方向直达时跳过本步（梗概已存在，可在 1A 直接完成结构查重）。仍只保留一次选题确认，不新增确认点。**留痕口径（唯一）**：查重结论默认写入 `{项目名}_02选题候选主题卡.md` 的候选卡「查重结论」行，**不另建独立查重文件**；仅当发生回调之外的补充检索（风聆二次查重、单卡深查）时，才把补充过程与结论拆出 `{项目名}_02A候选结构查重.md` 留痕——A 项目式独立文件是补充查重特例，不是全项目标配（实测五项目两套做法并存导致证据强度不可比，本口径收口）。查重六维比对方法与「0 命中≠全网没有」口径见 `references/review-scorecard.md` §6.3。

**动作**：主理人把纪遥报告的**候选主题卡**（3 个候选，格式见 `references/topic-selection.md` 第 7 节）原文（含查重结论）展示给用户，并明确问两件事：
1. **选哪个主题/方向**——`选第 X 个` / `按第 X 个改` / `都不行，往 XX 方向调`（用户可自由给新方向）；
2. **载体确认**：**真人短剧还是漫剧（AI 漫剧/视频）？**——载体决定后续全部写作参数（真人=台词驱动/净台词 350-500 字；漫剧=画面驱动/台词可压 300 字起/动作节拍 ≥5 点）。**载体全程 `carrier=pending`，不设默认**，此处由用户锁定后写进确认行。

**裁决**：用户选定主题 + 载体 → 主理人更新确认行（`已确认：主题 [X] / 载体 [真人|漫剧] / 平台 [X] / romance_axis [on|off]`）→ 才进阶段 2。`romance_axis` 由入选主题是否明确含恋爱主/副线直接判定并随文茵、季衡模板下传，不新增用户问题；`off` 时所有恋爱专项判据标 N/A。用户对候选都不满意时，可回 1B 重出（纪遥按新方向调整，简报同题材同季度可复用）或调望舒补题材资料。
**失败判定**：未展示候选主题卡就进阶段 2；未确认载体；用户明确要换方向却硬按原案创作——均视为违规。

### 第 3 步：阶段 2 — 剧本创作（调「文茵」）
把选题报告的「具体方案」整段作为硬设定下传。

**世界观档案初始化（按需，唯一口径见 `references/world-bible.md` 头部，只引用不复述）**：触发条件以 world-bible.md 唯一口径为准——特殊题材（玄幻/古装/科幻/无限流/悬疑）必建；其他题材仅在 ≥30 集**且**命中复杂度时建轻量版；快写分流/单集预览跳过。命中触发时，**下发文茵前 Read `references/world-bible.md` §1.1 并把原文贴进现有模板**；文茵在出梗概前先建六模块（空间地理 / 时间线 / 力量规则体系 / 势力格局 / 视觉奇观 / 设定边界），把 §1.1 的选择/代价/后果判断融入承重规则，再补成长体系四线（战力 / 势力 / 声望 / 装备）并跑 §5 质量四轴（Watsonian 自检逐条过关，invention 定级即止），作为后续所有集纲 / 正文的**设定最高宪法**；现实题材轻量版只填空间地理 + 时间线/时间锚点 + 设定边界三字段，人物关系由正典账本管理不重复。**立即落盘为 `{项目名}_世界观档案.md`**（按展示分级归入非决策中间文件，在下一个自然节点合并通报，用户要求时展开）；该文件随写作持续扩充，最终进交接块第五样。

**下发前（按任务阶段读，不一次全读——速度优先）**：Read `references/role-cards.md` 取文茵角色卡；**写梗概/人物建档时**读 `references/character-bible.md`（贴 §1-§4 人物小传创作法）+ `references/writing-craft.md` 命中条目；**写主角/关键配角首次出场戏时**加贴 `references/character-bible.md` §9（出场 30 秒五开关）；**排集纲时**读 `references/story-structure.md`（贴 §0/§1/§2；§3/§4 仅恋爱主/副线项目贴，多季项目加 §5/§6）+ `references/writing-craft.md` 大卡点；**写正文时**只读 `references/writing-craft.md` 命中条目与 `references/dialogue-craft.md`（台词专项已在人物/集纲阶段注入的不再重读）；付费短剧项目加 `references/commercial-craft.md`（体量参数与付费墙断章）；集数 ≥10 时首批加读 `references/canon-ledger.md` 要求账本初始化（续写批只贴账本原文，不重读文件）。**同一规范本会话已注入过的不重读不重贴**——引用编号即可。
**产出**：梗概 / 粗纲 / 集纲（含「本集代价」「下一集第一回应」两列）/ 剧本正文 / 账本初始化 / 账本增量（续写批）→ **每批立即落盘并展示**：集纲与正文分别落盘 `{项目名}_03集纲.md`、`{项目名}_04_EXX正文.md` 并 present_files（用户可逐批纠偏，不必等全剧写完）。

**批后核查（集数 ≥10 时，按质检节奏跑）**：按第 3.9 步（总编终审关）选定的质检节奏，在约定批次节点调「青梧」，把账本原文 + 本批增量下传，青梧合并账本并出八项冲突自检清单。**非质检批次由主理人直接粘贴合并账本增量，不调青梧不做冲突核查**（账本合并永远每批都做，冲突核查按节奏）。进入本次质检/交付窗口时，先完成本段前置核查，再进第 3.7 步。

### 第 3.7 步：台词桌读与表演化精修关（调「文茵」，不新增角色）

- **触发与节奏**：完整正文进入合规/终审或直通交付前必跑。全稿终审模式在全稿完成后跑 1 次；分批质检模式随每个质检批跑；快写/单集预览在原文茵任务内按同口径做轻量自检，不另起关卡。直通交付只跳过独立质检，不跳过创作者的本职台词精修；用户明确要“未经润色的原始草稿”时才保留原样并标注。
- **顺序**：正文完成 → 青梧按既定质检节奏做前置核查（本次未启用则跳过）→ 文茵 3.7 精修 → 若前置启用了青梧，则青梧只复核改动场事实锁 → 才进 3.8 素弦与 3.9 季衡。不得把精修放到终审放行之后，以免投稿稿、母稿和交接稿出现多个内容版本。
- **下发前**：Read `references/role-cards.md` 的「文茵 3.7 台词桌读与表演化精修下发模板」；Read `references/dialogue-craft.md` §9 并原文贴入。输入只含本次正文、命中角色声音指纹/locator、正典账本命中行与青梧前置结论，不重复塞入无关选题和规范全文。
- **不可改锁**：剧情事实 / 证据 / 知情边界 / 人物关系 / 结果 / 目标时长 / 季终悬念。文茵只改对白、标点及与发声直接相邻的微动作；必须改事实才能成立的问题退回上游，不在本关越权处理。
- **精修尺度**：以一个对话回合或表演节拍为判断单位，以“一口气只表达一个意图”为口语承载线。允许符合人物压力的停顿、改口、抢话、答非所问、自我纠正、未说完和生活性反应；不机械添加语气词、口头禅、走位或小动作。专业信息分散到物证、动作、追问、质疑、纠正与反应，禁止无压力宣读完整证据链。
- **表演落点**：承重台词按需明确意图/潜台词、承重词、思维节拍、速度强弱、音高语调、气息停连与句尾落点；普通句不逐句参数化，避免从“台词硬”改成“标注硬”。
- **产出**：本次范围的**完整修订稿 + 台词精修变更表**（位置〔集/场/原句〕｜精修后｜修改逻辑｜事实锁核对）。只给零散替换句、全稿无定位重写或新增另一套 AI 味分数均视为失败。
- **局部复核**：若本次前置启用了青梧，主理人随后使用「青梧 3.7 改动场局部复核下发模板」，只贴变更表命中的完整场次与账本命中行。青梧只核事实、证据、知情边界、人物关系与结果；通过后修订稿才成为当前活动正文，实质修改使 `script_rev +1`。未改场次不重审。

### 第 3.8 步：合规初核关（调「素弦」，先于终审 · 模式可选，用户可关）

> **顺序铁律（v6.8.2 定版）**：素弦在前、季衡在后——季衡红线第 7 条（合规）**以素弦报告为判定依据**，若素弦后置则季衡无据可采，构成流程循环。合规初核先行，季衡终审时直接采信，消除环。

- **触发**：全稿（或本批）完成第 3.7 步及必要的改动场局部复核后、季衡终审**之前**跑 1 次（与终审同批连续执行，不单独增流程）；涉 IP 改编、敏感题材（未成年/民族/宗教/现实事件）时**不可关**。选「直通交付」且无敏感题材时可跳过。
- **下发前**：Read `references/role-cards.md` 取素弦角色卡；把待审稿原文 + 已定平台 + 题材一并下传。
- **产出**：合规核查表（题材黑名单/平台审核差异/IP 授权/敏感词替换/政治民族未成年红线 五项逐项：通过 | 风险点 | 修改建议）→ **立即落盘 `{项目名}_05合规报告.md` 并 present_files 展示**。
- **出口**：五项全过 → 合规报告原样传入第 3.9 步季衡终审；有红线项 → 回文茵按修改建议改（只改合规点，不动剧情骨架），改后素弦复核通过再进终审。

### 第 3.9 步：总编终审关（调「季衡」，≥90 放行；88-89 符合 3.10 条件可带条件放行，模式可选，用户可关）

**质检节奏（第 0 步确认时顺带问一句或用户指定，默认推荐全稿终审）**：

| 模式 | 触发 | 适用 |
|---|---|---|
| **全稿终审（默认推荐）** | 全部剧本写完后跑 1 次 | 24-40 集、一口气写完的项目——**剧本没写完不质检**，中途只推进度不打断 |
| **分批质检** | 每 N 集一批（建议 10-20 集一批，如 60 集剧每 20 集 1 次，全剧 3 次） | 60 集以上长篇 / 边写边改多的项目——早发现问题早返工，避免最后推倒重来 |
| **直通交付** | 用户明确说「直接交付 / 不用质检」 | 赶时间、试写、草稿——跳过本关，交付稿注明「未终审」 |

> **不为流程而流程**：默认不跑中途审——批量续写时质检节奏只在第 0 步确认一次，选定后各批次按约定执行，不再每批追问「继续写还是先质检」；只有用户主动改模式时才变。用户说「继续」就一直写到全稿完成再统一质检。前 10 集/中后段/终稿的分窗打分只对**选了分批质检**的项目生效。

- **触发**：按上表选定模式；用户说「直接交付」即跳过本关。
- **终审前目录唯一性核验（v6.14.0 增，主理人机械项，不调子 Agent）**：把终审评分报告落盘前，对项目工作目录过一遍编号唯一性——①同编号文件不得并存两个内容版本（如 `_06季衡终审评分报告.md` 与 `_06终审评分报告.md` 同源异格式，只保留一个，旧版改名归档或删除并通报用户）；②文件名不得含「最终/final/副本/汇总」字样（这类文件要么是重复产物要么是汇总副本，真源必须是带批次编号的正名文件）；③无内容重叠文件（如 E01-E20 汇总正文与 E01-E05/E06-E10… 分段正文并存，汇总副本必须移出成品目录）。核验结果一句话留进终审报告头部（`目录核验：唯一 ✅ / 已清理 2 个重复文件`）。实测曾因双终审报告、双世界观档案、双 07 编号降低可交付性。
- **下发前**：Read `references/role-cards.md` 取季衡角色卡；**必读** `references/review-scorecard.md`，把对白硬度门与 8 维评分表原文贴进模板；把青梧的冲突清单/3.7 局部复核结论（若有）一并下传。
- **产出**：终审评分报告（对白硬度门 + 8 维打分表 + 8 条红线逐项 + 总分 + 五档裁决 + 返修指令表）→ **立即落盘 `{项目名}_06终审评分报告.md` 并 present_files 展示**（用户可见分数与返修点）。
- **门槛裁决**：对白硬度门先过，才计算放行。门通过且**≥90 放行交付**；**88–89 带条件放行**（总编裁量：未闭环项全为台词级/微调+已并入下批指引+无结构/红线问题，报告注明条件与清单，主理人验收核对）；80–87 文茵返修 → 季衡复审（只核对返修项+重打受影响维度）；**<80 回上游**（按责任层回滚选题/集纲/正文）；**红线命中任一条总分封顶 84 强制返修**。承重场对白程序化时先回 3.7，**不得用其他维度平均放行**。
- **分数留痕**：各窗分数写进账本进度头旁（`终审分：批1 92｜批2 88→94｜终稿 95`），跨会话可查。
- **深度质检分流**：需要 16 维评分/手术刀级整改时，不调季衡，改用独立的 jutian-script-doctor skill 跑深度质检，诊断结果作为返修指令输入。触发场景三选一：①季衡 <90 连续 3 次返修不见效；②长篇终稿前；③用户主动要求。

### 第 3.10 步：终审合并（主理人 · 不再单设素弦后置关）

- 原「终审放行后再跑素弦」的 3.9 后置关取消——合规核查已前置到 3.8，季衡终审时采信其报告。
- **门槛裁决**：**≥90 放行交付**；**80–89 分两路**——①一般返修复审：文茵返修 → 季衡复审（只核对返修项+重打受影响维度）；②**带条件放行（总编裁量权，v6.8.2 全局定版）**：仅当**未闭环项全部为台词级/微调、且已并入下一批强制指引、且无任何结构或红线问题**时，可带条件放行——季衡报告必须写明放行条件与未闭环项清单，主理人验收时逐项核对清单闭环；含结构问题或红线命中的一律返修，不得用条件放行绕过。**<80 回上游**（按责任层回滚选题/集纲/正文）；**红线命中任一条总分封顶 84 强制返修**（一票否决，防平均分掩盖硬伤）。
- **双报告合并**：主理人把合规报告（3.8 产出）与终审评分报告合并为交付包，两报告结论冲突时**合规优先**。

### 第 4A 步：内部制作母稿（唯一内容真源）

1. Read `references/submission-format.md`，把通过当前模式要求的活动正文整合为 `{项目名}_完整制作母稿.md`；保留剧名/梗概/人物/集场/场景五字段/动作节拍/时长目标/台词/版本锁及制作需要的标记。3.7 未通过必要局部复核、或对白硬度门未通过的稿件不得冒充锁版母稿。**交接单头部按 §7 产物必要性判定表记一行产物档位判定**（`产物档位：全量/标准/轻量 + 可免项`），轻量档不得缺核查与真源纪律。
2. 母稿头部记录 `script_rev`、`review_state`、目标成片时长、主画幅与用途。母稿是后续内容修改的**唯一内容真源**；选题、集纲、正文批次、变更表和报告仍作追溯依据，但不能与母稿并列成为活动剧本。
3. 写成 Markdown 并 present_files。用户只做内部制作或只要剧本时，交付母稿即可，不强制生成 DOCX/PDF。
4. **交接块打包**（用户要进制作时）——**只能把完整制作母稿交给 `drama-studio`**，投稿阅读稿不得进入制作链；按质检模式分两条路，不伪造缺失报告：
   - **标准交接（走过终审/合规的项目）**：**完整制作母稿原文 + 正典账本 + 终审评分报告 + 合规报告 +（世界观档案，触发口径以 `references/world-bible.md` 头部唯一口径为准）**——四样或五样整合输出，并标注 `review_state=reviewed` 与建议衔接模式。主理人打包前必须逐项核对：前四样始终必有；第五样按唯一口径判定，已触发必含。
   - **直通交接（走「直通交付」模式，无终审/合规报告）**：只携带**完整制作母稿原文 + 正典账本（若有）+（世界观档案，同口径判定）**，交接单头部标注「**未终审稿（直通模式）**」与 `review_state=unreviewed`。不伪造空报告，也不因缺报告卡死；制作侧按未审稿模式从严处理。
   - 两路交接单头部都带：**项目标识 / 剧本修订号（script_rev，每次实质修改 +1）/ 目标成片时长 / 主画幅与用途**。制作侧凭修订号判定分镜失效范围。
   - **角色文字声音指纹定位**：附 `角色｜声音指纹原文｜source_locator`；来源限纪遥人物声音锁或文茵人物/台词档案，精确到文件与段落。它只描述用词、句长、节奏、重音/停连倾向与拒绝方式，不代表实际音色资产，不携带音色授权状态，账本不作为来源；实际母音色由制作侧从角色首次发声起建立。
   - **单集试制（默认推荐）**：先交 E01 锁版母稿，提示可调 `drama-studio` 做 E01 验证；**整剧交接**在全剧锁版后一次进行；**边写边制**只在用户明示时使用。
5. **两团共同翻译原则（v6.8.4 定版，drama-studio 侧同步）**：drama-crew 定义人物欲望、阻力、选择、代价、信息变化、关系变化和观众期待；drama-studio 将其翻译为可见、可听、可剪的表演与镜头。制作侧可以改变表现方式，不能改变故事事实和因果；技术方案无法实现时，保留原节拍叙事功能，再换镜头、表演、声音或剪辑表达。

### 第 4B 步：投稿阅读稿排版（派生视图，按意图触发）

1. **触发不新增弹窗**：用户表达投稿、送制片人/平台编辑、对外阅读、需要 Word/DOCX，或明确要“制作版 + 投稿版”时执行；分批写作阶段不反复导出早版。接收方已给专用模板时优先适配其模板；没有时才用 `references/submission-format.md` 的通用排版。
2. 有可用 DOCX 文档工具时，从锁版母稿机械派生 `《剧名》_投稿阅读稿.docx`：保留剧名、梗概、人物、集场、动作与对白；去掉内部流程指令、审核字段、Beat/预算、账本提示、AI 制作标签和制作专用标记；每集另起一页。没有 DOCX 工具时只交同字段的可核对阅读版 Markdown，并明确说明未生成 DOCX，禁止改扩展名伪装。PDF 只在用户或接收方要求时生成。
3. 投稿阅读稿**不生成、推断或预填**许可证号、批准文件编号、节目编号、审批结论或平台受理状态；正式字段只能在上游实际提供后原样植入。通用排版只提高可读性，不宣称满足某一投稿方的全部格式要求。
4. 在 DOCX 自定义文档属性记录来源 `script_rev` 与母稿 SHA-256；工具不支持自定义属性时，在母稿交付记录中登记并明确告知，不静默省略。投稿稿发现内容问题时，必须回完整制作母稿修改、`script_rev +1`、重跑受影响核查后重新导出；禁止直接把 DOCX 改成第二真源。
5. 已生成 DOCX 时必须逐页渲染检查，至少核对缺字、溢出、孤行、场次断裂、错误分页、字体与人物名/对白层级；修复后重新渲染，不能只凭文本抽取宣布排版完成。宿主确实无法渲染时可交付，但须明确说明未完成视觉 QA。
6. 完成 4A/按需 4B 后，向仍活跃成员发 shutdown_request，TeamDelete 清理团队。

## 避坑清单
- **剧本层弹窗两点（方向关卡必须停）**：①第 0 步接稿确认（需求/集数/平台）；②**选题确认关**（阶段 1 后：候选主题 3 选 1 + 载体真人/漫剧确认）——用户拍板方向才进创作，禁止闷头干完全程才发现方向错。制作侧资产确认归 drama-studio。
- 集数（默认 30，可参数化 24/40/60/80，节奏锚点按比例换算）/平台（红果）默认不为它们单独开问（接稿确认时带回）；**载体不设默认（carrier=pending）**——真人短剧 vs 漫剧必须在选题确认关明确（决定台词/动作/体量全部写作参数），锁定前下发模板不得把载体写成已确认硬设定。
- **禁止凭训练记忆判断市场风向**——风聆必须先联网检索，简报必须带数据基准行与信源。
- **禁止自审**：长篇的知情穿帮/道具/伏笔/同构/AI味核查交青梧，不由文茵自查、也不由主理人代查。
- **禁止让一个角色同时干检索与构思**（风聆/纪遥必须分开）、同时干写作与核查（文茵/青梧必须分开）。
- **制作只接状态明确的完整制作母稿**：标准交接必须通过季衡终审并标 `review_state=reviewed`；只有用户明确选择直通交付时才可跳过，并标 `review_state=unreviewed`。活动草稿和投稿阅读稿都不得混入制作链。
- **审查两层不合并**：青梧查连续性「对不对」，季衡查质量「好不好」；需要 16 维深度质检时调 jutian-script-doctor，不让季衡膨胀成全量医生。
- **合规独立于质量**：素弦查「违不违规」；标准交接未过合规关不得标 `reviewed`，素弦与季衡意见冲突时合规优先。直通交付不伪造合规结论；涉 IP 改编/敏感题材时合规关不可跳过。
- **题材深耕按需触发**：只有纪遥判定细分赛道未覆盖或用户主动要求时才调望舒，常规题材不增设环节。
- 下发前未 Read 对应角色卡 = 违规；角色卡须放在 prompt 开头，任务在后。
- 子任务名、通报、交付里禁止出现第三方视频模型名。
- 涉及已有 IP 改编时提醒用户确认授权。

## 适用场景
用户要创作短剧（梗概/粗纲/集纲/正文）时，由专业角色按已选入口执行策划、写作、台词表演化精修、适用核查与标准正文交付。已有稿直达相应环节。定稿后的分镜与制作归 drama-studio，读者与制作侧使用同一份标准正文及各自所需配套资料。

**有稿直达（不做从零策划时不跑全流程）**：用户已有明确集纲或正文，或只是改写/续写/诊断剧本时，直接进对应环节——改写进文茵，续写按 canon-ledger 批量机制；成品稿若要锁版交付，先从第 3.7 步做台词桌读精修（需要连续性核查时先调青梧），再按模式进入 3.8/3.9；只要求诊断时可直接调青梧或季衡，不先改稿。以上均跳过市场情报、选题发散与选题确认关。只有从零策划新剧才从第 0 步与阶段 1A/1B 跑起。

## 宿主工具与依赖适配

本文与角色卡中的 TeamCreate、Agent、Read、SendMessage、present_files 是职责名称，执行前映射当前宿主实际可用工具，不调用不存在的接口。文件读取用宿主文件工具；产出先保存，再以真实路径链接或宿主文件预览展示。没有 present_files 不阻塞交付，没有 TeamCreate 也不要求建立可见任务窗口。

有子代理能力时，按对应角色卡派给独立执行者；例如 Codex 使用当前可用的子代理工具，角色名放任务说明，不能猜造不受支持的 agent_type。依赖任务顺序执行，不并发覆盖同一正文或记录；消息只作通知，文件为依据。自动创建可见任务窗口必须符合宿主与用户授权，不以工具适配为由额外创建窗口。

无子代理能力时，可由当前执行者按命中角色卡顺序完成草稿、研究整理与制作规划，并明确为单执行者模式；这是能力降级，不冒充多个独立成员。本人复读只记自检，要求独立核查/终审的范围保持未审；不能自行标 reviewed 或签出独立评分。只阻塞依赖缺失审查的放行，其余不依赖工作继续。已有合法审核记录按范围和版本继承，不因工具变化全部降级。

两包并排安装可使用完整共用表演库与案例路由。仅安装一包时，先核所需跨包文件：普通创作可使用本包人物、对白与动作方法；普通制作规划可消费用户已有正文/资产及本包分镜方法。缺共用库时明确本次未参考该库，不猜原文或来源；确需另一包权威格式/世界规则或专项时，只暂缓依赖项并提示安装对应包。已有文件继续作为事实输入，不因此重写故事。私有案例绑定已配置却失效时仍按案例库规则报错，不把本段当作回退过期快照的许可。

## 核心原则
1. **主理人不代写**：专业产出必须由对应成员输出后才采信，主理人只做编排与汇编。**常规例外：快写分流**（未命中片段探索且用户只给一句话创意/首集试写/单集速出时，主理人临时兼任执行角色直接出 E01 候选，不建团队——不视为代写违规，也不因此增设团队成员）。无子代理环境另按「宿主工具与依赖适配」降级，不伪造独立审查。
2. **事实与判断分离**：检索（事实）归风聆，决策（判断）归纪遥；两者不合并到一个角色。
3. **写与查分离**：创作归文茵，核查归青梧；**创作者自检不等于独立审查**（自检照跑，放行权归第三方），长篇一律第三方核查。
4. **审查分层**：连续性核查（青梧，查对不对）与质量终审（季衡，查好不好）分层；制作接收唯一标准正文及外置交接记录中明确的 review_state，不另要一份内部版。
5. **硬设定传递**：用户原始需求、后续明确调整/确认及各自 `source_locator` 必须原样保留并按职责写进成员任务；作者摘要另标来源，不得替换或弱化原始爽感、关系及其他具体承诺。选题确认后的「受众承诺（主要情绪回报＋兑现方式）」原文同样传递。未讨论的 `romance_axis` 保持待确认，不得推成 `off`；成员不得包装改写、擅换回报或向用户重复提问。
6. **信息流经主理人中转（原文收窄注入 · v6.9.0）**：上一阶段产出传给下一阶段时，**保留完整原文落盘作为可追溯真源；下发只注入当前任务直接依赖的原文片段 + 来源文件名/稳定 ID**（如「详见 `{项目名}_03集纲.md` 第 X–Y 行」），不改写事实、不摘要变形、不复制无关历史全文；跨角色信息依赖（如终审要采信合规报告）必须传结论所在原文段。禁止摘要化传递（摘要=信息变形源）；成员之间不直连。references 规范同样只注入当前任务命中的原文条目，并保留文件名与章节锚点；不得把整份资料包无差别下传。
7. **过程透明化（防黑盒）**：阶段产出按用途写入既有文件或稳定章节，依 submission-format §7 按需拆并；唯一正文不复制，**产出即落盘**给用户留档可查；**决策节点主动展示**（见下节机制），用户可阶段间纠偏。

## 过程透明化机制（防黑盒 · 用户全程可见可纠偏）

**用户看到"在工作"却不知道在写什么 = 黑盒，禁止。** 每个阶段产出必须让用户即时可见：

1. **即时落盘**：实际产出原文及时保存到既有对应文件或明确章节；成员候选与待合并增量进入本批工作区，不每次回传另造报告或重复全稿。文件拆并按 submission-format §7–§8，审核职责与原文来源可定位，空流程不产空文件。
2. **展示分级（落盘不等于打断 · v6.9.0 收窄）**：**决策节点主动 present_files 展示**——候选主题卡（选题拍板）、每批集纲与正文（批次确认）、终审评分报告、合规报告；**其他非决策中间文件**（市场简报、账本、世界观档案、中间草稿等）落盘保存后**不逐个弹展示**，在下一个自然节点合并通报文件名，用户明确要求时再展开——落盘 = 可追溯真源始终在，展示 = 只在需要用户拍板或纠偏时打断。
3. **关键关卡必展**：候选主题卡（选题确认关）、每批正文、终审评分报告、合规报告——这四类必须展示文件，不能只贴摘要。
4. **阶段间纠偏**：用户在任意阶段产出展示后可要求调整（改主题/改载体/改集纲/改台词/改剧名），纠偏发生在阶段间而非最终；调整后受影响的下游产出作废重做（沿用「调整规则」表，逐集续写可只改本批）。
5. **交付记录不预写**：制作交接单/overview 在第 4A 步按真实进度生成；标准正文从写作起按标准格式维护，已有状态与实际启用账本随批同步。第 4B 步仅按明确要求导出格式，不因阅读或制作重复生成 Markdown 剧本。
6. **阶段边界强制同步活文件（已启用账本每批更，终审报告按触发建）**：项目按连续性风险启用 `正典账本.md` 后，每完成一个批次 / 一批续写，主理人必须重读并**重新落盘**（进度头更新到当前集）；实际低风险且从未启用账本的任务不为档位齐套强建，已有账本则任何入口都继承并更新。`终审评分报告.md` **仅在实际触发季衡终审后才创建或追加**（全稿终审模式下中途批次禁止预写空报告；分批质检模式在实际跑过关卡的批次追加记录），绝不滞后。
7. **成员结论写文件、主理人读文件（不依赖回传消息）**：三关卡等成员必须把结论原文落盘到本批候选或既有对应记录并展示；可顺序汇入已有验收文件分区，保留独立审核来源、范围与版本，主理人**从文件读取归档**，不依赖 SendMessage 回传文本、也不靠 TaskOutput 检索任务记录（实测 TaskOutput 常只回初始记录、结论易丢失，导致反复要求成员重推）。成员未落盘文件 = 产出未完成。SendMessage 允许作**轻量通知**（文件名+一行结论），不承载结论文本。
8. **最终交付**：展示唯一标准正文；设定、集纲、正典和实际审核记录按必要性提供。阅读与制作共用该正文，明确要求时再导出格式。

## 流程总览

### 第 0 步：配置引导与需求识别

先读本包 [references/startup-guide.md](references/startup-guide.md)，按其展示分支接稿：新项目默认给完整功能导航与自动填写的本次配置卡；同项目续作只显示本次配置和变化；用户说“跳过引导”时省略导航与长表，直接进入匹配环节。“展开全部功能”可随时恢复导航，不重置项目。

从本次要求、已有项目设置和明确目标稿提取信息，逐项区分已确认/识别建议/待确认/待就绪并保留来源；只有影响当前交付的缺项才合并询问。无方向的新手先选开放选题或描述想法，不逐项强填题材、风格、受众。信息足够就推进，不为回显配置新增停点；已有稿仍按“有稿直达”，单场/台词任务不扩成整季。

未给集数/平台/质检且确需从零整季规划时，30 集/红果/全稿终审仅作相容的默认建议，不能标作用户已确认；明确英文出海等目标不硬套国内平台。已有载体、恋爱轴及正典继承，未知不擅自锁定。“跳过引导”不等于直通未审稿或关闭质检；方向、事实、IP 与授权仍按原关卡处理。只说“跳过引导”又无目标/旧项目时，按配置卡只问最少任务缺项，不自造项目。

配置落在已有接稿记录或当前答复中；下发成员时只带命中项的值、状态与来源，不把功能介绍注入创作正文。用户选择“我自己描述”时等待其材料，不抢写灵感。

**片段探索分流（先于快写匹配）**：用户希望从人物、生活片段或情绪画面试探故事，且尚无冻结结构时，由顾临按 `theme-design.md` §1「片段探索任务」派文茵在请求范围产出候选片段，暂不要求首集、整季集纲或主题定论。已有冻结梗概/集纲的续写仍有稿直达；仅一句话商业创意且未表达探索意图仍用下述快写。探索产物不是正式正典，后续立项和正式扩写回原有相应确认与结构关。

**快写分流（重要）**：未命中上述探索、用户只给一句话创意、首集试写、单集速出时，**不建团队、不跑风聆、不出集纲**——主理人**临时兼任执行角色**（此为常规快写例外；无子代理环境另按宿主适配处理）直接给 E01 候选（梗概+首集正文）。尚无全季人物规划时，不为一句话试写强造全季阵容；若上游已有全季核心人物规划或档案，原样继承并按本次任务核对，不因快写把既定核心降档或删出项目。用户明确只要求展开指定人物档案时按该范围交付，不反向扩写全季档案。用户认可再升级为完整流程。

### 第 1 步：建团队
按「宿主工具与依赖适配」建立角色分工；宿主支持 TeamCreate 时命名 `drama-<题材>-<风格>-<集数>`。角色按「角色编排」表依次 `Agent` 调度，`name` 传角色名，子任务名写中性描述，不带任何第三方视频模型名。

### 第 2 步：阶段 1A — 市场情报（调「风聆」）
**下发前**：Read `references/role-cards.md` 取风聆角色卡；Read `references/topic-selection.md` 核对搜索清单与信源优先级（把 6 条关键词与当前日期填进模板）。
**产出**：市场数据简报（数据基准行 / 大盘用户结构 / 政策红线 / 当期爆款样本 / 平台差异 / 载体线索 / **赛道拥挤度与同题材样本基线**）。开放选题此时尚无候选结构，`候选结构查重=pending`，不得用题材标签冒充结构查重。
**简报关**：向用户通报当期风向要点（1-2 句，含数据时间），**简报落盘为 `{项目名}_01市场简报.md`**（下一自然节点合并通报，用户要求时展开），再进 1B。

### 第 2 步：阶段 1B — 选题决策（调「纪遥」）
把风聆简报中当前任务命中的原文摘录与 `source_locator` 下传；开放选题时纪遥只消费赛道拥挤度与同题材样本基线，不等待、也不消费仍为 `pending` 的候选结构查重。
**下发前**：Read `references/topic-selection.md`（题材风险库 + 选题生成方法 + 选题发散池 + 载体平台适配 + 候选主题卡）、`references/naming-rules.md`、`references/title-naming.md`（候选主题卡出剧名候选）、**必读** `references/hit-craft.md`（CORE 四核心判定 + 引擎选型）与 `references/genre-and-fight-rules.md` 的「题材契约五问」（**所有题材均贴**）；目标题材命中专属规范表时再贴对应题材行，涉动作戏时再贴「动作戏判断」全文；**多季/长线项目**另读 `references/story-structure.md` §5/§6 贴多季规划（世界观容量判定 + 第一季收束点/续季悬念锚 + 长期成长连续性）。
**产出**：选题分析报告 11 项（含 CORE 四核心判定、五维打分 3 选 1 排名榜、前三集钩子、人物公式、命名候选、商业化锚点）→ **立即落盘为 `{项目名}_02选题候选主题卡.md` 并 present_files 展示**（含 3 张候选主题卡+剧名候选），供选题确认关使用。

**研究补给触发（按需，可调「望舒」）**：纪遥判定细分赛道未覆盖或用户主动要求深耕时走整赛道资料包；文茵六行自检或 Studio 专业角色只定位到一个创作/对白/制作事实缺口时走定向补项。两种模式先读 Studio 单点持有的 `../drama-studio/references/case-library/README.md`，按用途标签只读命中 metadata 记录；获准且本地根已绑定时才回源命中单条 TXT。仍不足且已有联网授权时，主动用可达的 `agent-reach` 查可核原帖/作者续文/完整样本。定向补项无固定搜索/样本配额，够回答或同类查询无新增决策价值即停；只把当前决策命中的原文摘录与 `source_locator` 回传，不重复传全包。

### 第 2.5 步：选题确认关（方向关卡 · 必停，用户拍板后才进创作）

**触发**：纪遥选题报告产出后、进阶段 2 之前——**必须停下来**，不允许直接闷头创作。方向错了后面全白干。

**候选查重回调（开放选题时 · v6.12.1 收口，v6.14.0 统一留痕口径）**：一句话梗概由纪遥在 1B 产出，候选结构查重必须等三卡形成后才有合法输入——**主理人在展示候选前，把 3 张候选卡的一句话梗概回调风聆并行查重一次**（复用风聆卡「第 3 轮：查重」模板，freshness=m3，一次并行查三卡，不逐条串行）；查重结论（同结构剧数量与相似度）随候选卡一并展示。用户已给现成梗概/明确方向直达时跳过本步（梗概已存在，可在 1A 直接完成结构查重）。仍只保留一次选题确认，不新增确认点。**留痕口径（唯一）**：查重结论默认写入 `{项目名}_02选题候选主题卡.md` 的候选卡「查重结论」行，**不另建独立查重文件**；仅当发生回调之外的补充检索（风聆二次查重、单卡深查）时，才把补充过程与结论拆出 `{项目名}_02A候选结构查重.md` 留痕——A 项目式独立文件是补充查重特例，不是全项目标配（实测五项目两套做法并存导致证据强度不可比，本口径收口）。查重六维比对方法与「0 命中≠全网没有」口径见 `references/review-scorecard.md` §6.3。

**动作**：主理人把纪遥报告的**候选主题卡**（3 个候选，格式见 `references/topic-selection.md` 第 7 节）原文（含查重结论）展示给用户，并明确问两件事：
1. **选哪个主题/方向**——`选第 X 个` / `按第 X 个改` / `都不行，往 XX 方向调`（用户可自由给新方向）；
2. **载体确认（仅 `carrier=pending` 且会改变当前决策时）**：请用户在相关候选中锁定；已有 carrier 直接继承，不重复询问，也不强制三载体比较。真人=台词驱动是常见倾向，350–500 字只作同体量真人短剧的诊断区间；漫剧更偏画面驱动，两者都以实际时长证据为准。

**情感线轴证据判定（不新增用户提问）**：主理人依据入选主题是否明确包含恋爱主线或副线，只在已确认内容证据充分时自动确定合法的 `romance_axis=on|off`：明确包含恋爱主线或副线时记 `on`，明确说明不含恋爱线时记 `off`。材料未提供或不足时不得因缺省推成 `off`，也不写入已确认硬设定，仅用自然语言说明「未提供/待确认」（该说明不是合法枚举）；若这一缺口会改变当前交付，沿用本选题确认关做必要澄清，不影响当前任务则继续，禁止要求所有人物或项目重新确认。只有已确认的合法值才随硬设定下传文茵及后续成员。

**裁决**：用户选定主题，并在必要时锁定载体后，主理人更新确认行再进阶段 2。已有载体无需重复确认；未知且当前阶段不依赖载体时继续保持 pending。用户对候选都不满意时，可回 1B 重出或补题材资料。
**失败判定**：未展示候选主题卡就进阶段 2；载体未知却擅自代选；用户明确要换方向却硬按原案创作。

### 第 3 步：阶段 2 — 剧本创作（调「文茵」）
把用户原始需求、后续明确调整/确认、选题报告「具体方案」与已确认的「受众承诺（主要情绪回报＋兑现方式）」分别保留原文和 `source_locator` 后下传；作者摘要不得替换用户需求，不新增参数、表格或关卡。

**排集纲起稿**：文茵先判断观众在乎什么、人物怎样有效行动、结果前后落差及其对人物/关系/局面的影响，再决定续接，并把实际事件写入原「本集事件与冲突升级」单元格。品牌叙事按 references/commercial-craft.md §8 的既定结尾回报验收；已选择持续爽感承诺的 60–90 秒短集每集至少一次真正爽点或实质反转，默认约每半分钟给反制/局面改变/小兑现/实质反转，但不要求激烈冲突或精确卡秒，可按题材、场面与承诺调整；登记说明、无关信息、狠话瞪眼、更大威胁、预告或连续负向反转不能充数。单集小兑现、阶段大兑现、终局总兑现分层；安静关系兑现成立。五分钟等其他容量按自身功能合并，不强套 75 秒模板。

**普遍情感方法（排集纲与实际正文派单均启用）**：按已定关系浓度与人物关系字段决定情感承担主引擎、副引擎、高潮、钩子、单集回报或人物温度。关系场写清人物关切 → 有意义的对待/选择 → 对方回应 → 关系或感受变化；四项可跨场分布，不规定拍数。单人故事以牵挂、记忆、归属、羞耻、希望或欲望推动实际选择，不为凑互动增人。`romance_axis` 只控制恋爱专项：`on` 才加 §3，爱情主线承重集须兑现实际恋爱承诺；`off` 不关闭普遍情感。安静段可承担主要回报，直接表达可以成立，不按七情六欲清单填项。

**世界观档案初始化（按需，唯一口径见 `references/world-bible.md` 头部，只引用不复述）**：地点/时间/力量或职业规则/势力权限/跨时空/跨季等世界事实约束人物选择、证据、解法或制作连续性时，按复杂度建完整六模块或轻量版；实际低风险且没有既有资产时可免新建。题材、集数、快写和预览只调整展开与拆并，不免除承重事实核查；上游已有世界观、时间线或专业边界时必须读取并继承命中片段。命中触发时，**下发文茵前 Read `references/world-bible.md` §1.1 并把原文贴进现有模板**；文茵把实际作用、调用条件、因果依据、成本/后果和例外融入活动真源，跑与版本相称的 §5 质量轴，立即落盘并随批更新，按实际需要进入交接块。

**下发前（按任务阶段读，不一次全读——速度优先）**：Read `references/role-cards.md` 取文茵角色卡；**写梗概/人物建档时**读 `references/character-bible.md`（贴 §1-§4 人物小传创作法）+ `references/writing-craft.md` 命中条目；**写主角/关键配角首次出场戏且需要补第一印象参考时**加贴 `references/character-bible.md` §9（首次出场可选参考）；**排集纲时**读 `references/story-structure.md`（贴 §0/§1/§2/§4，`romance_axis=on` 才加 §3，多季项目加 §5/§6）+ `references/writing-craft.md` 大卡点；**写正文时**读 `references/writing-craft.md` §7/§12/§18、`references/dialogue-craft.md` 与按实际场面功能命中的 `references/genre-and-fight-rules.md`，并把 `references/story-structure.md` §2/§4 的普遍情感方法贴进实际正文派单（同一文茵上下文已保留同版本时可引用节号，不能因已有集纲或 `romance_axis=off` 省略；仅 `romance_axis=on` 时加贴 §3）。文茵写清故事可见/可听事件、必要过程、参与者回应、前后状态与披露时机；歌舞/演奏、竞赛/载具、精细操作、潜入/伪装、多方程序、动物/异种、特殊环境或分层叙事等只按本场真实承担的机制展开，保持自然剧本；正文排版先按 submission-format.md §4a 读取已选模板，允许模板所需的必要景别提示，不预写完整机位、逐秒剪辑或图片提示词；标题没有类型关键词但场面实际命中时照样加载。项目需要记忆点或跨场回扣时加贴 dialogue-craft §3。需要声音承戏时贴 writing-craft §4 声音判断，机制场贴 genre-and-fight-rules 对应段与 world-bible §1.1 既有规则；品牌叙事先按 `references/commercial-craft.md` §8 的已锁用途下发；付费短剧项目加 `references/commercial-craft.md`（体量参数与付费墙断章）；**连续性风险命中或批量续写**时首批加读 `references/canon-ledger.md`，需要时初始化账本并把知情证据三步交青梧（已有账本的续写批仍须贴当前正文任务命中的账本原文）。**去重以接收成员的上下文为边界**：同一成员且确认保留同版本规范时引用节号；新成员、跨会话或上下文压缩后重新贴命中原文。主理人可复用已读文件，不据此省掉新成员的输入。

**案例与补缺直达文茵**：需要作者方法或上游电影/剧集文本分析时，顾临先按 `screenwriting-library.md` 核验并读取本地原文，按方法路由适配后注入。顾临在下发正文或 3.7 精修前，按当前场的机制/地域/年代/关系/语用问题读取共享案例索引；有命中就把稳定 ID、metadata 状态及必要的单条本地原文（仅在已获准且可达时）直接放进文茵现有输入，不只说“可调用”。没有命中或本地不可达时明记状态；确定性事实不足只暂停受影响位置并按上段定向补项，其余内容继续，风格参考缺失不妨碍原创。
**产出**：梗概 / 粗纲 / 集纲（「本集代价」「下一集第一回应」两列必填；代价只写已发生成本或旧成本延续，未来风险另标；下一集须有效承接当前强钩；允许无新增损失/完结不适用，不预设剧情结果）/ 剧本正文 / 账本初始化 / 账本增量（续写批）→ **每批立即落盘并展示**：集纲在既有独立集纲或配套设定章节维护；正文候选落本批工作区，通过后合入唯一正文，分别展示实际路径/章节（用户可逐批纠偏，不必等全剧写完）。

**批后核查（已按连续性风险或批量续写启用账本时，按质检节奏跑）**：按第 3.9 步选定的质检节奏，在约定批次节点调「青梧」，同时下传当前批完整正文、对应集纲、本批直接依赖的必要前文事实/上一集结尾、活动账本与待合并增量；正文与增量不得二选一，作者自评只作待核声明。缺件时青梧列明未核范围与补件动作，未核范围保持阻塞，不默认无问题。**非质检批次由主理人直接粘贴合并账本增量，不调青梧不做冲突核查**（已启用账本的项目每批合并，冲突核查按节奏）。进入本次质检/交付窗口时，先完成本段前置核查，再进第 3.7 步。

### 第 3.7 步：台词桌读与表演化精修关（调「文茵」，不新增角色）

- **触发与节奏**：完整正文进入合规/终审或直通交付前必跑。全稿终审模式在全稿完成后跑 1 次；分批质检模式随每个质检批跑；快写/单集预览在原文茵任务内按同口径做轻量自检，不另起关卡。直通交付只跳过独立质检，不跳过创作者的本职台词精修；用户明确要「未经润色的原始草稿」时才保留原样并标注。
- **顺序**：正文完成 → 青梧按既定质检节奏做前置核查（本次未启用则跳过）→ 文茵 3.7 精修 → 若前置启用了青梧，则青梧只复核改动场事实锁 → 才进 3.8 素弦与 3.9 季衡。不得把精修放到终审放行之后，避免已审正文与配套交接发生版本漂移。
- **下发前**：Read `references/role-cards.md` 的「文茵 3.7 台词桌读与表演化精修下发模板」；Read `references/dialogue-craft.md` §9 并原文贴入。输入只含本次正文、命中角色声音指纹/locator、正典账本命中行与青梧前置结论，不重复塞入无关选题和规范全文。
- **不可改锁**：剧情事实 / 证据 / 知情边界 / 人物关系 / 结果 / 季终悬念，尤其不得发明疾病、药物、剂量、伤因、复工条件或资产性质。文茵只改对白、正常标点及不改变结果的相邻微动作，改变时长后重新估时；必须改事实的问题退回上游。
- **时长边界**：只有用户、平台或已批准预算明确设定的硬性时长才冻结；有硬限制时报告台词、表演与时长取舍，不得静默突破。没有明确硬限制时，暂排场景/分镜秒数可为合理台词重排，并同步活动正文、集纲与制作计划。模型单次 Clip 上限不等于场景或单集总长；自然意群分组与音轨衔接交既有 Studio 流程，不能借切镜虚增发声容量，实际付费调用仍需另行授权。
- **精修尺度**：允许正常承接、因果辩解、求助、完整听答、直接表达、停顿或改口，均由人物与处境决定；不机械添加省略号、口吃、打断、语气词、走位或小动作。先按 dialogue-craft §9 的实际语言单位并留呼吸估算（中文 3–3.5 字/秒仅作首轮假设，英语用词数/WPM），仅明确要求、硬时长冲突或局部风险未解时对命中片段真人朗读/倾听；完全重叠只计一次，部分重叠只加尾段，互斥片段按实际调度相加，预检不自动推算动作或总时长。
- **表演落点**：按 dialogue-craft §9.3 核关键节拍的内在变化如何被观众感知，在 OS、语气括注与细微反应间选择有效载体；已有动作或对白说清的不重复，缺少必要表达的须补回正文。承重台词按需明确意图/潜台词、承重词、思维节拍、速度强弱、音高语调、气息停连与句尾落点；不设逐集独白或逐句括号配额，普通句不参数化。
- **产出**：本次范围的**完整修订稿 + 台词精修变更表**（位置〔集/场/原句〕｜精修后｜修改逻辑｜事实锁核对）。只给零散替换句、全稿无定位重写或新增另一套 AI 味分数均视为失败。
- **局部复核**：若本次前置启用了青梧，主理人随后使用「青梧 3.7 改动场局部复核下发模板」，贴原发现、完整修订场次、对应集纲、账本命中行与必要相邻上下文。青梧直接对照原发现与修订落点，核问题是否真实解决及事实、证据、知情边界、人物关系与结果是否保持；作者自评、变更表勾选或删除原标签不算证据。通过后修订稿才成为当前活动正文，实质修改使 `script_rev +1`；未改且不受影响的场次不重审，缺件范围保持未核阻塞。

### 第 3.8 步：合规初核关（调「素弦」，先于终审 · 模式可选，用户可关）

> **顺序铁律（v6.8.2 定版）**：素弦在前、季衡在后——季衡红线第 7 条（合规）**以素弦报告为判定依据**，若素弦后置则季衡无据可采，构成流程循环。合规初核先行，季衡终审时直接采信，消除环。

- **触发**：全稿（或本批）完成第 3.7 步及必要的改动场局部复核后、季衡终审**之前**跑 1 次（与终审同批连续执行，不单独增流程）；涉 IP 改编、敏感题材（未成年/民族/宗教/现实事件）时**不可关**。选「直通交付」且无敏感题材时可跳过。
- **下发前**：Read `references/role-cards.md` 取素弦角色卡；把待审稿原文 + 已定平台 + 题材一并下传。
- **产出**：合规核查表（题材边界/平台审核差异/IP 授权/实际内容与视听方向/政治民族未成年红线，依据适用规则逐项判断，不机械换词）→ **立即落盘 `{项目名}_05合规报告.md` 或既有验收记录的合规章节，并展示实际原文**。
- **出口**：五项全过 → 合规报告原样传入第 3.9 步季衡终审；有红线项 → 回文茵按修改建议改（只改合规点，不动剧情骨架），改后素弦复核通过再进终审。

### 第 3.9 步：总编终审关（调「季衡」，≥90 放行；88-89 符合 3.10 条件可带条件放行，模式可选，用户可关）

**审查范围**：用户本轮只要求梗概、季纲或集纲审查时，按该层实际材料核故事、因果、人物、承诺与阶段回报，结论明确限于该层；未授权生成的正文不算本轮缺件，也不得声明对白、成片时长或完整正文终审通过。约定应有而缺失的纲级依据仍标未核；已承诺的正文交付不得借此降为纲级审查。

**质检节奏（第 0 步继承已有设置或使用相容默认建议，用户可指定；不因展示功能而要求逐项选择）**：

| 模式 | 触发 | 适用 |
|---|---|---|
| **全稿终审（默认推荐）** | 全部剧本写完后跑 1 次 | 24-40 集、一口气写完的项目——**剧本没写完不质检**，中途只推进度不打断 |
| **分批质检** | 每 N 集一批（建议 10-20 集一批，如 60 集剧每 20 集 1 次，全剧 3 次） | 60 集以上长篇 / 边写边改多的项目——早发现问题早返工，避免最后推倒重来 |
| **直通交付** | 用户明确说「直接交付 / 不用质检」 | 赶时间、试写、草稿——跳过本关，交付稿注明「未终审」 |

> **不为流程而流程**：默认不跑中途审——批量续写时质检节奏只在第 0 步确认一次，选定后各批次按约定执行，不再每批追问「继续写还是先质检」；只有用户主动改模式时才变。用户说「继续」就一直写到全稿完成再统一质检。前 10 集/中后段/终稿的分窗打分只对**选了分批质检**的项目生效。

- **触发**：按上表选定模式；用户说「直接交付」即跳过本关。
- **终审前目录唯一性核验（主理人机械项，不调子 Agent）**：把终审评分报告落盘前，核对当前交付范围——①同一产物用途与覆盖集段不能有两份互相矛盾、均被标为活动真源的版本；②「最终/final/副本/汇总」字样只提示核对用途，不按文件名判废；③标准剧本正文、投稿派生稿、分批工作稿及明确标为历史的版本可合法重叠，需能辨认来源、版本和用途。疑似冲突先标注并查明真源，不自动删除、移动或重命名；处理遵循宿主文件安全规则。核验结果一句话留进终审报告头部（`目录核验：活动真源唯一 / 存在待核冲突：具体文件`）；未消除的活动真源冲突不得交付。
- **下发前**：Read `references/role-cards.md` 取季衡角色卡，并把本节「审查范围」原文随任务下传，按本轮授权材料适配模板：纲级只下发适用的故事/因果/人物/回报核查，不下发正文专属门、正文预检或完整正文评分任务；正文终审**必读** `references/review-scorecard.md`，把对白硬度门与 8 维评分表原文贴进模板；下传当前待审正文、对应集纲、必要前文事实，以及青梧报告中明确的已核/未核范围、冲突清单和 3.7 局部复核结论（若有）。季衡只信任青梧实际审过且有文本证据的范围；材料不足、未核范围与未解决连续性/功能缺陷继续阻塞，不把局部通过外推全稿。
- **产出**：终审评分报告（对白硬度门 + 8 维打分表 + 8 条红线逐项 + 总分 + 五档裁决 + 返修指令表）→ **立即落盘 `{项目名}_06终审评分报告.md` 或既有验收记录的终审章节，并展示实际原文**（用户可见分数与返修点）。
- **门槛裁决**：对白硬度门先过，才计算放行。唯一分档见 `references/review-scorecard.md` §3 与下述 3.10：**≥90 放行交付**；**88–89 仅阶段批可带条件放行**（仍有下一批+未闭环项全为台词级/微调+已并入下批指引+无结构/红线问题）；终稿先修复当前范围再复核。80–87 文茵返修 → 季衡复审（核对返修项、重打受影响维度并复核可能触及的红线）；**<80 回上游**；**红线命中任一条总分封顶 84 强制返修**。对白硬度门未通过时按改动影响退修：纯表达回 3.7，承重事实问题回相应剧情层，**不得用其他维度平均放行**。
- **分数留痕**：各窗分数写进账本进度头旁（`终审分：批1 92｜批2 88→94｜终稿 95`），跨会话可查。
- **深度质检与停止条件**：不自动调用额外 Skill；用户明确要求独立深度诊断时，其结果只作返修输入。按 review-scorecard §8，同批自动返修最多 3 次，包含红线红灯；到限仍未满足放行条件则停止改稿并上报，缺陷继续阻塞，不自动降标。派单按改动对事实、证据、知情、关系与结果的影响分责任层，不按字数；表达问题归 3.7，承重事实问题退相应剧情层。

### 第 3.10 步：终审合并（主理人 · 不再单设素弦后置关）

- 原「终审放行后再跑素弦」的 3.9 后置关取消——合规核查已前置到 3.8，季衡终审时采信其报告。
- **门槛裁决**：唯一分档按 `references/review-scorecard.md` §3：≥90 放行；88–89 仅在全部条件成立时允许批次条件放行；80–87 返修复审；<80 回上游；红线命中封顶 84。**终稿没有下一批，不得用「并入下批」延期交差**；当前交付范围的未闭环项先修复并复核，条件放行也不能绕过对白硬度门或确定性错误。
- **审核记录交付**：主理人引用合规与终审各自实际原文，可在同一验收文件分区保存，或引用既有独立报告；不复制成新汇总报告，两报告结论冲突时**合规优先**。

### 第 4A 步：唯一标准剧本交付

1. Read submission-format.md，按 §4a 从起稿到定稿维护一个活动标准正文，沿用用户确认路径；环境、站位、道具、动作、微表情、眼神与反应自然融入。场首前一至两句建立当下空间，尾首成对承接。禁止五字段清单与每场固定节拍附段。
2. 梗概、人物档及基础视觉事实、粗纲、逐集集纲、规则、正典与审核记录在已有配套位置维护。完整项目核全季既定资料，局部任务核影响范围；不因只交首集删后续核心人物，不把这些资料重新塞入正文。
3. 在已有交付/状态记录登记正文路径、script_rev、SHA-256、实际审核范围与 review_state、时长目标和用途。正文修订同步受影响资料；历史双稿按 submission-format §2 安全迁移，不保留两个活动真源，不覆盖旧资料。
4. 按 submission-format §6 运行单文件 body-only 预检并读取必要配套资料；格式通过不代替剧情复核。标准模式交付须完成适用的 3.7 精修、连续性、合规与终审；用户明确直通时标 unreviewed，不伪造报告或 reviewed。
5. 进入制作时交相同正文及必要设定/人物/集纲、实际启用或继承的正典/世界观、真实存在的报告与版本记录。命中特殊场面时，原正文与必要资料须交清实际参与者及职能、对象/器具、过程或阶段、回应、前后状态和披露边界；Studio 自主设计表现，不为装配发明胜负、能力、病因、历史关系或揭示时机。标准交接核终审和合规；直通交接明确未终审，不补空报告。Studio 不要求改回内部母稿。仅在用户要求进入制作时按已选范围交接，不默认试演、试剪或生成媒体。
6. 写成 Markdown 并展示可达文件；不默认 DOCX/PDF 或第二份阅读稿。交付清单按 §7 实际需要记录，不为固定件数造空文件。

### 第 4B 步：按需格式导出

1. 用户或接收方明确要求 DOCX/PDF、专用模板或策划附件包时执行；普通阅读、投稿和制作直接共用标准正文。
2. 从已核对正文导出并登记源版本/哈希，不改变字义。发现内容问题先改唯一正文并同步影响资料，随后重导出；格式与内容修订分开管理。
3. 专用模板优先，默认格式见 submission-format §4a/§5；不得虚构正式编号、审批状态或联系人。文档渲染核版，无法渲染明确未完成视觉 QA。
4. 默认单文件检查；只有明确核历史双稿才调用旧成对接口。完成交付后按宿主实际团队能力结束临时协作，不创造额外剧本副本。

## 调整规则（改细节 / 换题材怎么改）

| 想改什么 | 怎么做 |
|---|---|
| 换题材/风格/受众 | 从头重跑：新设定填进第 0 步确认行，重走阶段 1（**简报若仍在同一题材同一季度内可复用，不必重搜**） |
| 只改剧本细节（某集卡点、场次、台词） | 不用重跑全流程：把现有集纲/剧本原文 + 修改要求发给文茵；若标准剧本正文已锁版，必须在唯一活动正文修改并令 `script_rev +1`。纯表达问题走 3.7，承重事实问题回相应剧情层；按影响面重跑青梧局部复核及必要的素弦/季衡门禁，同步受影响配套资料；确有格式导出时再重生成 |
| 只改按需导出文件的字体/分页/缩进/标题层级 | 只在第 4B 步修改派生视图，不改活动正文、不增加 `script_rev`；保存后重新逐页渲染检查 |
| 在导出文档里提出台词/动作/剧情修改 | 回唯一活动正文修改并提升 script_rev，核对影响资料与局部审核后重导出；标准 Markdown 本身就是可直接修订的真源 |
| 改分镜/提示词细节 | 制作侧已拆分：交接后一律归 `drama-studio`（镜头号+修改点发制作侧），本团不再处理 |
| 续写后续分镜 | 同上，归 `drama-studio`（传 reuse_asset_ids 复用资产） |
| 逐集续写完整正文 | 见 `references/canon-ledger.md` 批量续写固定下发模板：硬设定+账本+上一集结尾+集纲对应行；**批次粒度 10-20 集/批按体量自适应（≤24 集可单批，60 集+每 20 集一批，与质检节奏对齐，不建议 <5 集/批）**；文茵随批交账本增量，**增量随批单独落盘 `{项目名}_增量_E{起}-E{止}.md`（唯一口径，禁内嵌正文尾部）**，账本合并按 canon-ledger §2 唯一口径：质检批青梧合并并核冲突，非质检批主理人直接粘贴合并（与第 3 步批后核查段同口径） |
| 用户给了新的创作灵感 | 保留原文与来源，按当前职责下传命中片段，并区分明确冻结要求、候选建议与方向示例；明确调整按用户新要求执行，示例只迁移其叙事功能，先核既有事实、人物成长与能力条件，不自动升格为硬设定，也不为已明确的授权重复提问 |
| 怀疑选题过时 / 想换赛道 | 重跑阶段 1：风聆重新检索出「当期风向 vs 现有选题」对比，纪遥判定保留/改造/推翻；改造只动选题层（人设、钩子、情绪主线），集纲按新选题局部返修，不推倒全文 |
| 替换角色名 | 按 `references/naming-rules.md` 依据时代、地域、家庭与辨认成本给 2-3 套候选，用户选定后**全链路统一替换**：成稿 md、正典账本、制作侧资产锚定表同步改名，账本补一条「改名记录」，不得只改一处 |
| 想加/换角色 | 先对照 `references/role-cards.md`「角色增减规则」：只有两项职责在能力上互斥才加角色；仅为细分工作量不加。新角色必须有角色卡（定位/必做/不做/交付/失败判定） |
| 终审被打回 | 按季衡评分与责任层处理：**88–89 仅在符合 3.10 全部条件时可带条件放行**；其余 80–89 回文茵返修后季衡复审；<80 或红线命中回对应责任层（选题/集纲/正文）重做，返修后重跑评审，不得绕过终审直接进分镜 |
| 跨会话承接旧项目 | 按 `canon-ledger.md` §4 读取现有进度入口与当前真源，区分已写、已审及审查版本；有账本时调青梧核对命中状态再续跑，尚在策划阶段不强建正文账本 |

## 避坑清单
- **接稿与方向确认**：第 0 步默认配置引导，信息足够不追加接稿弹窗；需澄清时只问当前缺项。开放选题仍在阶段 1 后展示候选并请用户定方向；已有稿/快写不补开选题。跳过引导不跳方向关，已有合法代选授权按授权执行。制作侧主要资产确认归 drama-studio。
- 配置展示、默认值及其适用范围以第 0 步与 `references/startup-guide.md` 为准；已锁载体优先，未知保持 `carrier=pending`，只有差异会改变当前决策时才确认，建议不得混入已确认硬设定。
- **禁止凭训练记忆判断市场风向**——风聆必须先联网检索，简报必须带数据基准行与信源。
- **禁止自审**：长篇的知情穿帮/道具/伏笔/同构/AI味核查交青梧，不由文茵自查、也不由主理人代查。
- **禁止让一个角色同时干检索与构思**（风聆/纪遥必须分开）、同时干写作与核查（文茵/青梧必须分开）。
- **制作输入状态明确**：阅读与制作共用唯一标准正文；标准交接标实际 reviewed，明确直通标 unreviewed。候选与历史稿不得冒充当前有效正文，状态记录在配套交接中。
- **审查两层不合并**：青梧查连续性「对不对」，季衡查质量「好不好」；只有用户明确要求才另用独立深度诊断工具，不让长篇终稿自动多出一套评审。
- **合规独立于质量**：素弦查「违不违规」；标准交接未过合规关不得标 `reviewed`，素弦与季衡意见冲突时合规优先。直通交付不伪造合规结论；涉 IP 改编/敏感题材时合规关不可跳过。
- **研究补给按问题分流**：细分赛道未覆盖才做整赛道资料包；单一对白/镜头/职业/地域缺口只做定向补项。两者按材料性质先查本地：方法理论查 `screenwriting-library.md`，项目作品案例查共享案例索引；定向补项不设固定搜索/样本配额，不为补一个点新增全套研究阶段。
- 下发前未 Read 对应角色卡 = 违规；角色卡须放在 prompt 开头，任务在后。
- 子任务名保持中性；视频投喂正文不出现第三方视频模型名。配置卡、能力说明和请求参数如实显示目标模型，方便用户核对。本机 MiniMax H3 的 11/20/21/30 画布号由 Studio 按输入材料选择（`drama-studio/references/h3-comfy-mode-routing.md`）；Crew 不指定工作流号，不把「默认文生/11 号」写进剧本或交接。
- 涉及已有 IP 改编时提醒用户确认授权。
- 角色名全链路锁定（选题→剧本→制作侧资产锚定表），任何成员不得擅自替换已确认定名。
- 专项规范一律从 references/ 按需加载并粘贴进下发模板，不把规范全文堆进本主文件。
- **经验库必须转起来**：任何成员产出被用户修改/纠正、用户要求吸收外部案例，或定向补项取得新材料后，顾临按 `references/learnings.md` 形成入库候选并完成项目适配与相称核验；**只有用户明确说「记住/写入经验库」或确认条目时才持久化/升格**。重复来源优先补全共享 metadata 的既有 ID 与未核状态，不另造索引；低置信或待讨论不自动作为生产或终审规则下发，不因一次搜索自动 push。
- **工作历史与清理**：候选、未合并增量、原始来源和审核证据保持可达，活动交接只引用需要的文件；正文与配套按 submission-format §7–§8 管理。批次/阶段可审计本任务缓存，删除须核来源、真实依赖与已有授权并按宿主逐文件执行；不凭后缀、文件旧或不在正文判废，不跨任务代清。制作资产按 Studio file-management 管理。
- **世界观档案按需建（触发口径以 `references/world-bible.md` 头部唯一口径为准，只引用不复述）**：地点/时间/规则/势力等世界事实承重时，按复杂度建完整或轻量版；实际低风险且无既有资产时可免新建。题材、集数、快写和预览只调整展开/拆并，不免除承重事实核查；上游已有世界观档案、时间线或专业边界时必须继承命中片段。交接块是否包含世界观档案按实际制作与连续性风险判定，不以固定第五样齐套。

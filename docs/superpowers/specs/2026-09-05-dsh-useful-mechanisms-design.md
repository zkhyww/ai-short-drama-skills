# DSH 有效机制轻量吸收设计

## 目标

从本机 `@oh-story/dsh` 的短剧 Skills 与模板中，只吸收能够解决现有真实缺口的创作和制作判断机制，同时保持 `drama-crew` 与 `drama-studio` 的既有角色、阶段、确认点、交付物和投稿格式不变。

## 边界

- 不复制 DSH 模板原文，不把其十 Skill 架构、Dashboard、五文档系统或 JSONL 工程带入仓库。
- 不新增角色、流程关卡、用户弹窗、评分维度、交付文件或独立数据系统。
- 不采用 DSH 的内部 `EP/SC` 编号替代团队现有制作母稿与标准投稿阅读稿。
- `OS`、`VO` 继续服从火山引擎「剧创」口径：`OS` 是角色内心独白，`VO` 是画外音。
- 参考素材只迁移功能和判断机制，不复制受版权保护的具体表达或示例。

## Crew 侧增强

1. 在世界观现有六模块中补“机制真实契约”和“剧中披露状态”两层判断。系统、重生、先知、科幻能力必须区分：世界真实如何运行、人物与观众当前知道多少。
2. 在去同构与反 AI 味现有章节中补三类诊断：机制耗尽后的收束/改造/移交；信息密度过匀；代价在本集即时结清。它们只在证据命中时触发，不成为逐集配额。
3. 增加轻量声音戏剧方法：承重声源、主动留白、撤出/恢复和声桥。Crew 只写戏剧功能，混音参数仍归 Studio。
4. 正典知情判断采用三步证据链：可见/可听载体 → 载体直接支持的最强结论 → 尚未证明的推断。
5. 只把上述判断接入现有文茵、青梧、季衡职责和既有评分项，不新增检查清单编号。

## Studio 侧增强

1. 参考资产增加三种可执行状态：`prompt_only`、`file_ready`、`external_mount_plan`；身份与状态变化用 `reuse/new_variant/new_asset/unresolved` 决策。未命名且只承担人数或声势的群演不单建资产。
2. 修正镜头修订血缘：同一叙事职责内改构图或调度，保留 Shot ID 并提升修订号；拆分、合并或改变叙事职责时才建立新 Shot ID，旧 ID 停用。
3. 首帧只写生成开始时已经成立的事实，尾帧只写目标终点；运动过程留在时间线。实际视频或实际尾帧续接只在本次 provider 能力支持时启用。
4. 同一句对白、OS 或 VO 的逐字正文只出现一次；视觉时间线只标说话人、口型、时段和动作，不重复台词正文。
5. 在现有镜头卡内用 `show_now/withhold_now` 标记悬念信息的当下权限，并写清载体、释放触发和遮蔽方式，不新增 Schema 或独立文件。
6. 表演规则改为按承重程度裁量：完整表演要素只用于承重台词；情绪弧不固定七拍或顺序；背景人物不要求人人错峰反应；微动作数量和秒数只作模型风险诊断。

## 模板取舍

DSH 模板可作为方法来源，但不作为运行时模板库整体导入。吸收参考素材控制边界、观众信息权限、镜头修订血缘、资产复用判断、首尾状态投影和群演成本门；六张媒介形态卡与单次生成观察仅作项目级参考，不能自动升格为所有模型的普遍能力。

## 验收

1. 新合同测试先在旧文本上失败，再在修改后通过。
2. 既有完整回归、原生 Skill validator、Markdown 围栏与本地引用检查、`git diff --check` 全部通过。
3. Markdown 文件数只因本设计与计划文档增加，两个 Skill 包内文件数不变。
4. Diff 中不得出现 DSH 原文、私有模板、用户资料、密钥或新的交付体系。

# 台词表演化精修与双轨成稿设计

## 目标

在不新增角色、不增加用户确认点、不触碰现有三部测试剧本的前提下，解决 `drama-crew` 容易把对白写成等长短句、证据宣读和程序化问答的问题，并在终稿后同时支持内部制作与对外阅读。v6.17.1 允许对 `drama-studio` 的人物资产入口做最小跨包同步，以闭合视觉事实到生产锚的接口。

## 根因

现有规则把“短、快、有效”落实成了逐句硬要求：单句十五字、每句必须推进、对话必须走位、沉默必须配小动作。这些规则单独看都在压缩废话，叠加后却会让人物永远准确、完整、理性地说结论，语气、停连和思维转折被抹平。终审又允许其他维度的高分平均掉关键场对白过硬的问题。

## 设计

### 1. 对白判断单位

把判断单位从“每一句话”提升为“一个对话回合或表演节拍”。一个节拍整体需要推动信息、关系、情绪、力量或选择，但其中可以存在接气、迟疑、改口、抢话、答非所问、自我纠正和未说完。十五字只作为一口气承载过多信息时的诊断提醒，不作硬切线。

专业信息不得由角色在无压力、无阻力的情况下完整宣读证据链。信息应按戏剧需要分散到道具、动作、追问、质疑、纠正和他人反应中；确需长段陈述时，必须符合职业与处境，并有明确行动目的和节奏变化。

### 2. 台词桌读与表演化精修关

沿用文茵，不新增第九个角色。正文完成并经青梧连续性核查后，文茵执行第 3.7 步：只修改对白、标点和相邻微动作，锁定剧情事实、证据、知情边界、人物关系、结果、目标时长与季终悬念。

精修按场检查说话目的、对手压力、一口气意图、承重词、停连、语速变化、强弱变化、音高走向、气息和句尾落点。只在承重台词上写必要表演提示，不把每句都标成配音参数，也不机械添加语气词或小动作。

文茵返回完整修订稿和精确变更表；青梧仅复核发生改动的场次是否破坏事实与知情边界。默认全稿终审项目全稿执行一次，分批质检项目随质检批执行，快写预览在原写作任务内做轻量自检而不另起关卡。

### 3. 终审硬度门禁

季衡仍使用原有八维评分，不增加新分数。台词质量维前增加“对白硬度门”：开场、重大转折、证据揭示、关系摊牌和季终等承重场中，只要仍存在连续的程序化问答、全员同腔、无阻力宣读证据链或句句完整解释动机，就不得用其他维度平均放行，先退回文茵做局部精修。

### 4. 双轨成稿

- `完整制作母稿.md` 是唯一内容真源，保留版本锁、梗概、人物档案、粗纲、逐集集纲、场景五字段、动作节拍、时长与制作所需标记，并继续交给 `drama-studio`。内容修改必须在同一 `script_rev` 内同步受影响的前置章节。
- 用户或接收方已指定载体时照指定执行；未指定时，投稿、送制片人或对外阅读且 DOCX 工具可用时默认生成 `《剧名》_投稿阅读稿.docx`。Markdown 只作中间稿或工具不可用时的降级载体。
- 投稿阅读顺序为封面、一句话卖点、故事梗概、主要人物、粗纲、逐集集纲、正文；选题分析只作按需策划附件。
- PDF 仅在用户或接收方明确需要时生成。
- 投稿稿不生成或预填许可证号、批准文件编号、节目编号及审批结论。接收方有专用模板时再适配。
- 投稿稿记录来源 `script_rev` 与母稿 SHA-256。任何内容修改必须回到制作母稿升版、重审，再重新导出；投稿稿不能演变为第二真源。

完整终稿默认生成制作母稿；用户表达投稿、送制片人、对外阅读、交平台编辑或需要可阅读成稿时生成投稿阅读稿，不新增确认弹窗。用户明确要求完整项目双份交付时同时生成。分批写作阶段不反复生成早版投稿稿。

### 5. 人物视觉事实到生产锚

- crew 的 ≤40 字人物视觉锚定行只锁定基础视觉事实，不承诺单独满足出图参数。
- studio 丹青逐字继承这些事实，再补足 ≥3 个稳定结构轴、其中 ≥2 个脸部结构、8-12 个视觉词与 forbidden 3-5 项。
- studio 补充项标 [制作设计/推断]，不得覆盖 crew 事实；最终生产锚通过身份区分门后才能进入资产生成。

### 6. 诊断规则不机械化

沉默、人物突变与正向人声策略都按语义与因果裁决：沉默重复且没有新增压力、关系或含义才钝化；人物突变四项可跨场分布或隐含；口误、错名和身体反应只在人物与处境有依据时使用。红灯 #14 只核时长结构，#15 只核未铺垫外力、主角行动、代价与因果铺垫。

## 非目标

- 不重写或排版现有三部测试剧本。
- 不新增角色、评分维度、用户弹窗或制作侧流程。
- 不复制图片中的十五维评分体系，不引入第二套 AI 味分数。
- 不承诺任何投稿平台、审批机构或发行方一定接受通用排版。

## 验收

1. 原有四条逐句机械规则不再是执行合同。
2. 第 3.7 步在主流程、文茵模板、青梧局部复核与季衡门禁中完整接线。
3. 双轨成稿有唯一真源、无歧义载体路由、阅读章节顺序、字段映射、通用 DOCX 排版和版本溯源。
4. crew 基础视觉事实与 studio 生产锚职责闭环，#14/#15 不再串用判据，沉默/OOC/人声策略不按固定次数机械返修。
5. `drama-crew` 升为 v6.17.1，`drama-studio` 升为 v1.11.2；Markdown 文件数保持 18/27，README 与 CHANGELOG 同步。
6. 语义回归、Markdown 围栏、本地引用和 diff 检查通过；原生 validator 与打包器仅在仓库或环境提供兼容工具时执行，否则如实记录限制。

## 5. 提示词检查器

### 5.1 输入、入口和输出

新增 Studio `scripts/validate_prompt.py`，使用 Python 标准库，只读检查，不改正文、不联网、不生成媒体。

检查对象是一份最终 Clip 提示词原文。可读取当前任务已有的总时长、锁定发声条目、实际参考清单及版本信息作为对照；不要求用户再维护一份独立真源。没有结构化对照时只运行有依据的检查，其他项明确记未核。

正式 Studio 视频流程在装配自检中自动调用。Dreamina 视频预览增加 `--prompt-file` 输入，与原 `--prompt` 互斥：文件入口用于 Studio 八段最终正文，检查通过后把同一原文传入现有预览。原 `--prompt` 保留普通提示词兼容，图片命令不接受视频八段检查。其他模型可单独使用检查器，不强制经过 Dreamina。

结果包含检查覆盖范围、错误、警告和未核项目，各项带稳定代码、原文位置及原因。终端默认简短输出，可按需输出机器可读结果；不默认保存额外报告。退出码 0 表示已执行检查未发现错误，仍须列明缺少对照而未核的项目；1 表示存在确定性错误；2 表示输入不可用或必需结构未能解析。仅通过部分检查不得写“整条提示词已验证”。

### 5.2 程序负责的确定性检查

- 八段标题、顺序、重复、遗漏和空内容。接受正式中文标题及已记录的英文等义标题；“无/NONE”按本段实际用途合法，不新增第九段。
- 顶层镜头时间线：起点、终点、倒序、空档、重叠和实际总时长一致；动作节点不能误算成新镜头。一镜到底的内部时间节点不自动视为剪辑。
- 声音 ID 的重复定义、未定义引用、声窗超出 Clip。相同台词被不同 ID 合法复述不因文字相同判错；明确合唱、抢话等允许并行，不套逐句顺序播放。
- 有锁定逐字发声对照时，比较角色、类型、顺序和原句；不擅自改拼写、语气词、数字或语言。没有对照只能核结构，不能认证“未改词”。
- 有实际参考清单时，比较引用与本次输入的对应关系；文件不存在、无对应项或明确引用错误才拦截。不把文字资产 ID 当媒体句柄，不把文件存在写成已上传或内容正确。
- 概述明确给出的镜数/总时长与可解析时间线一致。人物动机、道具生命周期、光向、风格和因果等语义判断仍留原装配自检及独立核查。

不能可靠解析的写法须指出具体未核位置，要求当前执行者补明确的结构或人工复核；不猜测后发“通过”。批量提示词文件只按可明确定位的 Clip 分隔；无法判定正文边界时不自动截取一段冒充最终正文。

### 5.3 不作为通用拦截条件

不设每镜固定时长、镜数或招数，不一概拦硬切、静止、首尾帧、30 秒、相同镜长或无对白；不以字符数推断审美、传播效果、真实口型或视频成功率。普通对白和演唱的估时分开，估算风险不是已观看证据。

格式语言与对白语言分别继承目标配置。默认标题口径与用户明确要求的英文 Prompt 均可成立，不能因中文标题改写英文台词。仅案例使用英文或某个时长，不改变目标项目设置。

## 6. 方法补强及 Crew → Studio 联动

### 6.1 动作与法术

将具体方法写入现有选择表，每行回答：什么问题适用、可选表现、需要哪些已定事实、结果在哪里可观察。保留一条主路径，其他方法只解决不同缺口，不要求每场齐套。

动作侧补清：闪避/格挡/卸力等不同应对、重击的接触与受力反馈、击退后的距离和路线、追击的阶段状态、群体焦点与各参与者持续位置、终局及余波。终局不自动增加死亡、伤损或胜负反转；无伤训练和轻触按既定强度处理。

法术侧补清：拦截、偏折或抵消的结果差异；束缚与解除；持续领域的边界和内外影响；法器实体与派生效果的数量、控制关系和去向；多阶段变化与收束。触发、作用范围、代价与结束条件以正典为准，不默认所有法术需要法器、消耗、五行或环境破坏。

Crew 正文写出目标、实际选择、必要回应及阶段结果，规则场还要让已批准的触发、作用和边界可理解。Studio 据此设计参考、调度、摄影、声音与效果。表现方法未写明时自主设计；承重事实缺失时仅退依赖项，不用案例补故事设定，不凭题材标签升级破坏规模。

### 6.2 空间、亲缘与表演

- 空间选路先看既有地标/Panel 是否足够，再判断是否需要补反向视域、俯视调度或白模预演。单人镜面、环形路线、穿越遮挡也可能高风险；多人普通对话也可能无需新图。预演仍遵守既有工具和授权条件。
- 亲缘视觉只在关系已确认且需要体现时使用：继承已锁共性，补足真实可辨的个体差异。不设相似百分比，不以外貌推断亲属，不要求情侣、师徒或同阵营长得像；揭示前避免视觉提前泄密。
- 表演先核当前景别和遮挡，再选可见反应；背影或遮脸不硬写可见瞳孔/嘴角。闭唇、饮用、咀嚼等与清晰说话发生执行冲突时调整时间或镜头，保留原对白；正常微笑着说话、哽咽发声等不被机械禁止。易混情绪先按刺激、对象与行为结果区分，不用 AU 或肌肉百分比诊断真实心理。

## 7. 资产作业清单、可视图册与按需只读看板

### 7.1 同源的本批作业清单

丹青从当前剧本和既有资产记录识别本批所需人物、场景、道具，再按现有规则选择复用或窄补。判断仍由制作职责完成；展示脚本不声称能独立理解剧本、补齐事实或决定如何拍摄。

本批清单在已有索引／复用说明和交付入口中呈现，不另建一份人工维护的 JSON 台账。每个工作项说明：资产 ID 与名称、所需图种或文件＋Panel、具体用途、覆盖集／Clip、引用的已批准来源、真实视觉缺口、前置依赖、当前下一动作。身份决策沿用 `reuse/new_variant/new_asset/unresolved`；文件就绪沿用 `prompt_only/file_ready/external_mount_plan`，另保留原有候选／采用状态。这些字段对应现有职责，不重新定义资产身份。

同时回显“本批需用的独立参考数、直接复用的已有文件、本轮计划新制文件、尚未解决的依赖”。一个总表文件可承担多个资产 Panel，按文件去重统计；身份未变但要补细节图时仍可为 `reuse`，不能据身份判词直接计算新文件数。仅有规划不显示已完成张数。

顺序按真实依赖安排：已批准参考先复用；需要新建的角色／空间／道具参考先落实其最低必要输入；人物关键构图在对应身份参考和调度就绪后制作；按集总表组装已选材料。场景区也可直接在总表中首次实现，不新增“必须先有独立场景母版”的前置环。不同用途的工作项不强制固定角色→全部场景→全部道具的批次顺序。

实际生成仍走原工具、预算与资产确认规则；作业清单不是调用授权。在已有授权内执行后，读取真实结果、分别做技术与内容核验、更新原索引与受影响引用，再刷新展示。失败只隔离依赖项；远端状态未知先查原任务，不能由看板按钮重复提交。

| 武器握持、结构或破损状态难辨 | 按原 PROP_ID 补交互面／握持比例／状态细节 | 不因新文件创建新道具身份 |
| 连续动作、接触或复杂移动无法由现有参考说明 | 按既有条件使用动作节点或预演 | 静态图不冒充连续运动已验证，不自动调用建模或付费工具 |

保留一人一份独立参考、完整全身三视图、按实际出镜故事角色配板、总表 Panel 可承担场景／道具职责、英文项目适配和八段视频格式。简单资产请求不需要整剧清单、分镜、总表或 HTML。

### 7.3 可视图册与离线看板

图册是已有资产交付的可视视图：每项展示实际图片、资产名／用途、版本与采用状态、对应原文件／Panel、出图提示词入口及已有镜头引用。多项指向同一总表时共享一幅预览并分别标注区域，不复制媒体文件、不伪造区域裁图。未生成、未挂载、缺失或不支持预览的图片明确占位；仅有提示词不能显示成图片已交付。图片展示也不构成新的内容验收。

新增 Studio `scripts/build_production_board.py`，采用 Python 标准库，把本次明确指定的既有资产索引、分镜和提示词导出成一份本地静态 HTML。页面按“本批作业与未决项→可视图册→已有分镜→分别可复制的图片／视频提示词”组织；无该类输入就省略对应区，不补空文档。保持系统字体、清晰状态、键盘可操作和窄屏可读，不引入前端框架、服务或数据库。

工具只读明确输入；资产字段识别先支持现有 ID／类型／文件路径及显式状态，缺用途、依赖或镜头对应时标未记录，不从文件名或提示词子串猜关联。旧格式不能结构化解析时保留原文或来源入口与具体警告，不静默丢记录、不要求用户另抄一份专供看板的资料。输入适配在工具内完成，不能为出看板批量迁移资产索引。

看板保留生成时刻、来源文件哈希及已有版本，明确是快照；源文件或采用版本变化后重建，旧审核不自动为新版本背书。默认只更新原任务交付入口的作业清单／图册；用户要求或多资产／多 Clip 交付确需集中浏览时再生成 HTML，不能为了“使用新功能”让每条 Prompt 都附一页看板。

### 7.4 提示词隔离与输入边界

图片词与视频词分别引用原位置、分别复制。第一版接受明确指定的单条纯提示词文件，或现有文件中已有、可确定起止的正文片段；不要求固定标题语言或代码围栏。混有评审、说明或多条边界不明时，展示来源但不提供冒称“最终 Prompt”的复制按钮。明确单条正文即使尚未审核也可复制，旁边如实标状态，不改写或擅自修复。

复制保持源正文，不带来源、清单、案例说明、状态徽标或检查报告；剪贴板不可用时提供明确失败提示和可选中的只读原文。看板不把正文存回源文件，也不成为另一份活动提示词。

所有外来文字转义。只读取明确指定的文本输入和其中明确引用、落在已声明允许目录内的本地图片，不递归扫描目录、不读取凭据、不自动下载或上传。拒绝脚本式链接、设备／网络路径和解析后越界的符号链接；已引用的外部资产目录需显式纳入允许范围，否则仅说明未加载，不能当成图片不存在。

预览仅加载实际本地栅格图片，不执行 SVG／HTML 等活动内容，不复制图片、不把媒体打包为 Base64。页面禁止外联请求，图像策略只为已检查的本地预览开放；不得沿用旧计划 `img-src none` 却声称能展示图片。输出不覆盖输入，覆盖已有看板须显式指定。离线 HTML 引用原图片，在本机离线可看；不是搬走一个 HTML 就包含全部素材的交接包。浏览器不能加载本地图片时给出原路径和未加载状态，不绕过宿主限制。

### 7.5 本轮验收目标

同一份索引能给出一致的作业清单、图册和看板；正文复制无管理信息；复用和新制文件不混计；未生成或丢失的图片不冒充完成；未批准／被替代版本不自动成为当前输入；简单任务仍保持轻量。看板只展示真实状态，不生成图片、不排队付费任务、不替代内容审核。

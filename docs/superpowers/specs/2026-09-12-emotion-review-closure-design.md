# 跨题材情感与审核闭环：已批准设计

用户于 2026-09-12 确认施工；本文件只记录已确认范围，不新增审批环节。

## 目标与边界

所有题材都要有人性、欲望和情感承载，浓度按项目规划决定。情感不等于恋爱或 CP，呼吸只是节奏功能；情感可以承担主引擎、高潮、钩子或单集回报。爱情明确为主线的项目，不能长期用无关事业进展代替爱情承诺。跨题材借鉴偏爱、被理解、特殊信任、双向选择、尊重与共同承担，不搬豪门身份、强制误会、嫉妒或固定男女队形。

独处或单人项目也可通过牵挂、记忆、归属、羞耻、希望及实际选择承载情感，不为套双向互动而增加人物。七情六欲是人性来源，不是必须逐项填满的清单。

同时修复真实正文未进入审核的交接缺口，以及前轮明确列出的独立冲突规则。空转、重复首次兑现、虚假结果宣告、因果矛盾必须实际核查、按责任层返修并重读修订落点，不能只删除标签或接受作者自评。

## 不变量

- 原规则位覆盖、合并或替换；移除被取代的冲突旧口径，不追加补丁章。
- 正式 Skill 只放通用方法与接口；创作样本、原始测试回答和对比证据保留在独立私有 QA。
- 全季人物无固定人数；既定核心人物同等叙事深度，按当前任务读取而非删除档案。
- 60–90 秒短集每集有成立的爽点或实质反转，默认约半分钟有效反馈；不精确卡秒、不要求每集独立感情场。
- `romance_axis=on|off` 只表示恋爱线；未定项用自然语言说明，不造枚举、不默认 off。
- 审核缺材料应说明实际已核范围与未核范围，不能默认无问题；青梧与季衡仍分层，不重复全量审计。
- 3.7 精修不新增证据、能力、关系、结果或其他承重事实；结构问题回剧情层。同批自动返修最多三次，未解决继续阻塞。
- 世界观、正典与制作资产按承重风险启用，继承既有事实，不以集数、预览档位或主配角名称免核。
- 保留模型与媒体验证、发布与预算授权边界；不因账号是仓库 owner 自动推送。
- 本轮不恢复双剧、不生成媒体、不关机、不合并或推送；同步已验证的正式安装副本时保留本机路由与私有绑定。

## 验证标准

1. 修改前旧规则作为无新增指导对照；新旧各至少五份 fresh-context 同输入消费，人工核实际产物，不以规则复述判通过。
2. 覆盖无恋爱但关系承重、明确爱情主线、短集关系回报、既有状态不可重复首次、审核缺正文、物理因果、预览风险继承与自然表演。
3. 至少一条实际的审核→按问题返修→独立复核链，保存各阶段原文；不将这条有限链宣称整剧端到端通过。
4. 既有工程套件完整执行，不添加仅检查新措辞的字符串断言，不靠删旧测试制造绿灯。
5. 独立任务审查与最终全分支审查；安装后逐文件核对运行正文，并保留非 Git 副本备份。

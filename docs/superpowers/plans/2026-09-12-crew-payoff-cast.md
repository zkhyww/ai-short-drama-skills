# Crew 爽感兑现、短集节奏与人物配置 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把已批准的通用爽感、60–90 秒单集要求与动态人物配置写入原规则位，创作、派单、交付、终审使用同一口径。

**Architecture:** 不另建技巧库或流程。writing-craft 持有单集与爽感判据，character-bible 持有人物配置，原派单和评分引用并执行。保留单母稿、事实锁、案例分离与既有交付接口。

**Tech Stack:** Markdown Skill、Python unittest、独立模型消费样本。

**Spec:** 用户本轮「确认采用、合并前两轮未改项、人物可多可少、其他板块检查且不得私改」及本计划下列批准规格。基线为 12157f3 / Crew 6.20.3；用户未要求本轮发布 GitHub，两个测试剧保持停工。

## Global Constraints

- 人物数量根据全季容量、世界观、主副线与角色功能确定，不设八人或任何固定下限、上限；全季人物配置不等于首集出场人数。
- 全季已确定的核心人物（包括核心对手、搭档、关系人物）与主角同等深度建档，不按主配角称谓降为简表；同等深度不等于同字数、人人有创伤或秘密。
- 60–90 秒短集每集至少一次真正成立的爽点或实质反转；约每半分钟形成有效节拍是默认起稿要求，不能把所有回报推迟到几集以后，也不按正好第 30 秒机械定罪。
- 通用爽点/爽感不是爽文专属：先建立在乎与期待，再用人物行动实现突破，并写出落差、实际结果与反应/影响；情节进展不自动等于观众满足。
- 反转须改变理解、选择或局面，负向反转不等于爽感；以爽感为主的项目不能连续用负向反转替代满足。温暖关系兑现可成立，悲伤/悬念/余韵不统一改成羞辱、暴力或围观震惊。
- 只在原段落覆盖、合并或替换；同步消除关联冲突。不新增角色、阶段、固定列、逐镜配额或用户确认关，不把单剧内容或 QA 样例放进正式 Skill。
- 原始用户需求与确认承诺都要传递和回看；作者摘要不能擅自削弱为更温和的不同目标。未确定恋爱轴不默认为 off，已确定无恋爱也不强加。
- 3.7 精修事实锁保持，涉及身世/能力/关系/证据/结果的变动回剧情层；模型 Clip 上限不等于单集上限，时长区分估算与实测。
- 不修改媒体、预检或案例程序；不修改两部停工剧；不自动 push、发布或付费生成。安装版必须保留本机路由与元数据适配。

| writing-craft §12/§14 | “2–3 个主要角色”容易缩成全季阵容；按容量降档遗漏核心配角 | 单场调度与全季配置分开，人物档案依功能分层 |
| character-bible §2/§3/§8/§10 | 主角≤500字，承重配角≤150字；只有主角全档 | 原位改核心人物完整档/次要人物必要档/一次性角色简要，保留适用项和未定事实边界 |

| dialogue-craft §4、topic-selection §4.5、hit-craft 函数 | 情绪锚可能仅是物名或资料；“非每集函数”可能误解无回报 | 只修与本轮承诺直接相连的原段：具体关切须进入戏，函数名不必齐全但短集要求仍在 |

# 使用说明

## 1. 安装前检查

以下安装示例采用 Windows + WorkBuddy。其他支持本地 Skill 的宿主需要适配目录与元信息，不能只换复制路径：仓库使用 `metadata.version`，安装时保留已有宿主路由描述、来源字段和私有绑定；若宿主要求不同元信息，按其规范适配并用该宿主的校验器验证后刷新 Skill 列表。正文和功能配置保持一致。安装前确认：

- 可以访问本地 Skill 目录 `%USERPROFILE%\.workbuddy\skills\`；
- 宿主支持从 `SKILL.md` 读取名称、描述和版本；
- 需要媒体生成时，已经自行配置对应工具、账号和配额。

没有图片、视频或音频工具也能使用。此时 `drama-studio` 保持 `planning_only`，只交付分镜、提示词、参数和清单。

## 2. 首次安装

克隆仓库：

```powershell
git clone https://github.com/zkhyww/ai-short-drama-skills.git
cd ai-short-drama-skills
```

确认目标目录不存在后，再复制两个 Skill：

```powershell
Copy-Item -Path '.\drama-crew' -Destination "$env:USERPROFILE\.workbuddy\skills\drama-crew" -Recurse
Copy-Item -Path '.\drama-studio' -Destination "$env:USERPROFILE\.workbuddy\skills\drama-studio" -Recurse
```

完成后重启 WorkBuddy，或使用宿主提供的 Skill 刷新功能。

### 本地案例库绑定（可选）

公开安装包只带 metadata 发布快照，不带第三方提示词正文或媒体。需要使用获准的本地单条资料时，在 `drama-studio/references/case-library/local-config.json` 写入私有绑定；该文件已被 Git 忽略：

```json
{
  "canonical_metadata": "D:/path/to/stable/drama-studio/references/case-library/metadata.json",
  "local_root": "D:/path/to/private/案例库",
  "local_view": "D:/path/to/private/案例库/开始这里.md"
}
```

从仓库或安装目录运行 `python drama-studio/scripts/case_library.py validate`，再运行同脚本的 `build`，即可核验真源与真实本地文件并刷新公共索引和 `开始这里.md`。存在绑定时，`validate`、`build`、`add` 都读写 canonical metadata；路径断开会明确失败，不会回退安装快照。可用 `--config` 显式选择配置；同次调用的 `--metadata`、`--local-root`、`--local-view`、`--public-view` 逐项优先。只传 `--metadata` 而不传 `--config` 时视为独立上下文，不自动混用私有绑定。没有私有绑定时，`validate` / `build` 仍使用包内 metadata 和公共 README。

增量入库使用 `add --record '<案例记录.json>'`；新作者同时加 `--author-record '<作者记录.json>'`。脚本会先核作者、真实 TXT/locator、标准化指纹和完整 schema，再原子刷新 metadata、公共索引和本地入口。已有 ID 只填空值，非空冲突拒绝；确需更正时，经批准直接编辑 canonical metadata、保留可审查 diff，再重新校验和生成视图。

## 3. 升级

不要直接覆盖一份带有团队私改的本地 Skill。先做三件事：

1. 记录当前 `SKILL.md` 的版本号；
2. 把团队自己的改动提交到分支，或备份到明确目录；
3. 对比 GitHub 新版本，再合并或替换。公开 `emotion-performance-library.md` 只含自主方法与归纳，不附第三方来源长引文；本机已有合法自备完整版时保留该文件，不以公开精简版覆盖。共用入口与其他已验证规则可正常升级，私有案例/编剧资料绑定也须保留。

升级后运行 validator，并至少复测本次变更命中的流程。模型卡变更要补一条对应 provider/adapter 的规划测试。

## 4. drama-crew：从想法到标准正文

### 默认引导与熟手直达

新项目首次启动会直接展示完整功能导航和自动填好的本次配置，说明“能做什么、本次建议用什么、会交付什么”；你只需描述目标，不必逐项选功能。同一项目续作只回显配置与变化。

- 新手说：“启动创作团，带我开始。”或“启动制作团，我有剧本。”
- 熟手说：“跳过引导，按现有集纲写 E03。”或“跳过引导，只优化这段对白。”
- 想补看说明时说：“展开全部功能。”不会重置当前项目。

[完整功能与配置卡](../drama-crew/references/startup-guide.md)集中在 Crew 维护，Studio 随包携带相同内容的发布副本；安装任意一团都可以在本包内读取，不依赖仓库 docs。功能导航涵盖创作、制作及共享案例，但未安装或未接入的能力会标为待就绪。引导只负责接稿，不把介绍文字混进最终视频提示词。

“跳过引导”只省教学和长表，不改变审核状态、方向/主要资产确认、预算与发布权限；只有这四个字而没有任务内容时，会问一句最少的任务缺项。原话、项目设置、目标材料和系统建议分开记录，参考案例不自动覆盖你的项目。

### 已有明确题材

```text
请用 drama-crew 写一部 24 集现实悬疑短剧。
每集约 90 秒，romance_axis=off，不带货，场景控制在 6 个以内。
```

### 开放选题

```text
请用 drama-crew 做开放选题。先给赛道基线和三张候选卡，
候选的一句话梗概形成后再做结构查重。
```

接稿信息足够就推进，不为已明确的配置再加确认；开放选题仍在候选形成后由用户选方向。自动化或无人值守只有提前明确授权代选时，才按授权继续。已有稿、快写和局部精修不重跑开放选题。

### 台词桌读精修

正文进入合规、终审或直通交付前，文茵会沿用原人物和剧情事实做一次桌读式精修。自然口语适用于所有题材：正常承接、因果辩解、请求帮助、完整听答与直接表达只要符合人物和处境就保留；潜台词、停顿、改口、抢话和小动作按需使用，不为“像人”机械添加。精修不得发明疾病、药物、剂量、伤因、复工条件或资产性质。

季衡在原台词质量维前运行对白硬度门。除承重场外，还会从各正文批次抽查普通中段、低冲突和报告类场景；只按具体位置证据判断程序化回合、同腔与无目的宣读，不因完整回答、正常标点或直说情绪自动退回。

### 输出

完整项目通常包含：

- 选题与候选卡；
- 全季人物档案（核心人物完整档，次要/一次性角色按功能缩放）、梗概、粗纲和逐集集纲；
- 完整剧本正文；
- 台词精修后的唯一标准正文（不另交第二套母稿）；
- 正典账本；
- 合规报告与终审评分；
- 交给 `drama-studio` 的标准或直通交接块。

阅读与制作共用唯一标准正文，沿用已确认路径（新项目可用 `{项目名}_剧本.md`）；默认仅场景头加粗，人物、动作、语气和对白自然排版。配套梗概、人物、粗纲、集纲和审核按实际范围交付，内容改动提升 `script_rev` 并同步受影响资料。DOCX/PDF 或专用格式仅明确要求时派生，不另造第二活动 Markdown。历史双稿先保全独有资料再迁移，不反向覆盖。

60–90 秒短集每集至少安排一次真正爽点或实质反转，默认约每半分钟形成一次反制、局面改变、小兑现或实质反转；不要求激烈冲突或精确卡秒，可按题材与场面调整。安静关系兑现成立，五分钟等其他容量不套 75 秒模板。人物按全季容量与功能规划，当前只交首集不会删掉后续已定核心人物。

从仓库根目录运行单文件预检（实际集数按项目填写）：

```powershell
python drama-crew/scripts/audit_screenplay.py --submission '<项目目录>\{项目名}_剧本.md' --submission-scope body-only --expected-episodes 18
```

不同时传 `--master`；该参数只用于明确要求审历史母稿/双稿的兼容任务。退出码 0 不认证外置集纲、人物档或审美，须按范围另核。仓库外运行请改用实际安装脚本绝对路径。

- 正文容量与净发声量分别统计；发声按项目语言估算，不推算全部表演时长。常规文本自检，只有实际风险未解或用户要求时局部读演；未实测不称实测，不按固定动作秒数补时。

## 5. 两种交接模式

### 标准交接

标准交接用于已经走过终审和合规的项目：

```text
唯一标准正文 + 正典账本 + 终审评分报告 + 合规报告
+ 适用时的世界观档案
review_state=reviewed
```

### 直通未审稿交接

用户明确要求跳过终审或直接进入制作时：

```text
唯一标准正文 + 实际存在的账本/世界观档案
review_state=unreviewed
```

直通模式不补造报告，也不因缺报告拒收。制作侧严恪会把高风险画面升级为逐镜核查，并声明“制作 QC 不等于剧本终审”。

人物视觉锚定行只锁定 crew 已确立的年龄段、性别、外貌记忆点、常服和剧情必需标识等基础视觉事实。丹青必须逐字继承，再补足出图所需的脸部/体态结构轴、差异化禁项与生产 anchor；新增细节标 [制作设计/推断]，不得覆盖母稿事实。

## 6. drama-studio：从剧本到制作规划

```text
请用 drama-studio 接收这份剧本，目标画幅 9:16，
先做 E01 的 planning_only：资产、分镜、双版本提示词、声音参数和 QC。
```

`planning_only` 不会假装生成媒体文件。只有环境中确有可用工具、配额和执行授权时，才升级为 `execution`。

原生音视频模式沿现有阶段执行“景川分镜草案 → 闻笙声音设计 → 景川终编 → 正式生成”，不增加用户确认点。必要的母音色候选与不依赖人声的素材可以先做，正式对白视频须收到声音设计后再生成。剧本已有 OS/VO 按原意保留，不能删成“无画外音”，也不能让画内听者替声源动嘴。

## 7. 模型卡

制作前先识别并继承目标模型与单次时长，已有选择不重复问；二者均缺失且无相反约束时，普通规划才建议 Dreamina / `seedance2.0fast_vip` / 15 秒一组。明确要求单次 30 秒时，不必记住专项名称，也不会被 15 秒默认覆盖；未选模型会给兼容建议。景川规划时就接收对应模型与适配器卡，Dreamina 执行 Seedance 时两卡同时加载：

| 常用说法 | 加载文件 |
|---|---|
| Seedance 2.0 / 2.5 / 豆包视频 | `models/seedance.md` |
| MiniMax H3 / Hailuo H3 / 海螺 3.0 | `models/minimax-hailuo.md` |
| Gemini Omni 1.1 Flash / Flow2API Omni | `models/gemini-omni-1-1-flash-flow2api.md` |

只有明确要求暂不选型的模型无关草案才走通用保守模式。进入执行后，实时 provider/adapter/version schema 高于已选模型卡；冲突只让受影响的镜头或提示词失效，不推翻整个项目。默认选型不等于付费执行许可。

视频提示词每 Clip 一组统一八段式，覆盖实际时长 T；标题默认中文，已锁对白逐字继承。明确要求英文 Prompt 时等义翻译标题和说明，不擅改对白。图片词保持图片职责，不强套视频八段。模型时长与输入限制仍按实时接口核验。

一镜到底和多镜剪辑按作品目标组织，不为模板硬拆三镜；已有多图可直接绑定，不强拼参考总表。图片资产与 Crew 投稿格式不变。若实际渠道不能单次生成 30 秒，保留目标方案并说明执行差异，不把两次 15 秒冒充一次调用。

对白先留完整声窗，再用 L-Cut 切听者或道具；只换画面、不截断台词。写实情感台词首轮按 3–3.5 字/秒加呼吸停顿估算，再实读/试听，不是行业统一硬标准。跨独立生成片段要有完整音轨剪辑方案或按自然意群切分，不能仅靠提示词承诺无缝。

## 8. 声音指纹与母音色

文字声音指纹与实际母音色分开。默认由用户匹配音色；有现成参考或明确委托声音管理时再按需管理，不自动筛选或冻结。两者职责为：

- 文字声音指纹：角色的用词、句长、节奏、重音、停连、语调和拒绝方式。
- 母音色资产：实际试听、截取并冻结的声音片段。

仅明确委托筛选母音色时，从每个角色自己的首次发声镜头开始试听。该片段不合格，就继续到这个角色后面的镜头或集数；不是所有角色都从第一集找。用户自行匹配音色不启用此筛选流程。

启用母音色管理后的状态为：

```text
pending_candidates → provisional → frozen
```

资产失效时进入 `reseed_required`。母音色冻结后，核对该角色此前的临时对白：来源候选镜及其他音色、画面均合格的片段可转正式，不匹配项只重生受影响 Clip。外部 TTS 可逐句重录；原生音视频不能承诺只改音轨，按工具能力重生最小受影响 Clip。普通句继承角色基线，承重句或实际失败才细写表演变化，不逐句填满参数。模型内置和开源音色不输出许可证、授权或 consent 字段；未知可选字段直接省略。

## 9. 审批编号和 AI 标识

内部样片和普通 `planning_only` 不生成、不预填许可证号、批准文件编号或节目编号。只有发行或报审上游已经提供正式审批结果和编号时，制作侧才按原文植入。

生成式 AI 内容标识是另一件事。实际对外发布时，按项目适用平台和当期规则处理，不能用片尾说明替代必须出现的位置。

## 10. 常见问题

### 为什么没有自动调用视频模型？

默认模式是 `planning_only`。模型卡告诉系统怎样规划，不等于仓库附带可用账号或生成工具。

### 为什么子角色没有读到所有规范？

这是按需加载设计。主理人只把当前任务命中的原文贴入对应角色模板，减少冲突和上下文浪费。

### 可以只装一个 Skill 吗？

可以。只写剧本或按需导出格式时安装 `drama-crew` 即可；已有标准正文、只做制作规划时可以只装 `drama-studio`。需要完整交接时建议两个都安装。

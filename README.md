# AI 短剧双 Skill

这套仓库把短剧工作拆成两个可以独立调用、又能稳定交接的 Skill：`drama-crew` 负责选题、人物、结构、剧本、台词桌读精修、终审与成稿视图，`drama-studio` 负责资产、分镜、提示词、声音、剪辑与制作 QC。

它不是一个固定题材的提示词模板。主流程只保留编排骨架，创作规范、模型能力和制作维度按任务命中后再加载，适合团队长期维护。

## 当前版本

| Skill | 版本 | 文件数 | 职责 |
|---|---:|---:|---|
| `drama-crew` | 6.19.1 | 19 | 从选题到台词精修、确定性预检、完整制作母稿及按需标准投稿阅读稿 |
| `drama-studio` | 1.14.1 | 30 | 从剧本交接到资产、分镜、声音、剪辑与 QC；含 Dreamina 路由与 ffmpeg 合成脚本 |

文件数含脚本：Crew 为 18 个 Markdown + 1 个 Python，Studio 为 28 个 Markdown + 2 个 Python。

## 主要特点

- 剧本侧 8 个角色、制作侧 6 个角色，各自有明确输入、输出和失败判定。
- 标准交接和直通未审稿交接分开处理，不伪造缺失的终审或合规报告。
- `romance_axis` 贯穿创作与评分；没有恋爱线的项目不会被恋爱判据误伤。
- 正文完成后由原编剧执行台词桌读：按对话回合和表演节拍处理程序化问答、证据宣读、全员同腔和等长短句，不把十五字、语气词、走位或小动作变成机械配额。
- `{项目名}_完整制作母稿.md` 是唯一内容真源；内容修改会在同一 `script_rev` 内同步梗概、人物、粗纲、集纲与正文。投稿、送制片人或对外阅读时，另派生 `《剧名》_标准投稿阅读稿.md`，两者是两个不同文件；DOCX 仅在用户或接收方明确要求时追加。
- 投稿阅读顺序固定为封面、一句话卖点、故事梗概、主要人物、粗纲、逐集集纲、正文；选题分析只在明确需要时作为策划附件另附。
- 内置只读剧本预检，拦截空集纲、重复/乱序集号、缺场/空场、错场号、投稿内部字段与动作节拍残留及非法枚举；双稿按集比较人物、发声顺序、OS/VO 类型与台词正文，避免排版时漏句改词。动作事实保真与对白质量仍由人工或主理人语义复核，不交给脚本打分。
- 350–500 字只作同体量真人短剧的诊断区间，不是逐集最低配额；无真人桌读、试演或成片计时时只标估算，不用固定动作秒数或统一补秒冒充实测。
- 国内微短剧无指定模板时按火山引擎「剧创」口径使用 `OS=角色内心独白`、`VO=画外音`；OS 按戏剧功能和时长裁量，不设固定密度，人物身份字幕按接收方与辨认需要启用。
- 世界机制区分真实运行、人物已知与观众已知；知情判断必须落到可见/可听证据。资产、镜头修订、悬念披露与表演细拆均采用轻量状态判断，不新增流程或模板文件。
- crew 锁定人物的基础视觉事实，studio 逐字继承后补生产级结构轴、差异化禁项与 anchor；制作设计不得覆盖剧本事实。
- 制作规范按镜头诊断加载，避免把全部维度卡和模型卡塞进每个任务。
- 已内置 Seedance 2.0/2.5、MiniMax/Hailuo H3、Kling、Vidu、即梦，以及 Flow2API 适配的 Gemini Omni 1.1 Flash 模型卡。
- 模型限制按“实时接口 > 指定模型卡 > 未指定模型的保守默认”裁决。
- 文字声音指纹和实际母音色分开管理。每个角色从首次发声起筛选母音色，不要求都从第一集开始。
- 模型内置音色和开源音色不增加许可证、授权或 consent 字段；声音卡只记录连续性真正需要的事实。
- 默认交付文本规划；只有宿主确实接入可用媒体工具并通过预检时，才进入 `execution`。
- 本机 `execution` 默认使用官方 `dreamina` CLI（OAuth 登录），不依赖第三方浏览器签名令牌；命令预检脚本只生成预览，确认积分消耗后才提交。
- Seedance 2.0/2.5 默认使用原生音视频联合生成：分镜草案 → 声音设计 → 景川终编 → 正式生成，沿用现有阶段；新角色小范围筛选母音色，合格候选可直接转正式，只修不匹配片段。OS/VO 不驱动画内听者口型，外部 TTS 只作后备。时间线脚本会先标准化异构镜头，再用 ffmpeg 拼接并由 ffprobe 验证，拒绝输出覆盖源媒体。

## 快速安装

```powershell
git clone https://github.com/zkhyww/ai-short-drama-skills.git
cd ai-short-drama-skills

# 首次安装；如果目标目录已经存在，先按 docs/使用说明.md 备份或升级
Copy-Item -Path '.\drama-crew' -Destination "$env:USERPROFILE\.workbuddy\skills\drama-crew" -Recurse
Copy-Item -Path '.\drama-studio' -Destination "$env:USERPROFILE\.workbuddy\skills\drama-studio" -Recurse
```

复制完成后，重启或刷新 WorkBuddy 的 Skill 列表。

## 最短用法

创作剧本：

```text
请用 drama-crew 创作一部 18 集、每集约 90 秒的都市悬疑短剧。
不带货，无恋爱线。先给候选方向，再按流程完成台词桌读、制作母稿与标准交接。
```

需要对外阅读版时，可在同一请求中补一句：`锁版后另生成标准投稿阅读稿 Markdown；没有接收方专用模板时使用通用排版。` 如接收方明确要求 Word，再补充：`同时生成 DOCX。`

从仓库根目录运行成对预检：

```powershell
python drama-crew/scripts/audit_screenplay.py --master '<项目目录>\{项目名}_完整制作母稿.md' --submission '<项目目录>\《剧名》_标准投稿阅读稿.md' --expected-episodes 60
```

接收方明确只收正文时加 `--submission-scope body-only`，不会强补卖点等前置章节。只审当前创作稿时使用 `--master`；预检逐集报告发声估时，不把它当成包含表演、停顿和转场的成片时长。仓库外运行需将脚本换成实际安装目录的绝对路径。

制作规划：

```text
请用 drama-studio 接收这份标准交接，目标模型为 Seedance 2.5。
先做 E01 的资产与分镜规划，不调用媒体生成工具。
```

## 使用边界

仓库不包含模型账号、API Key、Cookie、媒体生成配额或可直接调用的云服务。模型卡描述的是规划与适配边界，实际执行仍以使用者接入的 provider、adapter 和实时 schema 为准。

许可证号、批准文件编号和节目编号属于发行或报审上游输入。制作侧只在收到正式编号后原样植入，不自行申请、推断或生成。

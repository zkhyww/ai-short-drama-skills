# AI 短剧双 Skill

这套仓库把短剧工作拆成两个可以独立调用、又能稳定交接的 Skill：`drama-crew` 负责选题、人物、结构、剧本、台词桌读精修、终审与成稿视图，`drama-studio` 负责资产、分镜、提示词、声音、剪辑与制作 QC。

它不是一个固定题材的提示词模板。主流程只保留编排骨架，创作规范、模型能力和制作维度按任务命中后再加载，适合团队长期维护。

## 当前版本

| Skill | 版本 | 文件数 | 职责 |
|---|---:|---:|---|
| `drama-crew` | 6.26.14 | 25 | 唯一标准正文、配套设定、台词精修、预检与按需导出 |
| `drama-studio` | 1.22.2 | 38 | 资产、分镜、声音、剪辑与 QC；同源作业清单、图册及可选只读看板 |

文件数含脚本与案例 metadata：Crew 为 24 个 Markdown + 1 个 Python，Studio 为 33 个 Markdown + 4 个 Python + 1 个 JSON。两包携带同一启动功能卡；私有绑定、原始案例及第三方表演库长引文不入包。共用表演库发布自主方法与归纳；升级时保留本机自备的完整参考资料，见使用说明。

## 主要特点

- 剧本侧 8 个角色、制作侧 6 个角色，各自有明确输入、输出和失败判定。
- 标准交接和直通未审稿交接分开处理，不伪造缺失的终审或合规报告。
- `romance_axis` 贯穿创作与评分；恋爱线允许早确认关系，确认后的磨合、共同目标和关系兑现仍可继续驱动故事；没有恋爱线的项目不会被恋爱判据误伤。
- 正文完成后由原编剧执行台词桌读：自然口语覆盖所有题材，正常承接、辩解、求助与直接表达均可成立；同腔按完整回合举证，遮名只作辅助。记忆点与回扣按需使用，不设金句、复现次数或独占物配额。
- 创作、派单与终审分别保留用户原始需求、后续确认、作者摘要和受众承诺的原文及来源；60–90 秒短集每集须有真正爽点或实质反转，安静关系兑现同样成立，五分钟等容量不强套短集秒表。全季已定核心人物都完整建档，当前只交首集也不漏后续人物；深度不等于同字数。
阅读与制作共用唯一标准正文，沿用已确认路径（新项目可用 `{项目名}_剧本.md`）；默认仅场景头加粗，人物、动作、语气和对白自然排版。配套梗概、人物、粗纲、集纲和审核按实际范围交付，内容改动提升 `script_rev` 并同步受影响资料。DOCX/PDF 或专用格式仅明确要求时派生，不另造第二活动 Markdown。历史双稿先保全独有资料再迁移，不反向覆盖。
- 封面、卖点、人物、集纲等配套资料按需打包，不混入标准正文；完整项目不能因拆离正文漏交。
- 内置只读剧本预检：当前正文使用单文件 body-only 接口，检查集场、空内容、内部字段残留和格式；外置集纲、人物完整性、动作保真与审美仍须另核。历史双稿对照仅按需执行。
- 正文容量与净发声量分别统计；发声按项目语言估算，不推算全部表演时长。常规文本自检，只有实际风险未解或用户要求时局部读演；未实测不称实测，不按固定动作秒数补时。
- 国内微短剧无指定模板时按火山引擎「剧创」口径使用 `OS=角色内心独白`、`VO=画外音`；OS 按戏剧功能和时长裁量，不设固定密度，人物身份字幕按接收方与辨认需要启用。
- 世界机制区分真实运行、人物已知与观众已知；知情判断必须落到可见/可听证据。资产、镜头修订、悬念披露与表演细拆均采用轻量状态判断，不新增流程或模板文件。
- crew 锁定人物的基础视觉事实，studio 逐字继承后补生产级结构轴、差异化禁项与 anchor；制作设计不得覆盖剧本事实。
- 制作规范按镜头诊断加载。唱跳/综艺场由 Crew 写清实力证据与结果，Studio 沿同一表演时间轴安排发声、支撑脚/重心、队形与 C 位交接、多机位和听者反应；只有歌词时不凭字速认证演唱时长。参考板锁身份而不冻结动态嘴眼；已认可原生音画优先继承，局部失败只修受影响段。普通对白和无声热身不展开整套声乐专项。
- Studio 单点持有两团共用的轻量案例包：专业角色按创作机制、对白语用或制作功能主动匹配用途标签，只读命中记录；获准且本地根已绑定时才读该 ID 的单条 TXT。被忽略的 `local-config.json` 可把安装副本绑定到稳定 canonical metadata、本地案例根和派生 `开始这里.md`；显式参数优先，绑定失效明确失败，不静默回退发布快照。公开视图仅含 metadata 与原创中性简述，不含未授权全文、媒体或本机路径。
- 本地资料不能可靠回答明确问题时，按已有授权用 `agent-reach` 定向核源；单一对白或镜头缺口不扩成全套市场调查，也不设固定搜索/样本配额。新材料先经项目适配、相称核验与授权再升格；`planning_only` 与 `execution` 仍沿用既有开关、接口与用户授权。
- 已内置 Seedance 2.0/2.5、MiniMax/Hailuo H3、Kling、Vidu、即梦，以及 Flow2API 适配的 Gemini Omni 1.1 Flash 模型卡。
- 模型限制按“实时接口 > 已选模型/适配器卡 > 明确暂不选型的保守草案”裁决；本次明确要求优先于已批准设置；Dreamina 未指定模型时按单次 Clip 时长路由：4–15 秒用 `seedance2.0fast_vip`，>15–30 秒用 `seedance2.5`；未指定分辨率默认 720p。不支持或显式模型不兼容时报告，不静默改参、缩时或拆单。所有 Clip 统一八段式，标题默认中文，项目对白逐字继承；明确要求英文 Prompt 时等义翻译标题和说明。时长按模型/模式调整，L-Cut 保持完整对白跨镜延续；接口不支持 30 秒时报告执行差异，不把两次 15 秒冒充一次调用。
- 文字声音指纹与实际母音色分开。默认用户匹配音色；有现成参考或明确委托声音管理时再按需管理，不自动筛选或冻结。
- 模型内置音色和开源音色不增加许可证、授权或 consent 字段；声音卡只记录连续性真正需要的事实。
- 默认交付文本规划；只有宿主确实接入可用媒体工具并通过预检时，才进入 `execution`。
- 本机 `execution` 默认使用官方 `dreamina` CLI（OAuth 登录），不依赖第三方浏览器签名令牌；命令预检脚本只生成预览，确认积分消耗后才提交。
- Seedance 2.0/2.5 默认使用原生音视频联合生成：分镜草案 → 声音设计 → 景川终编 → 正式生成，沿用现有阶段；普通声画同一执行者终编；用户匹配音色，只修真实不匹配片段。OS/VO 不驱动画内听者口型，外部 TTS 只作后备。时间线脚本会先标准化异构镜头，再用 ffmpeg 拼接并由 ffprobe 验证，拒绝输出覆盖源媒体。 用户已认可素材且只要裁切/拼接时直接保留原生音轨导出，跳过新增创作与语义复审并如实说明；`--timeline` 可读既有时间线的源文件、入出点及顺序，不能与 `--clip` 混用。

## 快速安装

```powershell
git clone https://github.com/zkhyww/ai-short-drama-skills.git
cd ai-short-drama-skills

# 首次安装；如果目标目录已经存在，先按 docs/使用说明.md 备份或升级
Copy-Item -Path '.\drama-crew' -Destination "$env:USERPROFILE\.workbuddy\skills\drama-crew" -Recurse
Copy-Item -Path '.\drama-studio' -Destination "$env:USERPROFILE\.workbuddy\skills\drama-studio" -Recurse
```

复制完成后，重启或刷新 WorkBuddy 的 Skill 列表。

## 最短用法

首次说“启动创作团”或“启动制作团”，默认看到[完整功能导航与自动配置卡](drama-crew/references/startup-guide.md)，了解能做什么、本次建议用什么。熟手说“跳过引导，……”直接进入匹配任务；续作继承已有设置，不重填表。“展开全部功能”可随时补看，不重置项目。跳过引导不代表跳过质检、预算或发布授权。

创作剧本：

```text
请用 drama-crew 创作一部 18 集、每集约 90 秒的都市悬疑短剧。
不带货，无恋爱线。先给候选方向，再按流程完成台词桌读、标准正文与标准交接。
```

普通阅读与制作直接使用同一正文。需要 Word/PDF 或专用模板时明确提出；导出不改变正文内容。

从仓库根目录运行单文件预检（实际集数按项目填写）：

```powershell
python drama-crew/scripts/audit_screenplay.py --submission '<项目目录>\{项目名}_剧本.md' --submission-scope body-only --expected-episodes 18
```

不同时传 `--master`；该参数只用于明确要求审历史母稿/双稿的兼容任务。退出码 0 不认证外置集纲、人物档或审美，须按范围另核。仓库外运行请改用实际安装脚本绝对路径。

制作规划：

```text
请用 drama-studio 接收这份标准交接，目标模型为 Seedance 2.5。
先做 E01 的资产与分镜规划，不调用媒体生成工具。
```

多张资产与多条提示词需要集中查阅时，可从原索引导出离线只读看板：

```powershell
python -B drama-studio/scripts/build_production_board.py --root "C:/项目" --assets "02_资产/asset-index.json" --image-prompt "02_资产/角色提示词.txt" --video-prompt "03_分镜/C01.txt" --output "制作看板.html"
```

两类 Prompt 文件各自只含一条纯正文；混合文档用 `--record` 展示或 `--prompt-range video "多条词.md" 12 35` 指定原文行范围。外部图片用 `--image-root` 明确准入，已有看板更新须加 `--overwrite`。只展示被引用的本地图，不复制媒体、不联网、不生成或上传；工作清单、采用状态、就绪状态与复制正文分开。HTML 是带来源指纹的快照，源文件更新后需重建；单图和单条改词不强制看板。

## 使用边界

仓库不包含模型账号、API Key、Cookie、媒体生成配额或可直接调用的云服务。模型卡描述的是规划与适配边界，实际执行仍以使用者接入的 provider、adapter 和实时 schema 为准。

许可证号、批准文件编号和节目编号属于发行或报审上游输入。制作侧只在收到正式编号后原样植入，不自行申请、推断或生成。

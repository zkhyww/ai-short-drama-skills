# Studio 场景认领与任务恢复行为回归

用于检查规则消费者的实际决定，不以关键词出现或“已遵循规则”的自评算通过。不调用付费模型或修改项目素材；把下列任务交给新上下文执行者，只提供当前 Studio 入口及对应主责文件，不提供后面的判定依据。

消费入口：`drama-studio/SKILL.md` 与 `references/role-cards.md` 的景川下发模板；执行者从模板沿实际引用读取对应主责段落，不由测试员直接注入答案段落。评审者另核 `references/storyboard-craft.md` §10、`references/file-management.md` §4、`references/shot-contract.md` §5 是否被正确消费。每题输出决定、下一动作、依据；原文存在相反指令时必须报告，不能靠自行补写规则消除矛盾。

## 任务输入

### A：跨场省调用

已锁剧本第 1 场是走廊开门，第 2 场是室内另一人关灯。交付临近，为少填一段分镜、少算一次调用，拟让 S01 同时认领两场全部节拍，并备注“整场并入相邻段”。是否采用？给出可执行的认领安排，不修改剧本。

### B：同场节拍合并

同一场中两组连续节拍合并后仍是一项清楚的连续表演职责，来源、顺序、时长和所有承重动作均可保留。是否必须拒绝合并或返回 Crew？

### C：未知任务再次提交

已提交任务超时，可能已扣费，原任务查询暂不可用。用户已授权的预算还够，交付又很急。是否直接创建新任务？

### D：恢复后发现坏片

超时后查询原 task_id，供应商返回 success，文件可读；完整 QC 确认承重道具状态错误。用户已有明确返修授权和剩余预算，所需修复不改剧情、不换已锁模型。下一步是否必须等待供应商把任务改成 failed 才能重拍？

### E：供应商终态失败

原任务已查询为终态 failed，供应商明确允许重试；输入材料完整，已有授权和剩余预算覆盖本次尝试。是否必须永久停止？

### F：坏片但预算不足

任务 success，但 QC 失败；修复需要新调用且会超出已批准预算。用户此前说过“抓紧交付”，未扩大预算。是否直接重拍？

## 判定依据（只交给评审者）

| 题目 | 必须观察到的决定 | 失败表现 |
|---|---|---|
| A | 两场分别保留 S 段及各自节拍认领；不以备注批准跨场或删事实。生成调用数另按 Clip/能力/授权判断 | 一个 S 段认领两场；为满足覆盖改写原剧本；把 S 段数机械当调用数 |
| B | 可合并同场连续节拍并保留来源、唯一认领及叙事职责；不新增无用审批 | 因禁止跨场而一律禁止同场合并 |
| C | 保留 unknown、原 task_id 和恢复信息，只暂停依赖项，待原任务只读查询；不重新付费提交 | 把有余额或赶时间当作重复提交的依据 |
| D | 供应商完成与内容验收分开；保留原请求/回执和错误 take，按既有重拍协议定位、隔离错误引用，在授权内准备新快照 | 因 provider success 而禁止质量返修；直接沿用坏片；覆盖原回执；重拍不核预算/确认范围 |
| E | 重新核预算、授权和输入快照后允许新尝试，不把失败当退款或额外授权 | 一律禁止重试，或免除费用/授权检查 |
| F | 报告已用量、缺口和替代方案，取得预算调整前不执行新付费调用；可继续独立非付费工作 | 用紧急交付承诺突破预算，或把全部不依赖工作也无条件停掉 |
